# Раздел 3: Работа с агрегатами и группировками (продолжение)

## Глава 29: Window функции (продолжение)

### Продвинутые примеры оконных функций

#### Пример 4: Накопительные статистические показатели

```sql
-- Показываем накопительное количество клиентов и средний возраст по дате регистрации
SELECT 
    дата_регистрации,
    COUNT(*) AS новых_клиентов_в_день,
    SUM(COUNT(*)) OVER (
        ORDER BY дата_регистрации 
        ROWS UNBOUNDED PRECEDING
    ) AS накопительное_количество_клиентов,
    AVG(EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) AS средний_возраст_в_день,
    AVG(AVG(EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения))) OVER (
        ORDER BY дата_регистрации 
        ROWS UNBOUNDED PRECEDING
    ) AS накопительный_средний_возраст
FROM клиенты
GROUP BY дата_регистрации
ORDER BY дата_регистрации;
```

#### Пример 5: Ранжирование с учетом доли

```sql
-- Расчет рангов и процентного вклада в общий объем по категориям
WITH категория_объемы AS (
    SELECT 
        т.категория,
        SUM(з.общая_сумма) AS объем_по_категории,
        SUM(SUM(з.общая_сумма)) OVER () AS общий_объем
    FROM заказы з
    JOIN товары т ON т.категория IS NOT NULL -- предположим, что есть связь
    GROUP BY т.категория
)
SELECT 
    категория,
    объем_по_категории,
    ROUND(объем_по_категории * 100.0 / общий_объем, 2) AS доля_в_общем_объеме,
    RANK() OVER (ORDER BY объем_по_категории DESC) AS ранг_по_объему,
    CUME_DIST() OVER (ORDER BY объем_по_категории) AS кумулятивное_распределение
FROM категория_объемы
ORDER BY объем_по_категории DESC;
```

### Особенности использования оконных функций

#### Порядок выполнения с оконными функциями

В SQL запросе с оконными функциями порядок выполнения следующий:
1. FROM
2. WHERE
3. GROUP BY
4. HAVING
5. SELECT (включая оконные функции)
6. ORDER BY

#### Сравнение оконных функций с агрегатными функциями в GROUP BY

```sql
-- Группировка с агрегатной функцией (уменьшает строки)
SELECT 
    город,
    COUNT(*) AS количество_клиентов
FROM клиенты
GROUP BY город;

-- Оконная функция (сохраняет все строки)
SELECT 
    фамилия,
    имя,
    город,
    COUNT(*) OVER (PARTITION BY город) AS количество_клиентов_в_городе
FROM клиенты;
```

### Практические применения оконных функций

#### Применение 1: Выявление аномалий

```sql
-- Нахождение заказов с аномально высокой стоимостью
SELECT 
    з.id,
    к.фамилия,
    к.имя,
    з.общая_сумма,
    AVG(общая_сумма) OVER (PARTITION BY к.город) AS средний_чек_по_городу,
    (з.общая_сумма - AVG(общая_сумма) OVER (PARTITION BY к.город)) / 
    NULLIF(AVG(общая_сумма) OVER (PARTITION BY к.город), 0) * 100 AS отклонение_в_процентах
FROM заказы з
JOIN клиенты к ON з.id_клиента = к.id
WHERE 
    з.общая_сумма > AVG(общая_сумма) OVER (PARTITION BY к.город) * 2  -- больше чем в 2 раза
ORDER BY отклонение_в_процентах DESC;
```

#### Применение 2: Сегментация на основе скользящих показателей

```sql
-- Сегментация клиентов по динамике их покупательской активности
WITH клиенты_с_активностью AS (
    SELECT 
        з.id_клиента,
        к.фамилия,
        к.имя,
        з.дата_заказа,
        з.общая_сумма,
        AVG(з.общая_сумма) OVER (
            PARTITION BY з.id_клиента 
            ORDER BY з.дата_заказа 
            ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
        ) AS среднее_за_3_заказа
    FROM заказы з
    JOIN клиенты к ON з.id_клиента = к.id
)
SELECT 
    фамилия,
    имя,
    дата_заказа,
    общая_сумма,
    среднее_за_3_заказа,
    CASE 
        WHEN общая_сумма > среднее_за_3_заказа * 1.5 THEN 'Высокий заказ'
        WHEN общая_сумма < среднее_за_3_заказа * 0.5 THEN 'Низкий заказ'
        ELSE 'Средний заказ'
    END AS тип_заказа
FROM клиенты_с_активностью
ORDER BY id_клиента, дата_заказа;
```

### Заключение главы 29

Оконные функции предоставляют мощные возможности для анализа данных, позволяя выполнять сложные вычисления без размножения строк, как при использовании `JOIN`, или уменьшения их количества, как при использовании `GROUP BY`. Они особенно полезны при создании аналитических отчетов, выполнении сравнений в рамках групп данных и вычислении динамических метрик. Владение оконными функциями - важный навык для любого специалиста по анализу данных.

# Раздел 4: JOIN'ы и комбинирование данных

## Глава 30: Введение в JOIN'ы

### Введение

JOIN (соединение) - это ключевая концепция в SQL, которая позволяет объединять данные из двух или более таблиц на основе взаимосвязей между столбцами этих таблиц. В реальных базах данных информация обычно нормализована и распределена по нескольким связанным таблицам. JOIN позволяет "склеивать" эти таблицы виртуально, чтобы получить полную картину данных.

### Основные понятия

#### Внешние ключи (Foreign Keys)

JOIN'ы обычно основаны на связях между внешними ключами в одной таблице и первичными ключами в другой. Например:
- В таблице "заказы" столбец "id_клиента" может быть внешним ключом, ссылающимся на "id" в таблице "клиенты"
- В таблице "товары_в_заказе" столбец "id_заказа" может ссылаться на "id" в таблице "заказы"

#### Базовый синтаксис JOIN

```sql
SELECT столбцы
FROM таблица1
JOIN тип_соединения таблица2 ON условие_соединения;
```

### Типы JOIN'ов

Существует несколько типов JOIN'ов, каждый из которых ведет себя по-разному при объединении данных:

1. **INNER JOIN** - возвращает только строки, которые имеют соответствия в обеих таблицах
2. **LEFT JOIN (LEFT OUTER JOIN)** - возвращает все строки из левой таблицы и соответствующие строки из правой
3. **RIGHT JOIN (RIGHT OUTER JOIN)** - возвращает все строки из правой таблицы и соответствующие строки из левой
4. **FULL OUTER JOIN** - возвращает все строки из обеих таблиц
5. **CROSS JOIN** - возвращает декартово произведение таблиц (все возможные комбинации)

### Примеры отношений между таблицами

В нашей учебной базе данных могут быть такие связи:
- Клиенты - Заказы (один ко многим: один клиент может сделать много заказов)
- Заказы - Товары (многие ко многим: в одном заказе может быть много товаров, один товар может быть в разных заказах)
- Клиенты - Города (многие к одному: много клиентов в одном городе)

### Важность правильного использования JOIN'ов

Неправильное использование JOIN'ов может привести к:
- Неверным результатам
- Дублированию строк
- Значительному увеличению времени выполнения запроса
- Перегрузке памяти при работе с большими наборами данных

### Основы производительности JOIN'ов

1. **Индексы** на столбцах, по которым происходит соединение, значительно улучшают производительность
2. **Порядок таблиц** может повлиять на производительность (обычно лучше начинать с меньшей таблицы при определенных условиях)
3. **Тип соединения** должен соответствовать бизнес-требованиям

### Простой пример JOIN

```sql
SELECT 
    к.фамилия,
    к.имя,
    з.дата_заказа,
    з.общая_сумма
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента;
```

Этот запрос объединяет информацию о клиентах и их заказах, показывая только тех клиентов, у которых есть заказы.

### Заключение главы

JOIN'ы - фундаментальный инструмент в работе с реляционными базами данных. Понимание различных типов соединений и умение эффективно использовать их - ключевые навыки для любого специалиста, работающего с SQL. В следующих главах мы подробно рассмотрим каждый тип JOIN'а с практическими примерами.

## Глава 31: Оператор AS

### Введение

Оператор `AS` в SQL используется для присвоения псевдонимов (алиасов) столбцам, выражениям и таблицам. Псевдонимы делают запросы более читаемыми и удобными для понимания, особенно при работе с JOIN'ами и сложными выражениями.

### Псевдонимы для столбцов

#### Базовое использование

```sql
SELECT 
    фамилия AS "Фамилия клиента",
    имя AS "Имя клиента",
    дата_регистрации AS "Дата регистрации"
FROM клиенты;
```

#### Псевдонимы для выражений

```sql
SELECT 
    фамилия,
    имя,
    (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) AS возраст,
    CONCAT(имя, ' ', фамилия) AS полное_имя
FROM клиенты;
```

### Псевдонимы для таблиц

Псевдонимы таблиц особенно полезны при использовании JOIN'ов:

```sql
-- Без псевдонимов
SELECT 
    клиенты.фамилия,
    клиенты.имя,
    заказы.дата_заказа,
    заказы.общая_сумма
FROM клиенты
JOIN заказы ON клиенты.id = заказы.id_клиента;

-- С псевдонимами (более читаемо)
SELECT 
    к.фамилия,
    к.имя,
    з.дата_заказа,
    з.общая_сумма
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента;
```

### Правила именования псевдонимов

1. **Описательность**: Псевдонимы должны быть понятными и описательными
2. **Краткость**: Особенно для таблиц - часто используются сокращения
3. **Согласованность**: Используйте одинаковые псевдонимы для одной таблицы в разных частях запроса

### Практические примеры

#### Пример 1: Псевдонимы для агрегатных функций

```sql
SELECT 
    к.город AS город_клиента,
    COUNT(з.id) AS количество_заказов,
    AVG(з.общая_сумма) AS средний_чек
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
ORDER BY количество_заказов DESC;
```

#### Пример 2: Псевдонимы для вложенных запросов

```sql
SELECT 
    клиент AS "Наименование клиента",
    город AS "Местоположение",
    заказы AS "Количество заказов"
FROM (
    SELECT 
        CONCAT(имя, ' ', фамилия) AS клиент,
        город,
        COUNT(з.id) AS заказы
    FROM клиенты к
    LEFT JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.id, CONCAT(имя, ' ', фамилия), город
) AS клиенты_с_заказами;
```

#### Пример 3: Псевдонимы для оконных функций

```sql
SELECT 
    наименование AS "Наименование товара",
    цена AS "Цена",
    категория AS "Категория",
    RANK() OVER (
        PARTITION BY категория 
        ORDER BY цена DESC
    ) AS ранг_в_категории
FROM товары
ORDER BY категория, ранг_в_категории;
```

### Особенности использования AS

#### Необязательность ключевого слова AS

В некоторых случаях слово `AS` можно опустить:

```sql
-- Оба запроса эквивалентны
SELECT фамилия AS фамилия_клиента FROM клиенты;
SELECT фамилия фамилия_клиента FROM клиенты;
```

Однако рекомендуется использовать `AS` для ясности.

#### Проблемы с именами, содержащими пробелы

Если вы хотите использовать пробелы или специальные символы в псевдониме, заключайте его в двойные кавычки:

```sql
SELECT 
    фамилия AS "Фамилия Клиента",
    имя AS "Имя Клиента"
FROM клиенты;
```

#### Псевдонимы в других частях запроса

Псевдонимы столбцов можно использовать в `ORDER BY`, `GROUP BY`, но не в `WHERE`:

```sql
-- ПРАВИЛЬНО
SELECT фамилия AS фамилия_клиента
FROM клиенты
ORDER BY фамилия_клиента;

-- НЕПРАВИЛЬНО
SELECT фамилия AS фамилия_клиента
FROM клиенты
WHERE фамилия_клиента = 'Иванов';
```

Для использования в `WHERE` нужно использовать оригинальное имя столбца:

```sql
-- ПРАВИЛЬНО
SELECT фамилия AS фамилия_клиента
FROM клиенты
WHERE фамилия = 'Иванов';
```

### Практические советы

#### Совет 1: Использование единообразных псевдонимов

Для каждой таблицы используйте один и тот же псевдоним в пределах запроса:

```sql
-- ПРАВИЛЬНО
SELECT к.фамилия, з.дата_заказа
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента;

-- НЕПРАВИЛЬНО
SELECT к.фамилия, з.дата_заказа
FROM клиенты к
JOIN заказы з ON клиенты.id = заказы.id_клиента;
```

#### Совет 2: Описательные псевдонимы для сложных выражений

```sql
SELECT 
    к.фамилия,
    к.имя,
    (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM к.дата_рождения)) AS полный_возраст,
    CASE 
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM к.дата_рождения)) < 25 THEN 'Молодой'
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM к.дата_рождения)) BETWEEN 25 AND 40 THEN 'Средний возраст'
        ELSE 'Зрелый'
    END AS возрастная_категория
FROM клиенты к;
```

#### Совет 3: Стандартные сокращения

Для часто используемых таблиц можно использовать стандартные сокращения:

```sql
-- клиенты - к, cl, cust
-- заказы - з, ord, o
-- товары - т, prod, p
```

### Заключение главы

Оператор `AS` значительно улучшает читаемость SQL-запросов и делает их более понятными. Использование осмысленных псевдонимов особенно важно при работе с JOIN'ами, где нужно различать столбцы из разных таблиц. Хорошее именование - один из признаков профессионального подхода к написанию SQL-запросов.

## Глава 32: INNER JOIN

### Введение

INNER JOIN - это наиболее часто используемый тип соединения в SQL. Он возвращает только те строки, которые имеют соответствия в обеих соединяемых таблицах. Другими словами, результатом INNER JOIN будут только те записи, для которых найдено совпадение по условию соединения в обеих таблицах.

### Базовый синтаксис

```sql
SELECT столбцы
FROM таблица1
INNER JOIN таблица2 ON условие_соединения;
```

Слово `INNER` на самом деле необязательно - его можно опустить:

```sql
SELECT столбцы
FROM таблица1
JOIN таблица2 ON условие_соединения;
```

### Как работает INNER JOIN

INNER JOIN работает следующим образом:
1. Берет каждую строку из левой таблицы
2. Находит соответствующие строки в правой таблице по условию соединения
3. Возвращает только те строки, для которых найдено совпадение в обеих таблицах
4. Если в одной из таблиц нет соответствия, строка не попадает в результат

### Простые примеры INNER JOIN

#### Пример 1: Клиенты и их заказы

```sql
SELECT 
    к.фамилия,
    к.имя,
    з.дата_заказа,
    з.общая_сумма
FROM клиенты к
INNER JOIN заказы з ON к.id = з.id_клиента
ORDER BY к.фамилия, з.дата_заказа;
```

Этот запрос вернет только клиентов, у которых есть заказы. Если у клиента нет заказов, он не появится в результатах.

#### Пример 2: Заказы с информацией о клиентах

```sql
SELECT 
    з.id AS id_заказа,
    к.фамилия,
    к.имя,
    к.город,
    з.дата_заказа,
    з.общая_сумма,
    з.статус
FROM заказы з
INNER JOIN клиенты к ON з.id_клиента = к.id
ORDER BY з.дата_заказа DESC;
```

### INNER JOIN с тремя и более таблицами

INNER JOIN может объединять три и более таблиц:

```sql
SELECT 
    к.фамилия,
    к.имя,
    з.дата_заказа,
    з.общая_сумма,
    т.наименование AS наименование_товара,
    т.цена
FROM клиенты к
INNER JOIN заказы з ON к.id = з.id_клиента
INNER JOIN товары т ON т.категория IS NOT NULL -- предполагаем соединение через другую таблицу
ORDER BY к.фамилия, з.дата_заказа;
```

### INNER JOIN с условиями WHERE

Можно комбинировать INNER JOIN с условиями WHERE:

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    з.дата_заказа,
    з.общая_сумма
FROM клиенты к
INNER JOIN заказы з ON к.id = з.id_клиента
WHERE к.город = 'Москва' 
  AND з.общая_сумма > 50000
ORDER BY з.общая_сумма DESC;
```

### INNER JOIN с агрегатными функциями

```sql
SELECT 
    к.город,
    COUNT(*) AS количество_заказов,
    SUM(з.общая_сумма) AS общая_сумма_по_городу,
    AVG(з.общая_сумма) AS средний_чек
FROM клиенты к
INNER JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
ORDER BY общая_сумма_по_городу DESC;
```

### INNER JOIN с условиями на несколько столбцов

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    з.дата_заказа,
    з.общая_сумма
FROM клиенты к
INNER JOIN заказы з ON к.id = з.id_клиента 
    AND к.город = 'Москва'  -- дополнительное условие в ON
ORDER BY з.дата_заказа;
```

Важно: условие в `ON` отличается от условия в `WHERE` для INNER JOIN - оба этих подхода дадут одинаковый результат.

### Практические примеры

#### Пример 1: Топ клиентов по сумме заказов

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    COUNT(з.id) AS количество_заказов,
    SUM(з.общая_сумма) AS общая_сумма_заказов,
    AVG(з.общая_сумма) AS средний_чек
FROM клиенты к
INNER JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя, к.город
ORDER BY общая_сумма_заказов DESC
LIMIT 10;
```

#### Пример 2: Анализ заказов за определенный период

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    з.дата_заказа,
    з.общая_сумма,
    з.статус
FROM клиенты к
INNER JOIN заказы з ON к.id = з.id_клиента
WHERE з.дата_заказа BETWEEN '2023-01-01' AND '2023-12-31'
  AND з.общая_сумма > 30000
ORDER BY з.дата_заказа DESC, з.общая_сумма DESC;
```

#### Пример 3: Группировка с INNER JOIN

```sql
SELECT 
    EXTRACT(YEAR FROM з.дата_заказа) AS год,
    EXTRACT(MONTH FROM з.дата_заказа) AS месяц,
    к.город,
    COUNT(*) AS количество_заказов,
    SUM(з.общая_сумма) AS общая_сумма
FROM заказы з
INNER JOIN клиенты к ON з.id_клиента = к.id
WHERE EXTRACT(YEAR FROM з.дата_заказа) = 2023
GROUP BY 
    EXTRACT(YEAR FROM з.дата_заказа),
    EXTRACT(MONTH FROM з.дата_заказа),
    к.город
ORDER BY год, месяц, общая_сумма DESC;
```

### Когда использовать INNER JOIN

INNER JOIN особенно полезен, когда:
1. Нужны только записи, которые имеют соответствия в обеих таблицах
2. Выполняется анализ взаимосвязанных данных (например, клиенты и их заказы)
3. Нужно объединить данные для создания аналитических отчетов
4. Требуется исключить "осиротевшие" записи (записи без соответствий)

### Преимущества INNER JOIN

1. **Производительность**: Обычно быстрее, чем другие типы соединений
2. **Точность**: Возвращает только действительно связанные данные
3. **Очистка данных**: Автоматически исключает записи без соответствий

### Потенциальные проблемы

1. **Потеря данных**: Если в одной из таблиц есть записи без соответствий, они не попадут в результат
2. **Дублирование**: Если связи "один-ко-многим", могут возникнуть дубликаты строк

### Заключение главы

INNER JOIN - основной инструмент для соединения таблиц, когда нужно получить только те данные, которые связаны между собой. Он особенно полезен для анализа взаимосвязанных данных и создания отчетов на основе нескольких таблиц. Понимание работы INNER JOIN - необходимый навык для эффективной работы с реляционными базами данных.

## Глава 33: FULL OUTER JOIN

### Введение

FULL OUTER JOIN (или просто FULL JOIN) - это тип соединения, который возвращает все строки из обеих таблиц, независимо от того, есть ли соответствия по условию соединения. Если в одной из таблиц нет соответствующей строки, для нее возвращаются NULL значения для столбцов из другой таблицы.

### Базовый синтаксис

```sql
SELECT столбцы
FROM таблица1
FULL OUTER JOIN таблица2 ON условие_соединения;
```

В PostgreSQL слово `OUTER` необязательно:

```sql
SELECT столбцы
FROM таблица1
FULL JOIN таблица2 ON условие_соединения;
```

### Как работает FULL OUTER JOIN

FULL OUTER JOIN объединяет результаты следующим образом:
1. Сначала выполняет INNER JOIN (возвращает строки с соответствиями в обеих таблицах)
2. Затем добавляет строки из левой таблицы, для которых нет соответствий в правой (с NULL в правой части)
3. И добавляет строки из правой таблицы, для которых нет соответствий в левой (с NULL в левой части)

### Примеры FULL OUTER JOIN

#### Пример 1: Все клиенты и все заказы

```sql
SELECT 
    к.id AS id_клиента,
    к.фамилия,
    к.имя,
    з.id AS id_заказа,
    з.дата_заказа,
    з.общая_сумма
FROM клиенты к
FULL OUTER JOIN заказы з ON к.id = з.id_клиента
ORDER BY к.id, з.id;
```

Этот запрос вернет:
- Клиентов, у которых есть заказы (с информацией как о клиентах, так и о заказах)
- Клиентов, у которых нет заказов (с информацией о клиентах и NULL для заказов)
- Заказы, не связанные с известными клиентами (с NULL для клиента и информацией о заказе)

#### Пример 2: Сравнение данных из разных источников

FULL OUTER JOIN особенно полезен для сравнения данных из разных источников:

```sql
-- Предположим, у нас есть временные таблицы с данными за разные месяцы
SELECT 
    coalesce(янв.фамилия, фев.фамилия) AS фамилия,
    янв.доход_январь,
    фев.доход_февраль,
    (фев.доход_февраль - COALESCE(янв.доход_январь, 0)) AS разница
FROM (
    SELECT к.фамилия, SUM(з.общая_сумма) AS доход_январь
    FROM клиенты к
    JOIN заказы з ON к.id = з.id_клиента
    WHERE EXTRACT(MONTH FROM з.дата_заказа) = 1
    GROUP BY к.фамилия
) AS янв
FULL OUTER JOIN (
    SELECT к.фамилия, SUM(з.общая_сумма) AS доход_февраль
    FROM клиенты к
    JOIN заказы з ON к.id = з.id_клиента
    WHERE EXTRACT(MONTH FROM з.дата_заказа) = 2
    GROUP BY к.фамилия
) AS фев ON янв.фамилия = фев.фамилия
ORDER BY фамилия;
```

### FULL OUTER JOIN с условиями

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    з.дата_заказа,
    з.общая_сумма
FROM клиенты к
FULL OUTER JOIN заказы з ON к.id = з.id_клиента
WHERE к.город = 'Москва' OR з.дата_заказа > '2023-01-01'
ORDER BY к.фамилия, з.дата_заказа;
```

### Использование COALESCE с FULL OUTER JOIN

Поскольку FULL OUTER JOIN может возвращать NULL значения, часто используют функцию `COALESCE` для замены NULL на дефолтные значения:

```sql
SELECT 
    COALESCE(к.фамилия, 'Клиент неизвестен') AS фамилия,
    COALESCE(к.имя, 'Имя неизвестно') AS имя,
    COALESCE(з.дата_заказа, '1900-01-01'::date) AS дата_заказа,
    COALESCE(з.общая_сумма, 0) AS сумма_заказа
FROM клиенты к
FULL OUTER JOIN заказы з ON к.id = з.id_клиента
ORDER BY фамилия, дата_заказа;
```

### Практические примеры

#### Пример 1: Сравнение наличия товаров и заказов

```sql
-- Показать все товары и все заказы, даже если какие-то из них не связаны
SELECT 
    COALESCE(т.id, 0) AS id_товара,
    т.наименование,
    т.категория,
    COALESCE(з.id, 0) AS id_заказа,

    з.общая_сумма
FROM товары т
FULL OUTER JOIN заказы з ON т.цена = з.общая_сумма  -- надуманный пример связи
ORDER BY т.наименование, з.дата_заказа;
```

#### Пример 2: Объединение данных с проверкой целостности

```sql
-- Проверить, есть ли заказы без клиентов или клиенты без заказов
WITH объединенные_данные AS (
    SELECT 
        к.id AS id_клиента,
        к.фамилия,
        к.имя,
        з.id AS id_заказа,
        з.дата_заказа,
        з.общая_сумма,
        CASE 
            WHEN к.id IS NULL THEN 'Лишний заказ'
            WHEN з.id IS NULL THEN 'Клиент без заказов'
            ELSE 'Нормальная связь'
        END AS статус_связи
    FROM клиенты к
    FULL OUTER JOIN заказы з ON к.id = з.id_клиента

SELECT 
    статус_связи,
    COUNT(*) AS количество
FROM объединенные_данные
```

#### Пример 3: Сводная информация по всем сущностям

```sql
-- Показать полную картину: всех клиентов, все заказы и информацию о них
SELECT 
    COALESCE(к.id, -1) AS id_клиента,
    CASE 
        WHEN к.id IS NULL THEN 'НЕИЗВЕСТНЫЙ КЛИЕНТ' 
        ELSE COALESCE(к.фамилия, 'БЕЗ ФАМИЛИИ')
    END AS фамилия,
    CASE 
        WHEN к.id IS NULL THEN 'НЕИЗВЕСТНОЕ ИМЯ' 
        ELSE COALESCE(к.имя, 'БЕЗ ИМЕНИ')
    END AS имя,
    COALESCE(з.id, -1) AS id_заказа,
    COALESCE(з.дата_заказа, '1900-01-01'::date) AS дата_заказа,
    COALESCE(з.общая_сумма, 0) AS общая_сумма,
    CASE 
        WHEN к.id IS NULL THEN 'Нет клиента' 
        WHEN з.id IS NULL THEN 'Нет заказа'
        ELSE 'Полная связь'
    END AS тип_записи
FROM клиенты к
FULL OUTER JOIN заказы з ON к.id = з.id_клиента
ORDER BY id_клиента, id_заказа
LIMIT 20;
```

### Когда использовать FULL OUTER JOIN

FULL OUTER JOIN особенно полезен, когда:
1. Нужно получить полную картину данных из двух таблиц
2. Требуется проверить целостность данных и найти "осиротевшие" записи
3. Выполняется сравнение данных из разных источников
4. Создаются сводные отчеты, включающие все возможные значения

### Преимущества FULL OUTER JOIN

1. **Полный охват данных**: Возвращает все строки из обеих таблиц
2. **Проверка целостности**: Позволяет выявить несогласованные данные
3. **Сравнительный анализ**: Полезно для сопоставления данных из разных источников

### Потенциальные проблемы

1. **Производительность**: Может быть медленнее других типов соединений
2. **Объем результатов**: Может вернуть очень много строк
3. **Обработка NULL**: Потребуется дополнительная обработка NULL значений

### Практические советы

#### Совет 1: Использование WITH для улучшения читаемости

```sql
WITH клиенты_с_заказами AS (
    SELECT 
        к.id,
        к.фамилия,
        к.имя,
        COUNT(з.id) AS количество_заказов
    FROM клиенты к
    LEFT JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.id, к.фамилия, к.имя
),
все_заказы AS (
    SELECT 
        з.id,
        з.id_клиента,
        з.общая_сумма,
        з.дата_заказа
    FROM заказы з
)
SELECT 
    ccz.фамилия,
    ccz.имя,
    ccz.количество_заказов,
    vz.id AS id_заказа,
    vz.общая_сумма
FROM клиенты_с_заказами ccz
FULL OUTER JOIN все_заказы vz ON ccz.id = vz.id_клиента
ORDER BY ccz.фамилия, vz.id;
```

#### Совет 2: Осторожное использование с большими таблицами

FULL OUTER JOIN может создать очень большой результат, особенно с большими таблицами. Всегда оценивайте размер ожидаемого результата.

### Заключение главы

FULL OUTER JOIN - мощный, но менее часто используемый тип соединения, который возвращает все строки из обеих соединяемых таблиц. Он особенно полезен для проверки целостности данных, сравнения источников и создания полных сводных отчетов. Однако следует осторожно использовать его с большими таблицами из-за потенциального объема результата.

## Глава 34: LEFT JOIN

### Введение

LEFT JOIN (или LEFT OUTER JOIN) - это тип соединения, который возвращает все строки из левой таблицы и соответствующие строки из правой таблицы. Если в правой таблице нет соответствия для строки из левой таблицы, в результирующем наборе будут NULL значения для столбцов из правой таблицы.

### Базовый синтаксис

```sql
SELECT столбцы
FROM левая_таблица
LEFT JOIN правая_таблица ON условие_соединения;
```

Слово `OUTER` необязательно, но его часто используют для ясности:
```sql
SELECT столбцы
FROM левая_таблица
LEFT OUTER JOIN правая_таблица ON условие_соединения;
```

### Как работает LEFT JOIN

LEFT JOIN работает следующим образом:
1. Возвращает все строки из левой таблицы
2. Для каждой строки из левой таблицы пытается найти соответствующую строку в правой таблице по условию соединения
3. Если соответствия нет, возвращает NULL значения для столбцов из правой таблицы
4. Если соответствий несколько, создает отдельную строку для каждого соответствия

### Примеры LEFT JOIN

#### Пример 1: Все клиенты и их заказы

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    з.дата_заказа,
    з.общая_сумма
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
ORDER BY к.фамилия, з.дата_заказа;
```

Этот запрос вернет:
- Всех клиентов, включая тех, у кого нет заказов
- Для клиентов с заказами - информацию как о клиенте, так и о заказе
- Для клиентов без заказов - информацию о клиенте и NULL для полей заказа

#### Пример 2: Клиенты и количество их заказов

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    COUNT(з.id) AS количество_заказов
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя, к.город
ORDER BY количество_заказов DESC, к.фамилия;
```

Этот запрос покажет всех клиентов с указанием количества их заказов (включая 0 для клиентов без заказов).

### LEFT JOIN с условиями WHERE

Важно понимать разницу между условиями в `ON` и `WHERE`:

```sql
-- Условие в ON: найдет всех клиентов, но покажет заказы только по Москве
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    з.дата_заказа
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента AND к.город = 'Москва'
ORDER BY к.фамилия;

-- Условие в WHERE: отфильтрует результат, исключив строки с NULL в городе
-- ВНИМАНИЕ: это превращает LEFT JOIN в нечто близкое к INNER JOIN
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    з.дата_заказа
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
WHERE к.город = 'Москва'
ORDER BY к.фамилия;
```

### LEFT JOIN с несколькими таблицами

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    COUNT(з.id) AS количество_заказов,
    COALESCE(SUM(з.общая_сумма), 0) AS общая_сумма_заказов
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя, к.город
ORDER BY общая_сумма_заказов DESC;
```

### LEFT JOIN для поиска "осиротевших" записей

LEFT JOIN особенно полезен для поиска записей в левой таблице, которые не имеют соответствий в правой таблице:

```sql
-- Найти клиентов, у которых нет заказов
SELECT 
    к.id,
    к.фамилия,
    к.имя,
    к.город
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
WHERE з.id IS NULL
ORDER BY к.фамилия;
```

### Практические примеры

#### Пример 1: Отчет по активности клиентов

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    к.дата_регистрации,
    COUNT(з.id) AS количество_заказов,
    COALESCE(SUM(з.общая_сумма), 0) AS общая_сумма_заказов,
    COALESCE(AVG(з.общая_сумма), 0) AS средний_чек
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
GROUP BY 
    к.id, к.фамилия, к.имя, к.город, к.дата_регистрации
ORDER BY количество_заказов DESC, общая_сумма_заказов DESC
LIMIT 20;
```

#### Пример 2: Подготовка данных для анализа

```sql
-- Подготовить таблицу для анализа, включая клиентов без недавних заказов
SELECT 
    к.id AS id_клиента,
    CONCAT(к.имя, ' ', к.фамилия) AS полное_имя,
    к.город,
    (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM к.дата_рождения)) AS возраст,
    COUNT(з.id) AS заказов_в_2023,
    COALESCE(SUM(з.общая_сумма), 0) AS сумма_в_2023,
    MAX(з.дата_заказа) AS последний_заказ
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента 
    AND EXTRACT(YEAR FROM з.дата_заказа) = 2023
GROUP BY 
    к.id, к.имя, к.фамилия, к.город, к.дата_рождения
ORDER BY сумма_в_2023 DESC;
```

#### Пример 3: Сравнение с эталонными данными

```sql
-- Сравнить существующие категории товаров с эталонным списком
-- (предположим, у нас есть эталонная таблица категорий)
WITH эталонные_категории AS (
    SELECT unnest(ARRAY['Электроника', 'Одежда', 'Книги', 'Бытовая техника', 'Обувь']) AS категория
)
SELECT 
    e.категория AS эталон,
    t.категория AS в_наличии,
    CASE WHEN t.категория IS NOT NULL THEN 'Есть' ELSE 'Нет' END AS статус
FROM эталонные_категории e
LEFT JOIN (SELECT DISTINCT категория FROM товары) t ON e.категория = t.категория
ORDER BY e.категория;
```

### Когда использовать LEFT JOIN

LEFT JOIN особенно полезен, когда:
1. Нужно сохранить все записи из основной (левой) таблицы
2. Требуется включить в результат записи без соответствий в правой таблице
3. Создается отчет, где важно показать отсутствие данных (например, клиенты без заказов)
4. Нужно подготовить данные для дальнейшего анализа, включая "нулевые" значения

### Преимущества LEFT JOIN

1. **Сохранение полноты данных**: Все записи из левой таблицы остаются в результате
2. **Анализ отсутствия связей**: Позволяет легко находить записи без соответствий
3. **Гибкость**: Можно использовать для создания отчетов с "нулевыми" значениями

### Потенциальные проблемы

1. **Производительность**: Может быть медленнее, особенно с большими таблицами
2. **Обработка NULL**: Требуется осторожная обработка NULL значений
3. **Дублирование**: При "один-ко-многим" отношениях могут возникнуть дубликаты

### Практические советы

#### Совет 1: Использование COALESCE для обработки NULL

```sql
SELECT 
    к.фамилия,
    к.имя,
    COUNT(з.id) AS количество_заказов,
    COALESCE(SUM(з.общая_сумма), 0) AS общая_сумма
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя
ORDER BY общая_сумма DESC;
```

#### Совет 2: Осторожность с условиями в WHERE

```sql
-- ПРАВИЛЬНО: Условие в ON фильтрует правую таблицу
SELECT к.фамилия, з.дата_заказа
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента AND з.дата_заказа > '2023-01-01';

-- ИЗМЕНЕННЫЙ РЕЗУЛЬТАТ: Условие в WHERE исключает строки без заказов
SELECT к.фамилия, з.дата_заказа
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
WHERE з.дата_заказа > '2023-01-01';  -- Это превращает LEFT JOIN в INNER JOIN
```

#### Совет 3: Комбинирование с другими функциями

```sql
-- Использование с оконными функциями
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    COUNT(з.id) AS количество_заказов,
    RANK() OVER (ORDER BY COUNT(з.id) DESC) AS ранг_по_активности
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя, к.город
ORDER BY количество_заказов DESC;
```

### Заключение главы

LEFT JOIN - это мощный инструмент для объединения таблиц, когда нужно сохранить все данные из основной таблицы. Он особенно полезен для аналитических запросов, где важно показать не только существующие связи, но и отсутствие таковых. Понимание разницы между условиями в `ON` и `WHERE` при использовании LEFT JOIN критически важно для получения ожидаемых результатов.

## Глава 35: RIGHT JOIN

### Введение

RIGHT JOIN (или RIGHT OUTER JOIN) - это тип соединения, который возвращает все строки из правой таблицы и соответствующие строки из левой таблицы. Если в левой таблице нет соответствия для строки из правой таблицы, в результирующем наборе будут NULL значения для столбцов из левой таблицы.

### Базовый синтаксис

```sql
SELECT столбцы
FROM левая_таблица
RIGHT JOIN правая_таблица ON условие_соединения;
```

Как и в других JOIN'ах, слово `OUTER` необязательно:
```sql
SELECT столбцы
FROM левая_таблица
RIGHT OUTER JOIN правая_таблица ON условие_соединения;
```

### Как работает RIGHT JOIN

RIGHT JOIN работает следующим образом:
1. Возвращает все строки из правой таблицы
2. Для каждой строки из правой таблицы пытается найти соответствующую строку в левой таблице по условию соединения
3. Если соответствия нет, возвращает NULL значения для столбцов из левой таблицы
4. Если соответствий несколько, создает отдельную строку для каждого соответствия

### Зеркальность RIGHT JOIN и LEFT JOIN

RIGHT JOIN эквивалентен LEFT JOIN с поменянными местами таблицами:

```sql
-- Эти два запроса возвращают одинаковый результат:
SELECT * FROM A RIGHT JOIN B ON A.id = B.a_id;
SELECT * FROM B LEFT JOIN A ON A.id = B.a_id;
```

### Примеры RIGHT JOIN

#### Пример 1: Все заказы и соответствующие клиенты

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    з.дата_заказа,
    з.общая_сумма,
    з.статус
FROM клиенты к
RIGHT JOIN заказы з ON к.id = з.id_клиента
ORDER BY з.дата_заказа DESC;
```

Этот запрос вернет:
- Все заказы, включая те, которые потенциально не имеют связанного клиента
- Для заказов с клиентами - информацию как о заказе, так и о клиенте
- Для заказов без клиентов - информацию о заказе и NULL для полей клиента

#### Пример 2: Заказы и статусы (гипотетический сценарий)

Предположим, у нас есть таблица возможных статусов:

```sql
-- Этот пример более искусственный, потому что RIGHT JOIN не часто используется
WITH возможные_статусы AS (
    SELECT unnest(ARRAY['новый', 'оплачен', 'в_доставке', 'доставлен', 'отменен']) AS статус
)
SELECT 
    в.статус AS возможный_статус,
    з.статус AS реальный_статус,
    COUNT(з.id) AS количество_заказов
FROM возможные_статусы в
RIGHT JOIN заказы з ON в.статус = з.статус
GROUP BY в.статус, з.статус
ORDER BY в.статус;
```

### RIGHT JOIN с условиями

```sql
-- Найти все заказы, включая те, у которых нет зарегистрированного клиента
SELECT 
    COALESCE(к.фамилия, 'Клиент не найден') AS фамилия_клиента,
    COALESCE(к.имя, 'Имя неизвестно') AS имя_клиента,
    з.id AS id_заказа,
    з.дата_заказа,
    з.общая_сумма,
    з.статус
FROM клиенты к
RIGHT JOIN заказы з ON к.id = з.id_клиента
WHERE з.дата_заказа >= '2023-01-01'
ORDER BY з.дата_заказа DESC;
```

### Когда использовать RIGHT JOIN

RIGHT JOIN может быть полезен, когда:
1. Правая таблица содержит эталонный или полный набор данных
2. Нужно убедиться, что все записи из правой таблицы включены в результат
3. Выполняется анализ полноты данных в левой таблице

### Почему RIGHT JOIN используется реже

RIGHT JOIN используется гораздо реже, чем LEFT JOIN, по нескольким причинам:

1. **Читаемость**: LEFT JOIN более интуитивен, особенно при чтении слева направо
2. **Практичность**: В большинстве случаев "основная" таблица - это та, из которой мы хотим получить все данные
3. **Аналогичность**: Любой RIGHT JOIN может быть переписан как LEFT JOIN с изменением порядка таблиц

### Преобразование RIGHT JOIN в LEFT JOIN

Любое использование RIGHT JOIN можно заменить на LEFT JOIN путем изменения порядка таблиц:

```sql
-- RIGHT JOIN
SELECT * FROM клиенты k
RIGHT JOIN заказы z ON k.id = z.id_клиента;

-- Эквивалентный LEFT JOIN
SELECT * FROM заказы z
LEFT JOIN клиенты k ON k.id = z.id_клиента;
```

### Практические примеры

#### Пример 1: Идентификация записей без связей

```sql
-- Найти заказы, которые не имеют соответствующего клиента
-- (в реальной ситуации это может указывать на проблему с целостностью данных)
SELECT 
    з.id AS id_заказа,
    з.дата_заказа,
    з.общая_сумма,
    з.статус
FROM клиенты к
RIGHT JOIN заказы з ON к.id = з.id_клиента
WHERE к.id IS NULL;
```

#### Пример 2: Сравнение с эталонным набором

```sql
-- Предположим, мы хотим проверить, все ли категории товаров из эталонного списка представлены
WITH эталонные_категории AS (
    SELECT unnest(ARRAY['Электроника', 'Одежда', 'Книги', 'Бытовая техника', 'Обувь', 'Мебель']) AS категория
)
SELECT 
    эт.категория AS эталонная_категория,
    т.категория AS существующая_категория,
    COUNT(т.id) AS количество_товаров
FROM товары т
RIGHT JOIN эталонные_категории эт ON т.категория = эт.категория
GROUP BY эт.категория, т.категория
ORDER BY эт.категория;
```

#### Пример 3: Аудит данных

```sql
-- Аудит соответствия статусов заказов
SELECT 
    возможный_статус.статус,
    COALESCE(существующие_заказы.количество, 0) AS количество_заказов
FROM (
    SELECT unnest(ARRAY['новый', 'оплачен', 'в_доставке', 'доставлен', 'отменен']) AS статус
) AS возможный_статус
RIGHT JOIN (
    SELECT статус, COUNT(*) AS количество
    FROM заказы
    GROUP BY статус
) AS существующие_заказы ON возможный_статус.статус = существующие_заказы.статус
ORDER BY возможный_статус.статус;
```

### Альтернативы RIGHT JOIN

В большинстве случаев вместо RIGHT JOIN лучше использовать LEFT JOIN:

```sql
-- Вместо RIGHT JOIN
SELECT к.фамилия, з.дата_заказа
FROM клиенты к
RIGHT JOIN заказы з ON к.id = з.id_клиента;

-- Лучше использовать LEFT JOIN с измененным порядком
SELECT к.фамилия, з.дата_заказа
FROM заказы з
LEFT JOIN клиенты к ON к.id = з.id_клиента;
```

### Потенциальные проблемы с RIGHT JOIN

1. **Читаемость**: Меньше интуитивно понятен для большинства разработчиков
2. **Поддержка**: Некоторые менее распространенные системы могут иметь ограниченную поддержку
3. **Перемещение логики**: Может усложнить понимание потока данных

### Заключение главы

RIGHT JOIN - полезный, но редко используемый тип соединения, который возвращает все строки из правой таблицы. В большинстве случаев его можно заменить на LEFT JOIN с изменением порядка таблиц, что делает код более читаемым и понятным. Тем не менее, понимание RIGHT JOIN важно для полного понимания всех типов соединений в SQL.

## Глава 36: UNION

### Введение

UNION - это оператор SQL, который используется для объединения результатов двух или более SELECT-запросов в один результирующий набор. В отличие от JOIN, который объединяет данные по строкам из разных таблиц, UNION объединяет результаты запросов по вертикали, добавляя строки одного запроса к строкам другого.

### Базовый синтаксис

```sql
SELECT столбцы FROM таблица1
UNION
SELECT столбцы FROM таблица2;
```

Также доступны варианты:
- `UNION` - объединяет результаты и удаляет дубликаты
- `UNION ALL` - объединяет результаты, сохраняя дубликаты

### Правила использования UNION

1. **Количество столбцов**: Каждый SELECT запрос должен возвращать одинаковое количество столбцов
2. **Типы данных**: Соответствующие столбцы должны иметь совместимые типы данных
3. **Порядок столбцов**: Столбцы должны следовать в одинаковом порядке в каждом запросе
4. **Имена столбцов**: Имена столбцов результата будут такими, как в первом SELECT запросе

### Примеры UNION

#### Пример 1: Объединение данных из разных таблиц

```sql
-- Получить фамилии клиентов и названия товаров в одном списке
SELECT фамилия AS имя FROM клиенты
UNION
SELECT наименование AS имя FROM товары
ORDER BY имя;
```

#### Пример 2: Объединение данных с одинаковой структурой

```sql
-- Предположим, у нас есть архивные и текущие заказы
SELECT 'архив' AS источник, id, id_клиента, дата_заказа, общая_сумма
FROM заказы_архив
UNION
SELECT 'текущий' AS источник, id, id_клиента, дата_заказа, общая_сумма
FROM заказы
ORDER BY дата_заказа DESC;
```

### UNION vs UNION ALL

#### UNION (без ALL)
- Удаляет дубликаты
- Может быть медленнее из-за операции удаления дубликатов
- Используется, когда нужно уникальные значения

```sql
SELECT фамилия FROM клиенты WHERE город = 'Москва'
UNION
SELECT фамилия FROM клиенты WHERE город = 'Санкт-Петербург'
ORDER BY фамилия;
```

#### UNION ALL
- Сохраняет все строки, включая дубликаты
- Быстрее, так как не требует удаления дубликатов
- Используется, когда дубликаты не важны или должны быть сохранены

```sql
SELECT фамилия FROM клиенты WHERE город = 'Москва'
UNION ALL
SELECT фамилия FROM клиенты WHERE город = 'Санкт-Петербург'
ORDER BY фамилия;
```

### Практические примеры

#### Пример 1: Создание общего списка контактов

```sql
-- Объединить клиентов и сотрудников для общего списка рассылки
SELECT 'клиент' AS тип, фамилия, имя, email, телефон
FROM клиенты
WHERE email IS NOT NULL
UNION
SELECT 'сотрудник' AS тип, фамилия, имя, email, телефон
FROM сотрудники
WHERE email IS NOT NULL
ORDER BY тип, фамилия;
```

#### Пример 2: Объединение результатов различных условий

```sql
-- Показать высокодоходные заказы и заказы с определенным статусом
SELECT id, id_клиента, 'высокодоходный' AS тип_заказа, общая_сумма, дата_заказа
FROM заказы
WHERE общая_сумма > 100000
UNION
SELECT id, id_клиента, 'в доставке' AS тип_заказа, общая_сумма, дата_заказа
FROM заказы
WHERE статус = 'в_доставке'
ORDER BY общая_сумма DESC;
```

#### Пример 3: Сравнение данных за разные периоды

```sql
-- Сравнить топ-5 клиентов по сумме заказов за 2022 и 2023 года
(
    SELECT '2022' AS год, к.фамилия, к.имя, SUM(з.общая_сумма) AS сумма
    FROM заказы з
    JOIN клиенты к ON з.id_клиента = к.id
    WHERE EXTRACT(YEAR FROM з.дата_заказа) = 2022
    GROUP BY к.id, к.фамилия, к.имя
    ORDER BY сумма DESC
    LIMIT 5
)
UNION ALL
(
    SELECT '2023' AS год, к.фамилия, к.имя, SUM(з.общая_сумма) AS сумма
    FROM заказы з
    JOIN клиенты к ON з.id_клиента = к.id
    WHERE EXTRACT(YEAR FROM з.дата_заказа) = 2023
    GROUP BY к.id, к.фамилия, к.имя
    ORDER BY сумма DESC
    LIMIT 5
)
ORDER BY год, сумма DESC;
```

### Продвинутые примеры

#### Пример 4: Условные выборки с разными критериями

```sql
-- Объединить различные сегменты клиентов
SELECT 'VIP' AS сегмент, id, фамилия, имя, годичная_сумма
FROM (
    SELECT к.id, к.фамилия, к.имя, SUM(з.общая_сумма) AS годичная_сумма
    FROM клиенты к
    JOIN заказы з ON к.id = з.id_клиента
    WHERE EXTRACT(YEAR FROM з.дата_заказа) = EXTRACT(YEAR FROM CURRENT_DATE)
    GROUP BY к.id, к.фамилия, к.имя
    HAVING SUM(з.общая_сумма) > 200000
) AS vip_клиенты
UNION ALL
SELECT 'новый' AS сегмент, к.id, к.фамилия, к.имя, 0 AS годичная_сумма
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
WHERE з.id IS NULL
UNION ALL
SELECT 'регулярный' AS сегмент, к.id, к.фамилия, к.имя, годичная_сумма
FROM (
    SELECT к.id, к.фамилия, к.имя, SUM(з.общая_сумма) AS годичная_сумма
    FROM клиенты к
    JOIN заказы з ON к.id = з.id_клиента
    WHERE EXTRACT(YEAR FROM з.дата_заказа) = EXTRACT(YEAR FROM CURRENT_DATE)
    GROUP BY к.id, к.фамилия, к.имя
    HAVING SUM(з.общая_сумма) BETWEEN 50000 AND 200000
) AS регулярные_клиенты
ORDER BY сегмент, годичная_сумма DESC;
```

### Когда использовать UNION

UNION особенно полезен, когда:
1. Нужно объединить результаты запросов с одинаковой структурой
2. Требуется получить уникальные значения из нескольких источников
3. Создаются сводные отчеты из разных таблиц
4. Выполняется сравнение данных по разным критериям

### Когда использовать UNION ALL

UNION ALL предпочтителен, когда:
1. Дубликаты важны и должны быть сохранены
2. Нужна максимальная производительность
3. Объединяемые наборы данных гарантированно не содержат дубликатов

### Практические советы

#### Совет 1: Использование круглых скобок для сложных запросов

```sql
-- Для сложных подзапросов используйте скобки
(
    SELECT фамилия, имя, 'А' AS группа
    FROM клиенты
    WHERE город = 'Москва'
    LIMIT 10
)
UNION
(
    SELECT фамилия, имя, 'Б' AS группа
    FROM клиенты
    WHERE город = 'Санкт-Петербург'
    LIMIT 10
)
ORDER BY группа, фамилия;
```

#### Совет 2: Проверка совместимости типов данных

При необходимости выполнить преобразование типов:

```sql
-- Если типы данных немного отличаются
SELECT фамилия, CAST(ROUND(средний_доход) AS TEXT) AS дополнительная_информация
FROM клиенты
UNION
SELECT наименование, CAST(цена AS TEXT) AS дополнительная_информация
FROM товары;
```

#### Совет 3: Использование ORDER BY в конце

```sql
-- ORDER BY применяется ко всему объединенному результату
SELECT фамилия, 'клиент' AS тип
FROM клиенты
UNION
SELECT наименование, 'товар' AS тип
FROM товары
ORDER BY фамилия; -- Используется имя столбца из первого SELECT
```

### Ограничения и особенности

1. **Производительность**: UNION (без ALL) может быть медленным на больших наборах данных из-за операции удаления дубликатов
2. **Неполные типы данных**: Если типы данных близки, но не идентичны, СУБД может выполнить неявное преобразование
3. **Поддержка в разных СУБД**: Основные возможности UNION поддерживаются всеми основными СУБД

### Заключение главы

UNION - мощный инструмент для вертикального объединения результатов запросов. Он позволяет создавать сложные аналитические отчеты, объединять данные из разных источников и выполнять сравнения между различными наборами данных. Понимание разницы между UNION и UNION ALL, а также правильное применение этого оператора - важные навыки для эффективной работы с SQL.

## Глава 37: Задание: JOIN'ы

### Введение

В этой главе вы получите практические задания на использование различных типов JOIN'ов: INNER JOIN, LEFT JOIN, RIGHT JOIN, FULL OUTER JOIN, а также UNION. Эти задания помогут закрепить понимание различных способов объединения данных из нескольких таблиц.

### Сценарии и задачи

#### Задание 1: INNER JOIN - Клиенты и их заказы

**Сценарий:** Менеджер по работе с клиентами хочет получить полную информацию о клиентах и их заказах.

**Задача:** Используя INNER JOIN, выведите фамилию, имя клиента, дату и общую сумму заказа. Покажите только клиентов, у которых есть заказы.

**Решение:**
```sql
SELECT 
    к.фамилия,
    к.имя,
    з.дата_заказа,
    з.общая_сумма
FROM клиенты к
INNER JOIN заказы з ON к.id = з.id_клиента
ORDER BY к.фамилия, з.дата_заказа;
```

#### Задание 2: LEFT JOIN - Все клиенты с информацией о заказах

**Сценарий:** Отдел маркетинга хочет видеть всех клиентов, включая тех, кто пока не сделал заказы.

**Задача:** Используя LEFT JOIN, выведите фамилию, имя клиента, дату и общую сумму заказа. Для клиентов без заказов должны быть показаны NULL значения в колонках заказов.

**Решение:**
```sql
SELECT 
    к.фамилия,
    к.имя,
    з.дата_заказа,
    з.общая_сумма
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
ORDER BY к.фамилия, з.дата_заказа;
```

#### Задание 3: INNER JOIN с агрегатными функциями

**Сценарий:** Финансисты хотят получить статистику по заказам для клиентов с более чем 2 заказами.

**Задача:** Используя INNER JOIN, выведите фамилию, имя клиента и количество его заказов. Покажите только тех клиентов, у которых более 2 заказов.

**Решение:**
```sql
SELECT 
    к.фамилия,
    к.имя,
    COUNT(з.id) AS количество_заказов
FROM клиенты к
INNER JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя
HAVING COUNT(з.id) > 2
ORDER BY количество_заказов DESC;
```

#### Задание 4: LEFT JOIN для поиска клиентов без заказов

**Сценарий:** Отдел продаж хочет выявить новых клиентов, которые еще не сделали заказы.

**Задача:** Используя LEFT JOIN, выведите фамилию, имя и город клиентов, у которых нет заказов.

**Решение:**
```sql

LEFT JOIN заказы з ON к.id = з.id_клиента
```

**Задача:** Используя RIGHT JOIN, выведите ID заказа, дату заказа, фамилию и имя клиента. Перепишите этот же запрос, используя LEFT JOIN.

#### Задание 6: INNER JOIN с тремя таблицами

**Сценарий:** Аналитик хочет получить информацию о клиентах, их заказах и товарах в заказах.

**Задача:** Используя JOIN для трех таблиц, выведите фамилию клиента, дату заказа и наименование товара. Предположим, есть дополнительная таблица "товары_в_заказе" с полями: id, id_заказа, id_товара, количество.


#### Задание 7: LEFT JOIN с группировкой

**Сценарий:** Отдел аналитики хочет получить сводку по активности всех клиентов, включая тех, кто не совершал покупки.

**Задача:** Используя LEFT JOIN, выведите фамилию, имя клиента, количество заказов и общую сумму заказов. Для клиентов без заказов должны быть показаны 0 в соответствующих колонках.

**Решение:**
```sql
SELECT

    к.имя,
```

#### Задание 8: FULL OUTER JOIN - полная картина данных

**Сценарий:** Администратор базы данных хочет получить полную картину: всех клиентов и все заказы, включая возможные аномалии.

**Задача:** Используя FULL OUTER JOIN, выведите ID клиента, фамилию, ID заказа, дату заказа. Обозначьте тип каждой строки (нормальная связь, клиент без заказов, заказ без клиента).

**Решение:**
```sql
SELECT 
    к.id AS id_клиента,
    COALESCE(к.фамилия, 'КЛИЕНТ НЕ НАЙДЕН') AS фамилия,
    з.id AS id_заказа,
    з.дата_заказа,
    CASE 
        WHEN к.id IS NULL THEN 'ЛИШНИЙ ЗАКАЗ'
        WHEN з.id IS NULL THEN 'КЛИЕНТ БЕЗ ЗАКАЗА'
        ELSE 'НОРМАЛЬНАЯ СВЯЗЬ'
    END AS тип_связи
FROM клиенты к
FULL OUTER JOIN заказы з ON к.id = з.id_клиента
ORDER BY тип_связи, фамилия
LIMIT 20;
```

#### Задание 9: INNER JOIN с фильтрацией

**Сценарий:** Менеджеры хотят видеть только заказы с высокой суммой от клиентов из конкретных городов.

**Задача:** Используя INNER JOIN, выведите фамилию клиента, город, дату и сумму заказов, где сумма больше 50000 и клиент из Москвы или Санкт-Петербурга.

#### Задание 10: UNION - объединение результатов

**Сценарий:** Требуется создать общий список фамилий клиентов и наименований товаров.

**Задача:** Используя UNION, объедините фамилии клиентов и наименования товаров. Убедитесь, что в результате нет дубликатов. Назовите колонку "наименование".

#### Задание 11: UNION ALL с метками

**Сценарий:** Нужно создать общий список с указанием типа каждой записи.

**Задача:** Используя UNION ALL, создайте список, включающий: фамилии клиентов с пометкой "клиент", названия городов с пометкой "город", названия категорий товаров с пометкой "категория".

**Решение:**
```sql
SELECT фамилия AS значение, 'клиент' AS тип
FROM клиенты
UNION ALL
SELECT DISTINCT город AS значение, 'город' AS тип
FROM клиенты
UNION ALL
SELECT DISTINCT категория AS значение, 'категория' AS тип
FROM товары
WHERE категория IS NOT NULL
ORDER BY тип, значение;
```

#### Задание 12: INNER JOIN с оконными функциями

**Сценарий:** Хотим получить топ-3 заказа по сумме для каждого клиента.

**Задача:** Используя INNER JOIN и оконные функции, выведите фамилию клиента, дату заказа и сумму, ограничив результаты топ-3 заказами по сумме для каждого клиента.

**Решение:**
```sql
WITH заказы_с_рангом AS (
    SELECT 
        к.фамилия,
        з.дата_заказа,
        з.общая_сумма,
        ROW_NUMBER() OVER (
            PARTITION BY к.id 
            ORDER BY з.общая_сумма DESC
        ) AS ранг
    FROM клиенты к
    INNER JOIN заказы з ON к.id = з.id_клиента
)
SELECT 
    фамилия,
    дата_заказа,
    общая_сумма
FROM заказы_с_рангом
WHERE ранг <= 3
ORDER BY фамилия, общая_сумма DESC;
```

**Сценарий:** Нужно показать всех клиентов и только заказы за определенный период.

**Задача:** Используя LEFT JOIN, выведите фамилию клиента, дату и сумму заказа, но присоедините только заказы, сделанные в 2023 году. Включите в результат всех клиентов, даже если у них нет заказов в 2023 году.

```sql
    з.дата_заказа,
    з.общая_сумма
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
```

#### Задание 14: Сложное объединение с условиями

**Сценарий:** Финансисты хотят получить отчет по клиентам с высокими заказами.

**Задача:** Используя JOIN, выведите фамилию клиента, город, количество заказов и общую сумму заказов, но только для клиентов из Москвы с общей суммой заказов более 100000.

#### Задание 15: Сравнение данных с помощью FULL OUTER JOIN

**Сценарий:** Требуется сравнить активность клиентов в разные месяцы.

**Задача:** Сравните количество заказов клиентов в январе и феврале 2023 года. Используйте FULL OUTER JOIN для полного охвата данных. Покажите фамилию клиента, количество заказов в январе, количество заказов в феврале и разницу.

**Решение:**
```sql
WITH январь_2023 AS (
    SELECT 
        к.id AS клиент_id,
        к.фамилия,
        COUNT(з.id) AS заказов_в_январе
    FROM клиенты к
    LEFT JOIN заказы з ON к.id = з.id_клиента 
        AND EXTRACT(MONTH FROM з.дата_заказа) = 1
        AND EXTRACT(YEAR FROM з.дата_заказа) = 2023
    GROUP BY к.id, к.фамилия
),
февраль_2023 AS (
    SELECT 
        к.id AS клиент_id,
        к.фамилия,
        COUNT(з.id) AS заказов_в_феврале
    FROM клиенты к
    LEFT JOIN заказы з ON к.id = з.id_клиента 
        AND EXTRACT(MONTH FROM з.дата_заказа) = 2
        AND EXTRACT(YEAR FROM з.дата_заказа) = 2023
    GROUP BY к.id, к.фамилия
)
SELECT 
    COALESCE(янв.фамилия, фев.фамилия) AS фамилия,
    COALESCE(янв.заказов_в_январе, 0) AS заказов_в_январе,
    COALESCE(фев.заказов_в_феврале, 0) AS заказов_в_феврале,
    (COALESCE(фев.заказов_в_феврале, 0) - COALESCE(янв.заказов_в_январе, 0)) AS разница
FROM январь_2023 янв
FULL OUTER JOIN февраль_2023 фев ON янв.клиент_id = фев.клиент_id
ORDER BY фамилия;
```

## Глава 38: CTE (Common Table Expressions)

### Введение

Common Table Expressions (CTE), или общие табличные выражения, - это временные именованные результаты, которые определяются в рамках выполнения одного SQL-запроса. CTE позволяют создавать более читаемые и понятные запросы, особенно при работе со сложными подзапросами или многократным использованием одного и того же результата.

### Базовый синтаксис

```sql
WITH имя_cte AS (
    SELECT столбцы FROM таблица WHERE условие
)
SELECT * FROM имя_cte;
```

CTE могут включать в себя:
- Простые выборки
- JOIN'ы
- Агрегатные функции
- Оконные функции
- Рекурсивные запросы (мы рассмотрим их позже)

### Простые примеры CTE

#### Пример 1: Основное использование CTE

```sql
WITH московские_клиенты AS (
    SELECT id, фамилия, имя
    FROM клиенты
    WHERE город = 'Москва'
)
SELECT * FROM московские_клиенты
ORDER BY фамилия;
```

#### Пример 2: CTE с JOIN'ами

```sql
WITH клиенты_с_заказами AS (
    SELECT 
        к.id,
        к.фамилия,
        к.имя,
        COUNT(з.id) AS количество_заказов
    FROM клиенты к
    LEFT JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.id, к.фамилия, к.имя
)
SELECT 
    фамилия,
    имя,
    количество_заказов
FROM клиенты_с_заказами
WHERE количество_заказов > 2
ORDER BY количество_заказов DESC;
```

### Многоуровневые CTE

Можно определять несколько CTE, которые могут ссылаться друг на друга:

```sql
WITH 
московские_клиенты AS (
    SELECT id, фамилия, имя
    FROM клиенты
    WHERE город = 'Москва'
),
заказы_москвы AS (
    SELECT 
        мк.фамилия,
        мк.имя,
        COUNT(з.id) AS количество_заказов,
        SUM(з.общая_сумма) AS общая_сумма
    FROM московские_клиенты мк
    JOIN заказы з ON мк.id = з.id_клиента
    GROUP BY мк.id, мк.фамилия, мк.имя
)
SELECT * FROM заказы_москвы
ORDER BY общая_сумма DESC;
```

### CTE с агрегатными функциями

```sql
WITH статистика_по_городам AS (
    SELECT 
        город,
        COUNT(*) AS количество_клиентов,
        AVG(EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) AS средний_возраст
    FROM клиенты
    GROUP BY город
)
SELECT 
    город,
    количество_клиентов,
    ROUND(средний_возраст, 2) AS средний_возраст
FROM статистика_по_городам
WHERE количество_клиентов > 1
ORDER BY количество_клиентов DESC;
```

### CTE с оконными функциями

```sql
WITH клиенты_с_рангом AS (
    SELECT 
        к.фамилия,
        к.имя,
        к.город,
        SUM(з.общая_сумма) AS общая_сумма,
        RANK() OVER (PARTITION BY к.город ORDER BY SUM(з.общая_сумма) DESC) AS ранг_в_городе
    FROM клиенты к
    JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.id, к.фамилия, к.имя, к.город
)
SELECT 
    фамилия,
    имя,
    город,
    общая_сумма,
    ранг_в_городе
FROM клиенты_с_рангом
WHERE ранг_в_городе <= 3  -- топ-3 клиента в каждом городе
ORDER BY город, ранг_в_городе;
```

### Практические примеры

#### Пример 1: Подготовка данных для отчета

```sql
WITH клиенты_с_анализом AS (
    SELECT 
        к.id,
        к.фамилия,
        к.имя,
        к.город,
        COUNT(з.id) AS количество_заказов,
        SUM(з.общая_сумма) AS общая_сумма,
        AVG(з.общая_сумма) AS средний_чек,
        MAX(з.дата_заказа) AS последний_заказ
    FROM клиенты к
    LEFT JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.id, к.фамилия, к.имя, к.город
)
SELECT 
    фамилия,
    имя,
    город,
    количество_заказов,
    общая_сумма,
    средний_чек,
    последний_заказ,
    CASE 
        WHEN количество_заказов = 0 THEN 'Новый клиент'
        WHEN количество_заказов = 1 THEN 'Один заказ'
        WHEN количество_заказов BETWEEN 2 AND 5 THEN 'Регулярный'
        ELSE 'VIP'
    END AS сегмент_клиента
FROM клиенты_с_анализом
ORDER BY общая_сумма DESC
LIMIT 10;
```

#### Пример 2: Сравнение с общей статистикой

```sql
WITH общая_статистика AS (
    SELECT AVG(общая_сумма) AS средний_чек
    FROM заказы
),
городская_статистика AS (
    SELECT 
        к.город,
        COUNT(з.id) AS количество_заказов,
        AVG(з.общая_сумма) AS средний_чек_города,
        SUM(з.общая_сумма) AS общая_сумма
    FROM клиенты к
    JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.город
)
SELECT 
    гс.город,
    гс.количество_заказов,
    ROUND(гс.средний_чек_города, 2) AS средний_чек_города,
    ROUND(ос.средний_чек, 2) AS общий_средний_чек,
    ROUND(гс.средний_чек_города - ос.средний_чек, 2) AS разница_с_общим
FROM городская_статистика гс
CROSS JOIN общая_статистика ос
ORDER BY разница_с_общим DESC;
```

#### Пример 3: Рекурсивные CTE (основы)

Рекурсивные CTE позволяют выполнять итеративные или иерархические запросы:

```sql
-- Пример: генерация последовательности чисел (от 1 до 10)
WITH RECURSIVE числа AS (
    -- Базовый случай
    SELECT 1 AS значение
    UNION ALL
    -- Рекурсивный случай
    SELECT значение + 1
    FROM числа
    WHERE значение < 10
)
SELECT * FROM числа;
```

### Преимущества CTE

1. **Читаемость**: Разделение сложного запроса на логические блоки
2. **Повторное использование**: Одно CTE можно использовать несколько раз в запросе
3. **Модульность**: Легче тестировать и отлаживать отдельные части
4. **Избежание сложных подзапросов**: Замена вложенных подзапросов более понятной конструкцией

### Практические применения CTE

#### Применение 1: Подготовка данных для анализа

```sql
-- Подготовка данных для анализа клиентской активности
WITH активные_клиенты AS (
    SELECT 
        к.id,
        к.фамилия,
        к.имя,
        к.город,
        MIN(з.дата_заказа) AS первый_заказ,
        MAX(з.дата_заказа) AS последний_заказ
    FROM клиенты к
    JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.id, к.фамилия, к.имя, к.город
    HAVING COUNT(з.id) >= 2
)
SELECT 
    *,
    EXTRACT(DAY FROM (последний_заказ - первый_заказ)) AS дни_между_первым_и_последним_заказом
FROM активные_клиенты
ORDER BY дни_между_первым_и_последним_заказом DESC;
```

#### Применение 2: Сравнительный анализ

```sql
-- Сравнение показателей по кварталам
WITH квартальные_данные AS (
    SELECT 
        EXTRACT(YEAR FROM дата_заказа) AS год,
        EXTRACT(QUARTER FROM дата_заказа) AS квартал,
        SUM(общая_сумма) AS объем_продаж,
        COUNT(*) AS количество_заказов
    FROM заказы
    GROUP BY 
        EXTRACT(YEAR FROM дата_заказа),
        EXTRACT(QUARTER FROM дата_заказа)
)
SELECT 
    год,
    квартал,
    объем_продаж,
    количество_заказов,
    LAG(объем_продаж) OVER (
        ORDER BY год, квартал
    ) AS объем_предыдущего_квартала,
    ROUND(
        (объем_продаж - COALESCE(LAG(объем_продаж) OVER (ORDER BY год, квартал), 0)) * 100.0 /
        NULLIF(LAG(объем_продаж) OVER (ORDER BY год, квартал), 0), 
        2
    ) AS рост_в_процентах
FROM квартальные_данные
ORDER BY год, квартал;
```

### Практические советы

#### Совет 1: Использование осмысленных имен

Называйте CTE понятными и описательными именами:

```sql
-- ХОРОШО

    SELECT ...
)

-- МЕНЕЕ ПОНЯТНО

    SELECT ...
)
```

#### Совет 2: Упрощение сложных запросов

Разбивайте сложные запросы на несколько логических CTE:

```sql
WITH 
-- Этап 1: Подготовка основных данных
основные_данные AS (
    SELECT ...
),
-- Этап 2: Агрегация
агрегированные_данные AS (
    SELECT ...
),
-- Этап 3: Ранжирование
ранжированные_данные AS (
    SELECT ...
)
SELECT * FROM ранжированные_данные;
```

#### Совет 3: Избегайте излишней вложенности

Хотя CTE могут ссылаться друг на друга, слишком сложные цепочки могут ухудшить понимание.

### Ограничения CTE

1. **Временность**: CTE доступны только в рамках одного запроса
2. **Невозможность изменения данных**: Только для операций SELECT, не для INSERT, UPDATE, DELETE
3. **Ограничения в материализации**: Некоторые СУБД могут не оптимизировать CTE эффективно

### Заключение главы

CTE - мощный инструмент для улучшения читаемости и структурирования SQL-запросов. Они особенно полезны при работе со сложными аналитическими запросами, где нужно выполнить несколько последовательных преобразований данных. Хорошее понимание и применение CTE делает код более поддерживаемым и понятным для других разработчиков.

## Глава 39: Подзапросы

### Введение

Подзапросы - это SQL-запросы, вложенные внутрь другого запроса. Они позволяют использовать результаты одного запроса в качестве условия или значения в другом запросе. Подзапросы могут быть использованы в различных частях SQL-запроса: в SELECT, WHERE, FROM, и HAVING.

### Типы подзапросов

1. **Коррелированные подзапросы** - зависят от внешнего запроса
2. **Некоррелированные подзапросы** - независимы от внешнего запроса

### Подзапросы в WHERE

#### Один результат (скалярный подзапрос)

```sql
-- Найти клиентов с возрастом выше среднего
SELECT фамилия, имя, дата_рождения
FROM клиенты
WHERE (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) > (
    SELECT AVG(EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения))
    FROM клиенты
);
```

#### Несколько результатов (используя IN)

```sql
-- Найти заказы клиентов из Москвы
SELECT id, дата_заказа, общая_сумма
FROM заказы
WHERE id_клиента IN (
    SELECT id
    FROM клиенты
    WHERE город = 'Москва'
);
```

#### Используя EXISTS

```sql
-- Найти клиентов, у которых есть заказы
SELECT фамилия, имя
FROM клиенты к
WHERE EXISTS (
    SELECT 1
    FROM заказы з
    WHERE з.id_клиента = к.id
);
```

#### Используя NOT EXISTS

```sql
-- Найти клиентов без заказов
SELECT фамилия, имя
FROM клиенты к
WHERE NOT EXISTS (
    SELECT 1
    FROM заказы з
    WHERE з.id_клиента = к.id
);
```

### Подзапросы в SELECT

Скалярные подзапросы в SELECT выполняются для каждой строки результата:

```sql
SELECT 
    фамилия,
    имя,
    город,
    (SELECT COUNT(*) FROM заказы WHERE id_клиента = клиенты.id) AS количество_заказов,
    (SELECT COALESCE(SUM(общая_сумма), 0) FROM заказы WHERE id_клиента = клиенты.id) AS общая_сумма
FROM клиенты
ORDER BY количество_заказов DESC;
```

### Подзапросы в FROM (производные таблицы)

```sql
SELECT 
    город,
    среднее_в_городе
FROM (
    SELECT 
        город,
        AVG(общая_сумма) AS среднее_в_городе
    FROM клиенты к
    JOIN заказы з ON к.id = з.id_клиента
    GROUP BY город
) AS средние_по_городам
ORDER BY среднее_в_городе DESC;
```

### Коррелированные подзапросы

Коррелированный подзапрос ссылается на столбцы внешнего запроса:

```sql
-- Найти заказы выше среднего по городу клиента
SELECT 
    к.фамилия,
    к.город,
    з.дата_заказа,
    з.общая_сумма
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
WHERE з.общая_сумма > (
    SELECT AVG(з2.общая_сумма)
    FROM заказы з2
    JOIN клиенты к2 ON з2.id_клиента = к2.id
    WHERE к2.город = к.город
);
```

### Практические примеры

#### Пример 1: Подзапросы для сложной фильтрации

```sql
-- Найти клиентов с количеством заказов выше среднего
SELECT 
    фамилия,
    имя,
    (SELECT COUNT(*) FROM заказы WHERE id_клиента = клиенты.id) AS количество_заказов
FROM клиенты
WHERE (SELECT COUNT(*) FROM заказы WHERE id_клиента = клиенты.id) > (
    SELECT AVG(количество)
    FROM (
        SELECT COUNT(*) AS количество
        FROM заказы
        GROUP BY id_клиента
    ) AS средние
)
ORDER BY количество_заказов DESC;
```

#### Пример 2: Подзапросы в HAVING

```sql
-- Группы с общей суммой выше средней по всем группам
SELECT 
    к.город,
    COUNT(з.id) AS количество_заказов,
    SUM(з.общая_сумма) AS общая_сумма
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
HAVING SUM(з.общая_сумма) > (
    SELECT AVG(сумма_группы)
    FROM (
        SELECT SUM(общая_сумма) AS сумма_группы
        FROM заказы з2
        JOIN клиенты к2 ON з2.id_клиента = к2.id
        GROUP BY к2.город
    ) AS группы
);
```

#### Пример 3: Подзапросы для вычисления процентов

```sql
-- Процентная доля каждого заказа в общем объеме для клиента
SELECT 
    к.фамилия,
    з.дата_заказа,
    з.общая_сумма,
    ROUND(
        (з.общая_сумма * 100.0) / (
            SELECT SUM(общая_сумма)
            FROM заказы
            WHERE id_клиента = к.id
        ), 
        2
    ) AS процент_от_общего_клиента
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
ORDER BY к.фамилия, процент_от_общего_клиента DESC;
```

### Производительность подзапросов

#### Некоторые подзапросы можно заменить JOIN'ами

```sql
-- Подзапрос в WHERE (может быть медленнее)
SELECT фамилия, имя
FROM клиенты
WHERE id IN (
    SELECT id_клиента
    FROM заказы
    WHERE общая_сумма > 50000
);

-- Эквивалентный JOIN (обычно быстрее)
SELECT DISTINCT к.фамилия, к.имя
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
WHERE з.общая_сумма > 50000;
```

#### Использование EXISTS вместо IN

Для проверки существования часто лучше использовать EXISTS:

```sql
-- Использование IN
SELECT * FROM клиенты
WHERE id IN (SELECT id_клиента FROM заказы);

-- Часто лучший вариант - EXISTS
SELECT * FROM клиенты к
WHERE EXISTS (SELECT 1 FROM заказы з WHERE з.id_клиента = к.id);
```

### Подзапросы со сравнениями

#### ANY/SOME

```sql
-- Найти клиентов, у которых есть заказ выше, чем у клиента с id = 1
SELECT фамилия, имя
FROM клиенты к
WHERE EXISTS (
    SELECT 1 FROM заказы з
    WHERE з.id_клиента = к.id
    AND з.общая_сумма > ANY (
        SELECT общая_сумма FROM заказы WHERE id_клиента = 1
    )
);
```

#### ALL

```sql
-- Найти клиентов, у которых все заказы выше, чем максимальный заказ клиента с id = 1
SELECT фамилия, имя
FROM клиенты к
WHERE NOT EXISTS (  -- НЕ существует заказа, который <= максимального у клиента 1
    SELECT 1 FROM заказы з
    WHERE з.id_клиента = к.id
    AND з.общая_сумма <= ALL (
        SELECT общая_сумма FROM заказы WHERE id_клиента = 1
    )
);
```

### Практические советы

#### Совет 1: Используйте альтернативы, когда это возможно

Многие подзапросы могут быть переписаны как JOIN или CTE, что может улучшить производительность.

#### Совет 2: Будьте осторожны с коррелированными подзапросами

Они выполняются для каждой строки внешнего запроса, что может быть медленно для больших таблиц.

#### Совет 3: Оптимизация скалярных подзапросов в SELECT

Скалярные подзапросы в SELECT могут выполняться многократно. Иногда лучше использовать JOIN:

```sql
-- Меньше эффективно
SELECT 
    фамилия,
    (SELECT COUNT(*) FROM заказы WHERE id_клиента = клиенты.id) AS заказов
FROM клиенты;

-- Более эффективно
SELECT 
    к.фамилия,
    COUNT(з.id) AS заказов
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия;
```

### Заключение главы

Подзапросы - мощный инструмент для выполнения сложных SQL-запросов. Они позволяют использовать результаты одного запроса в другом, обеспечивая гибкость в формулировании условий и вычислений. Однако, важно понимать, как они влияют на производительность, и знать альтернативные способы достижения тех же результатов с использованием JOIN'ов или CTE.

# Раздел 5: Продвинутые техники SQL

## Глава 40: Метки времени и извлечение

### Введение

Работа с датами и временем (timestamp) является важной частью анализа данных. В SQL существует множество функций для работы с метками времени, извлечения отдельных компонентов даты (год, месяц, день и т.д.) и выполнения различных операций с ними.

### Типы данных даты и времени в PostgreSQL

1. **DATE** - только дата (YYYY-MM-DD)
2. **TIME** - только время (HH:MM:SS)
3. **TIMESTAMP** - дата и время без временной зоны
4. **TIMESTAMP WITH TIME ZONE** - дата и время с временной зоной

### Базовые функции извлечения

#### EXTRACT

Функция `EXTRACT` извлекает определенную часть из даты/времени:

```sql
-- Извлечение года
SELECT EXTRACT(YEAR FROM дата_заказа) AS год
FROM заказы;

-- Извлечение месяца
SELECT EXTRACT(MONTH FROM дата_заказа) AS месяц
FROM заказы;

-- Извлечение дня недели (1-7, где 1 - воскресенье)
SELECT EXTRACT(DOW FROM дата_заказа) AS день_недели
FROM заказы;
```

#### Другие способы извлечения

```sql
-- Извлечение различных компонентов
SELECT
    дата_заказа,
    EXTRACT(YEAR FROM дата_заказа) AS год,
    EXTRACT(MONTH FROM дата_заказа) AS месяц,
    EXTRACT(DAY FROM дата_заказа) AS день,
    EXTRACT(DOY FROM дата_заказа) AS день_года,
    EXTRACT(QUARTER FROM дата_заказа) AS квартал,
    EXTRACT(WEEK FROM дата_заказа) AS неделя_года
FROM заказы
LIMIT 10;
```

### Функции для работы с датами

#### AGE

Функция `AGE` вычисляет интервал между датами:

```sql
-- Возраст клиента
SELECT 
    фамилия,
    имя,
    дата_рождения,
    AGE(CURRENT_DATE, дата_рождения) AS возраст
FROM клиенты;

-- Сколько прошло времени с регистрации
SELECT 
    фамилия,
    дата_регистрации,
    AGE(CURRENT_TIMESTAMP, дата_регистрации) AS с_регистрации
FROM клиенты;
```

#### TO_CHAR

Форматирование даты в строку:

```sql
-- Форматирование даты для отчета
SELECT 
    дата_заказа,
    TO_CHAR(дата_заказа, 'DD.MM.YYYY') AS дата_формат1,
    TO_CHAR(дата_заказа, 'Day, DD Month YYYY') AS дата_формат2,
    TO_CHAR(дата_заказа, 'YYYY-MM-DD HH24:MI:SS') AS дата_время
FROM заказы
LIMIT 5;
```

### Арифметические операции с датами

```sql
-- Добавление интервалов
SELECT 
    дата_заказа,
    дата_заказа + INTERVAL '1 day' AS следующий_день,
    дата_заказа + INTERVAL '1 month' AS следующий_месяц,
    дата_заказа - INTERVAL '7 days' AS неделя_назад
FROM заказы
LIMIT 5;

-- Вычисление разницы
SELECT 
    дата_регистрации,
    CURRENT_DATE,
    CURRENT_DATE - дата_регистрации AS дней_с_регистрации
FROM клиенты
LIMIT 5;
```

### Практические примеры

#### Пример 1: Анализ по дням недели

```sql
-- Анализ заказов по дням недели
SELECT 
    EXTRACT(DOW FROM дата_заказа) AS день_недели,
    TO_CHAR(дата_заказа, 'Day') AS название_дня,
    COUNT(*) AS количество_заказов,
    AVG(общая_сумма) AS средний_чек,
    SUM(общая_сумма) AS общая_сумма

GROUP BY 
    EXTRACT(DOW FROM дата_заказа),
    TO_CHAR(дата_заказа, 'Day')
```

#### Пример 2: Анализ по месяцам и кварталам

```sql
-- Анализ по месяцам и кварталам
SELECT 
    EXTRACT(YEAR FROM дата_заказа) AS год,
    EXTRACT(QUARTER FROM дата_заказа) AS квартал,
    EXTRACT(MONTH FROM дата_заказа) AS месяц,

    COUNT(*) AS количество_заказов,

    AVG(общая_сумма) AS средний_чек

    EXTRACT(QUARTER FROM дата_заказа),
    EXTRACT(MONTH FROM дата_заказа)
```

#### Пример 3: Скользящие периоды

```sql
-- Показать заказы за последние 30 дней с детализацией
SELECT 
    дата_заказа,
    COUNT(*) AS заказов_в_день,
    SUM(общая_сумма) AS оборот_в_день,
    AVG(общая_сумма) AS средний_чек_в_день,
    -- Скользящее среднее за 7 дней
    AVG(COUNT(*)) OVER (
        ORDER BY дата_заказа
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS среднее_за_7_дней

WHERE дата_заказа >= CURRENT_DATE - INTERVAL '30 days'
GROUP BY дата_заказа
ORDER BY дата_заказа;
```

#### Пример 4: Сравнение с предыдущими периодами

```sql
-- Сравнение с предыдущим месяцем
WITH месячные_показатели AS (
    SELECT 
        EXTRACT(YEAR FROM дата_заказа) AS год,
        EXTRACT(MONTH FROM дата_заказа) AS месяц,
        COUNT(*) AS количество_заказов,
        SUM(общая_сумма) AS общая_сумма,
        AVG(общая_сумма) AS средний_чек
    FROM заказы
    GROUP BY 
        EXTRACT(YEAR FROM дата_заказа),
        EXTRACT(MONTH FROM дата_заказа)
)
SELECT 
    год,
    месяц,
    количество_заказов,
    общая_сумма,
    LAG(количество_заказов) OVER (ORDER BY год, месяц) AS заказы_прошлого_месяца,
    LAG(общая_сумма) OVER (ORDER BY год, месяц) AS сумма_прошлого_месяца,
    ROUND(
        (количество_заказов - COALESCE(LAG(количество_заказов) OVER (ORDER BY год, месяц), 0)) * 100.0 /
        NULLIF(LAG(количество_заказов) OVER (ORDER BY год, месяц), 0), 
        2
    ) AS рост_заказов_в_процентах
FROM месячные_показатели
ORDER BY год, месяц;
```

### Функции дат PostgreSQL

#### DATE_TRUNC

Обрезает дату до определенного уровня точности:

```sql
-- Обрезка до начала месяца
SELECT 
    дата_заказа,
    DATE_TRUNC('month', дата_заказа) AS начало_месяца
FROM заказы
LIMIT 5;

-- Группировка по месяцам
SELECT 
    DATE_TRUNC('month', дата_заказа) AS месяц,
    COUNT(*) AS количество_заказов,
    SUM(общая_сумма) AS общая_сумма
FROM заказы
GROUP BY DATE_TRUNC('month', дата_заказа)
ORDER BY месяц;
```

#### JUSTIFY_INTERVAL

Нормализует интервал:

```sql
-- Пример нормализации интервала
SELECT 
    INTERVAL '2 months 15 days 3 hours 90 minutes' AS до_нормализации,
    JUSTIFY_INTERVAL(INTERVAL '2 months 15 days 3 hours 90 minutes') AS после_нормализации;
```

### Продвинутые примеры

#### Пример 5: Бизнес-дни

```sql
-- Подсчет бизнес-дней между заказом и сегодня
SELECT 
    id,
    дата_заказа,
    CURRENT_DATE AS сегодня,
    дата_заказа + INTERVAL '7 days' AS ожидаемая_доставка,
    -- Приблизительное количество бизнес-дней (без учета праздников)
    EXTRACT(DAYS FROM (
        дата_заказа + INTERVAL '7 days' - дата_заказа
    )) - 
    -- Вычитаем предполагаемые выходные (около 2 дня в неделю)
    (EXTRACT(DAYS FROM (
        дата_заказа + INTERVAL '7 days' - дата_заказа
    )) / 7 * 2) AS бизнес_дней
FROM заказы
WHERE дата_заказа >= CURRENT_DATE - INTERVAL '1 month'
ORDER BY дата_заказа DESC;
```

#### Пример 6: Периоды активности клиентов

```sql
-- Анализ периодов активности клиентов
WITH клиенты_с_активностью AS (
    SELECT 
        id_клиента,
        MIN(дата_заказа) AS первый_заказ,
        MAX(дата_заказа) AS последний_заказ,
        COUNT(*) AS всего_заказов,
        EXTRACT(DAYS FROM (MAX(дата_заказа) - MIN(дата_заказа))) AS дней_активности,
        COUNT(*) * 1.0 / NULLIF(EXTRACT(DAYS FROM (MAX(дата_заказа) - MIN(дата_заказа))), 0) AS заказов_в_день
    FROM заказы
    GROUP BY id_клиента
)
SELECT 
    к.фамилия,
    к.имя,
    ca.первый_заказ,
    ca.последний_заказ,
    ca.всего_заказов,
    ca.дней_активности,
    ROUND(ca.заказов_в_день, 2) AS заказов_в_день
FROM клиенты_с_активностью ca
JOIN клиенты к ON ca.id_клиента = к.id
```

## Глава 41: Математические функции

### Введение

Математические функции в SQL позволяют выполнять числовые вычисления прямо в запросах. #### Работа с модулями и сравнениями

```sql
-- Найти товары с ценами, близкими к средней

    SELECT 
        AVG(цена) AS средняя_цена,
        STDDEV(цена) AS стандартное_отклонение
    FROM товары
)
SELECT 
    т.наименование,
    т.цена,
    s.средняя_цена,
    ABS(т.цена - s.средняя_цена) AS "Абсолютное отклонение",
    ABS(т.цена - s.средняя_цена) / s.стандартное_отклонение AS "Отклонение в сигмах"
FROM товары т
CROSS JOIN статистика s
WHERE ABS(т.цена - s.средняя_цена) / s.стандартное_отклонение < 1
ORDER BY "Отклонение в сигмах";
```

## Глава 42: Строковые функции

Строковые функции - это важная часть SQL, позволяющая манипулировать текстовыми данными. PostgreSQL предоставляет богатый набор строковых функций, которые значительно расширяют возможности работы с текстовыми данными.

```sql

        WHEN email NOT LIKE '%@%.%' THEN 'Некорректный формат'
        WHEN POSITION(' ' IN email) > 0 THEN 'Содержит пробелы'
        WHEN LENGTH(email) > 254 THEN 'Слишком длинный'
        ELSE 'Корректный'
    END AS "Статус валидации"
FROM клиенты
LIMIT 10;
```

## Глава 43: Подзапросы (дополнительно)

### Введение

В предыдущей главе мы рассмотрели основы подзапросов. В этой главе мы углубимся в более сложные и продвинутые аспекты использования подзапросов, включая коррелированные подзапросы, скалярные подзапросы в различных частях запроса, а также оптимизацию подзапросов.

### Скалярные подзапросы в разных частях запроса

#### Скалярные подзапросы в SELECT

```sql
-- Сложный пример с несколькими скалярными подзапросами
SELECT 
    к.id AS id_клиента,
    к.фамилия,
    к.имя,
    -- Количество заказов клиента
    (SELECT COUNT(*) FROM заказы WHERE id_клиента = к.id) AS количество_заказов,
    -- Общая сумма заказов клиента
    (SELECT COALESCE(SUM(общая_сумма), 0) FROM заказы WHERE id_клиента = к.id) AS общая_сумма,
    -- Средний чек клиента
    (SELECT COALESCE(AVG(общая_сумма), 0) FROM заказы WHERE id_клиента = к.id) AS средний_чек,
    -- Номер по выручке среди всех клиентов
    (SELECT COUNT(*) FROM (
        SELECT id_клиента, SUM(общая_сумма) AS сумма
        FROM заказы
        GROUP BY id_клиента
        HAVING SUM(общая_сумма) >= COALESCE((SELECT SUM(общая_сумма) FROM заказы WHERE id_клиента = к.id), 0)
    ) AS ранги) AS ранг_по_выручке
FROM клиенты к
ORDER BY общая_сумма DESC
LIMIT 10;
```

#### Скалярные подзапросы в ORDER BY

```sql
-- Сортировка по результату подзапроса
SELECT 
    id,
    дата_заказа,
    общая_сумма
FROM заказы
ORDER BY (
    SELECT COUNT(*) 
    FROM клиенты 
    WHERE id = заказы.id_клиента

```

#### Скалярные подзапросы в HAVING

```sql
-- Группировка с условием на подзапрос
SELECT 
    к.город,
    COUNT(з.id) AS количество_заказов,
    SUM(з.общая_сумма) AS общая_сумма
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
HAVING SUM(з.общая_сумма) > (
    SELECT AVG(общая_сумма) * 2  -- больше чем двойной средний чек
    FROM заказы
)
ORDER BY общая_сумма DESC;
```

### Коррелированные подзапросы

#### Более сложные коррелированные подзапросы

```sql
-- Найти клиентов, у которых все заказы выше среднего по городу
SELECT 
    к.фамилия,
    к.имя,
    к.город
FROM клиенты к
WHERE NOT EXISTS (
    -- Не существует заказа, который меньше среднего по городу
    SELECT 1
    FROM заказы з
    WHERE з.id_клиента = к.id
    AND з.общая_сумма < (
        SELECT AVG(з2.общая_сумма)
        FROM заказы з2
        JOIN клиенты к2 ON з2.id_клиента = к2.id
        WHERE к2.город = к.город
    )
);
```

#### Множественные условия в коррелированных подзапросах

```sql
-- Клиенты с особым поведением: все заказы выше среднего, но количество в пределах нормы
SELECT 
    к.id,
    к.фамилия,
    к.имя,
    -- Средний чек клиента
    (SELECT AVG(общая_сумма) FROM заказы WHERE id_клиента = к.id) AS средний_чек_клиента,
    -- Количество заказов клиента
    (SELECT COUNT(*) FROM заказы WHERE id_клиента = к.id) AS количество_заказов
FROM клиенты к
WHERE 
    -- У клиента есть заказы
    (SELECT COUNT(*) FROM заказы WHERE id_клиента = к.id) > 0
    -- Все заказы клиента выше среднего по всем заказам
    AND NOT EXISTS (
        SELECT 1
        FROM заказы з
        WHERE з.id_клиента = к.id
        AND з.общая_сумма <= (SELECT AVG(общая_сумма) FROM заказы)
    )
    -- Количество заказов в разумных пределах
    AND (SELECT COUNT(*) FROM заказы WHERE id_клиента = к.id) BETWEEN 2 AND 10
ORDER BY средний_чек_клиента DESC;
```

#### Замена подзапросов на JOIN

```sql
-- МЕНЕЕ эффективный подзапрос

    FROM заказы
```

### Сложные вложенные подзапросы

#### Подзапросы в подзапросах

```sql
-- Сложный пример с вложенными подзапросами
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    клиентская_группа.название_группы,
    клиентская_группа.статус
FROM клиенты к
JOIN (
    SELECT 
        id_клиента,
        CASE 
            WHEN общая_сумма > (
                SELECT PERCENTILE_CONT(0.9) WITHIN GROUP (ORDER BY общая_сумма)
                FROM (
                    SELECT SUM(общая_сумма) AS общая_сумма
                    FROM заказы
                    GROUP BY id_клиента
                ) AS суммы
            ) THEN 'Премиум'
            WHEN общая_сумма > (
                SELECT AVG(общая_сумма) 
                FROM (
                    SELECT SUM(общая_сумма) AS общая_сумма
                    FROM заказы
                    GROUP BY id_клиента
                ) AS суммы
            ) THEN 'Стандарт'
            ELSE 'Базовый'
        END AS название_группы,
        CASE
            WHEN количество_заказов > (
                SELECT PERCENTILE_CONT(0.8) WITHIN GROUP (ORDER BY количество_заказов)
                FROM (
                    SELECT COUNT(*) AS количество_заказов
                    FROM заказы
                    GROUP BY id_клиента
                ) AS заказы
            ) THEN 'Активный'
            ELSE 'Обычный'
        END AS статус
    FROM (
        SELECT 
            id_клиента,
            SUM(общая_сумма) AS общая_сумма,
            COUNT(*) AS количество_заказов
        FROM заказы
        GROUP BY id_клиента
    ) AS клиентская_статистика
) AS клиентская_группа ON к.id = клиентская_группа.id_клиента
ORDER BY к.фамилия;
```

```sql
-- Комбинация подзапросов и оконных функций
WITH клиенты_с_окнами AS (

        к.id,
        к.фамилия,
        к.имя,
```

### Практические примеры

#### Пример 1: Сравнение с агрегированными значениями

```sql
-- Клиенты с показателями выше средних по их группе (городу)
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    клиентские_показатели.количество_заказов,
    клиентские_показатели.общая_сумма,
    -- Сравнение с городскими средними
    (SELECT AVG(кз.количество_заказов) 
     FROM (
         SELECT 
             к2.id,
             COUNT(з2.id) AS количество_заказов
         FROM клиенты к2
         LEFT JOIN заказы з2 ON к2.id = з2.id_клиента
         GROUP BY к2.id
         HAVING к2.город = к.город
     ) AS кз) AS среднее_в_городе
FROM клиенты к
JOIN (
    SELECT 
        id_клиента,
        COUNT(*) AS количество_заказов,
        SUM(общая_сумма) AS общая_сумма
    FROM заказы
    GROUP BY id_клиента
) AS клиентские_показатели ON к.id = клиентские_показатели.id_клиента
WHERE клиентские_показатели.количество_заказов > (
    SELECT AVG(количество_заказов)
    FROM (
        SELECT COUNT(*) AS количество_заказов
        FROM заказы з2
        JOIN клиенты к2 ON з2.id_клиента = к2.id
        WHERE к2.город = к.город
        GROUP BY з2.id_клиента
    ) AS средние
)

```

#### Пример 2: Условия с несколькими подзапросами

```sql
-- Сложный запрос с множественными условиями на подзапросы
SELECT 
    к.id,
    к.фамилия,
    к.имя,
    к.город,
    (SELECT COUNT(*) FROM заказы WHERE id_клиента = к.id) AS количество_заказов,
    (SELECT SUM(общая_сумма) FROM заказы WHERE id_клиента = к.id) AS общая_сумма
FROM клиенты к
WHERE 
    -- У клиента больше заказов, чем у среднего клиента
    (SELECT COUNT(*) FROM заказы WHERE id_клиента = к.id) > (
        SELECT AVG(количество_заказов) 
        FROM (
            SELECT COUNT(*) AS количество_заказов 
            FROM заказы 
            GROUP BY id_клиента
        ) AS средние
    )
    -- И общая сумма заказов выше медианы
    AND (SELECT SUM(общая_сумма) FROM заказы WHERE id_клиента = к.id) > (
        SELECT PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY сумма)
        FROM (
            SELECT SUM(общая_сумма) AS сумма
            FROM заказы
            GROUP BY id_клиента
        ) AS суммы
    )
    -- И у клиента есть заказы в этом году
    AND EXISTS (
        SELECT 1
        FROM заказы з
        WHERE з.id_клиента = к.id
        AND EXTRACT(YEAR FROM з.дата_заказа) = EXTRACT(YEAR FROM CURRENT_DATE)
    )
ORDER BY общая_сумма DESC;
```

```sql

    id,
    (SELECT COUNT(*) FROM заказы WHERE id_клиента = клиенты.id) AS кол_заказов
```

#### Совет 3: Использование CTE для сложных подзапросов

```sql
-- Вместо сложного вложенного подзапроса использовать CTE
WITH клиенты_с_статистикой AS (
    SELECT 
        к.id,
        к.фамилия,
        к.имя,
        COUNT(з.id) AS кол_заказов,
        SUM(з.общая_сумма) AS общ_sum
    FROM клиенты к
    LEFT JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.id, к.фамилия, к.имя
),
медианы AS (
    SELECT 
        PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY кол_заказов) AS медиана_заказов,
        PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY общ_sum) AS медиана_суммы
    FROM клиенты_с_статистикой
)
SELECT 
    фамилия,
    имя,
    кол_заказов,
    общ_sum
FROM клиенты_с_статистикой cs
CROSS JOIN медианы m
WHERE cs.кол_заказов > m.медиана_заказов
  AND cs.общ_sum > m.медиана_суммы;
```

## Глава 44: Self-Join

### Введение

Self-Join (самосоединение) - это соединение таблицы самой с собой. Это мощная техника, которая позволяет сравнивать строки внутри одной таблицы или устанавливать отношения между различными строками одной и той же таблицы. Self-Join особенно полезен при работе с иерархическими данными, сравнении записей, анализе последовательностей и других сценариях.

### Базовый синтаксис Self-Join

```sql
SELECT столбцы
FROM таблица AS псевдоним1
JOIN таблица AS псевдоним2 ON условие_соединения;
```

### Простые примеры Self-Join

#### Пример 1: Найти клиентов из одного города

```sql
SELECT 
    к1.фамилия AS фамилия_клиента1,
    к1.имя AS имя_клиента1,
    к1.город,
    к2.фамилия AS фамилия_клиента2,
    к2.имя AS имя_клиента2
FROM клиенты к1
JOIN клиенты к2 ON к1.город = к2.город
WHERE к1.id < к2.id  -- чтобы избежать дубликатов (себя с собой и перестановок)
ORDER BY к1.город, к1.фамилия;
```

#### Пример 2: Найти клиентов с одинаковыми именами

```sql
SELECT 
    к1.фамилия AS фамилия1,
    к1.имя,
    к1.дата_регистрации AS дата_регистрации1,
    к2.фамилия AS фамилия2,
    к2.дата_регистрации AS дата_регистрации2
FROM клиенты к1
JOIN клиенты к2 ON к1.имя = к2.имя
WHERE к1.id < к2.id  -- исключаем дубликаты
  AND к1.фамилия != к2.фамилия  -- не однофамильцы
ORDER BY к1.имя, к1.фамилия;
```

### Более сложные примеры Self-Join

#### Пример 3: Анализ временных интервалов

```sql
-- Найти заказы, которые пересекаются по времени (гипотетический пример с интервалами)
-- Предположим, у нас есть таблица с интервалами
WITH заказы_с_интервалами AS (
    SELECT 
        id,
        id_клиента,
        дата_заказа AS начало_интервала,
        дата_заказа + INTERVAL '5 days' AS конец_интервала
    FROM заказы
)
SELECT 
    з1.id AS id_заказа1,
    з2.id AS id_заказа2,
    з1.начало_интервала,
    з1.конец_интервала,
    з2.начало_интервала AS начало_интервала2,
    з2.конец_интервала AS конец_интервала2
FROM заказы_с_интервалами з1
JOIN заказы_с_интервалами з2 
    ON з1.id_клиента = з2.id_клиента  -- тот же клиент
    AND з1.id < з2.id  -- избегаем дубликатов
    AND з1.начало_интервала < з2.конец_интервала
    AND з2.начало_интервала < з1.конец_интервала
ORDER BY з1.id_клиента, з1.дата_заказа;
```

#### Пример 4: Сравнение последовательных заказов

```sql
-- Найти пары последовательных заказов одного клиента
SELECT 
    к.фамилия,
    к.имя,
    з1.id AS id_первого_заказа,
    з1.дата_заказа AS дата_первого_заказа,
    з1.общая_сумма AS сумма_первого_заказа,
    з2.id AS id_второго_заказа,
    з2.дата_заказа AS дата_второго_заказа,
    з2.общая_сумма AS сумма_второго_заказа,
    (з2.дата_заказа - з1.дата_заказа) AS дни_между_заказами,
    (з2.общая_сумма - з1.общая_сумма) AS разница_в_сумме
FROM клиенты к
JOIN заказы з1 ON к.id = з1.id_клиента
JOIN заказы з2 ON к.id = з2.id_клиента
WHERE з1.id < з2.id  -- чтобы не дублировать пары
  AND з1.дата_заказа < з2.дата_заказа  -- первый заказ раньше второго
  -- Допустим, мы ищем заказы в пределах 30 дней друг от друга
  AND (з2.дата_заказа - з1.дата_заказа) <= INTERVAL '30 days'
ORDER BY к.id, з1.дата_заказа;
```

### Self-Join с условиями на разницу значений

#### Пример 5: Найти "похожие" заказы по сумме

```sql
-- Найти заказы с близкой суммой (в пределах 10%)
SELECT 
    з1.id AS id_заказа1,
    з1.общая_сумма AS сумма1,
    з1.дата_заказа AS дата1,
    з2.id AS id_заказа2,
    з2.общая_сумма AS сумма2,
    з2.дата_заказа AS дата2,
    ABS(з1.общая_сумма - з2.общая_сумма) AS разница,
    ROUND(ABS(з1.общая_сумма - з2.общая_сумма) / з1.общая_сумма * 100, 2) AS процентная_разница
FROM заказы з1
JOIN заказы з2 ON з1.id < з2.id  -- избегаем дубликатов
WHERE ABS(з1.общая_сумма - з2.общая_сумма) / з1.общая_сумма <= 0.1  -- разница не более 10%
  AND з1.общая_сумма > 0  -- избегаем деления на 0
ORDER BY процентная_разница, з1.дата_заказа
LIMIT 10;
```

### Self-Join для анализа дубликатов

#### Пример 6: Найти потенциальные дубликаты клиентов

```sql
-- Найти клиентов с похожими данными (возможные дубликаты)
SELECT 
    к1.id AS id1,
    к1.фамилия AS фамилия1,
    к1.имя AS имя1,
    к1.email AS email1,
    к2.id AS id2,
    к2.фамилия AS фамилия2,
    к2.имя AS имя2,
    к2.email AS email2
FROM клиенты к1
JOIN клиенты к2 ON к1.id < к2.id  -- избегаем дубликатов
WHERE (к1.фамилия = к2.фамилия AND к1.имя = к2.имя)  -- одинаковые имя и фамилия
   OR (к1.email = к2.email AND к1.email IS NOT NULL)  -- одинаковые email
ORDER BY к1.фамилия, к1.имя;
```

### Self-Join с агрегатными функциями

#### Пример 7: Сравнение с агрегатными значениями

```sql
-- Найти клиентов с количеством заказов выше среднего
-- (можно решить и другими способами, но в качестве примера Self-Join)
WITH средние_показатели AS (
    SELECT AVG(заказы_на_клиента) AS среднее_количество
    FROM (
        SELECT COUNT(*) AS заказы_на_клиента
        FROM заказы
        GROUP BY id_клиента
    ) AS статистика
)
SELECT 
    к1.id,
    к1.фамилия,
    к1.имя,
    COUNT(з1.id) AS количество_заказов
FROM клиенты к1
LEFT JOIN заказы з1 ON к1.id = з1.id_клиента
CROSS JOIN средние_показатели
GROUP BY к1.id, к1.фамилия, к1.имя, средние_показатели.среднее_количество
HAVING COUNT(з1.id) > средние_показатели.среднее_количество
ORDER BY количество_заказов DESC;
```

### Практические примеры использования Self-Join

#### Пример 8: Анализ активности клиентов

```sql
-- Найти клиентов, у которых есть заказы в разные месяцы одного года
SELECT DISTINCT
    к.фамилия,
    к.имя,
    EXTRACT(YEAR FROM з1.дата_заказа) AS год
FROM клиенты к
JOIN заказы з1 ON к.id = з1.id_клиента
JOIN заказы з2 ON к.id = з2.id_клиента
WHERE з1.id < з2.id  -- избегаем дубликатов
  AND EXTRACT(YEAR FROM з1.дата_заказа) = EXTRACT(YEAR FROM з2.дата_заказа)  -- тот же год
  AND EXTRACT(MONTH FROM з1.дата_заказа) != EXTRACT(MONTH FROM з2.дата_заказа)  -- разные месяцы
ORDER BY к.фамилия;
```

#### Пример 9: Найти клиентов с определенной динамикой

```sql
-- Найти клиентов, у которых последующий заказ был больше предыдущего
SELECT 
    к.фамилия,
    к.имя,
    з1.дата_заказа AS дата_меньшего_заказа,
    з1.общая_сумма AS сумма_меньшего_заказа,
    з2.дата_заказа AS дата_большего_заказа,
    з2.общая_сумма AS сумма_большего_заказа
FROM клиенты к
JOIN заказы з1 ON к.id = з1.id_клиента
JOIN заказы з2 ON к.id = з2.id_клиента
WHERE з1.id != з2.id  -- разные заказы
  AND з1.дата_заказа < з2.дата_заказа  -- первый раньше второго
  AND з1.общая_сумма < з2.общая_сумма  -- второй заказ больше
ORDER BY к.id, з1.дата_заказа;
```

### Self-Join для создания матриц и перекрестных ссылок

#### Пример 10: Создание матрицы "клиент-клиент" по городу

```sql
-- Матрица связи клиентов по общему городу
SELECT 
    к1.фамилия AS клиент1,
    к1.город,
    COUNT(*) AS общие_связи_в_городе
FROM клиенты к1
JOIN клиенты к2 ON к1.город = к2.город AND к1.id != к2.id
```

### Оптимизация Self-Join

#### Избегание лишних соединений

```sql
-- НЕПРАВИЛЬНО: будет соединять каждую строку с каждой
-- SELECT * FROM клиенты к1 JOIN клиенты к2 ON к1.город = к2.город

-- ПРАВИЛЬНО: добавляем условие для избегания дубликатов
SELECT * FROM клиенты к1 
JOIN клиенты к2 ON к1.город = к2.город AND к1.id < к2.id;
```

### Практические советы

#### Совет 1: Всегда используйте условия для избегания дубликатов

При Self-Join почти всегда нужно добавлять условие, чтобы избежать дубликатов и соединения строки с собой:

```sql
-- Хорошая практика
SELECT * FROM таблица t1
JOIN таблица t2 ON условие_логическое
WHERE t1.id < t2.id;  -- или другое условие для избегания дубликатов
```

#### Совет 2: Подумайте о необходимости Self-Join

Иногда Self-Join можно заменить более эффективными конструкциями:

```sql
-- Вместо Self-Join для получения статистики
-- (SELECT * FROM клиенты к1 JOIN клиенты к2 ON ...)

-- Возможно лучше использовать оконные функции
SELECT *, AVG(кол_заказов) OVER() AS среднее_по_всем
FROM (
    SELECT id, COUNT(заказы.id) AS кол_заказов
    FROM клиенты
    LEFT JOIN заказы ON клиенты.id = заказы.id_клиента
    GROUP BY клиенты.id
) AS статистика;
```

#### Совет 3: Используйте индексы

Для эффективной работы Self-Join особенно важны индексы на столбцах, используемых в условии соединения:

```sql
-- Создание индекса для оптимизации Self-Join по городу
CREATE INDEX idx_клиенты_город ON клиенты(город);
```

### Заключение главы

Self-Join - мощная техника SQL, позволяющая находить отношения внутри одной таблицы. Он особенно полезен для сравнения записей, анализа иерархий, поиска дубликатов и анализа последовательностей. Однако, важно понимать, что Self-Join может быть вычислительно затратным, особенно на больших таблицах, поэтому его следует использовать обдуманно и с правильной оптимизацией.

## Глава 45: JSON функции в PostgreSQL

### Введение

PostgreSQL предоставляет богатую поддержку JSON и JSONB данных, что делает его одним из самых мощных решений для работы с полуструктурированными данными. JSON функции позволяют хранить, извлекать, изменять и анализировать JSON данные прямо в базе данных, что особенно полезно в современных приложениях, где данные могут иметь гибкую структуру.

### Типы данных JSON в PostgreSQL

1. **JSON** - текстовое представление, сохраняет форматирование и порядок ключей
2. **JSONB** - бинарное представление, более эффективное для поиска и анализа

### Базовые операции с JSON

#### Создание JSON данных

```sql
-- Создание JSON объекта
SELECT 
    JSON_BUILD_OBJECT(
        'id', 1,
        'фамилия', 'Иванов',
        'имя', 'Иван',
        'город', 'Москва'
    ) AS json_объект;

-- Создание JSONB объекта
SELECT 
    JSONB_BUILD_OBJECT(
        'id', 1,
        'фамилия', 'Иванов',
        'имя', 'Иван',
        'город', 'Москва'
    ) AS jsonb_объект;
```

#### Создание JSON массивов

```sql
-- Создание JSON массива
SELECT 
    JSON_BUILD_ARRAY(
        JSON_BUILD_OBJECT('id', 1, 'имя', 'Товар1'),
        JSON_BUILD_OBJECT('id', 2, 'имя', 'Товар2')
    ) AS json_массив;
```

### Извлечение данных из JSON

#### Операторы извлечения

```sql
-- Пример с JSON данными
WITH пример_json AS (
    SELECT 
        1 AS id,
        '{"фамилия": "Иванов", "имя": "Иван", "контакты": {"email": "ivan@example.com", "телефон": "+79161234567"}}'::JSON AS данные
    UNION ALL
    SELECT 
        2 AS id,
        '{"фамилия": "Петрова", "имя": "Мария", "контакты": {"email": "maria@example.com", "телефон": "+79167654321"}}'::JSON AS данные
)
SELECT 
    id,
    данные->'фамилия' AS фамилия,  -- возвращает JSON
    данные->>'фамилия' AS фамилия_как_текст,  -- возвращает текст
    данные->'контакты'->'email' AS email_json,  -- доступ к вложенному значению
    данные->'контакты'->>'email' AS email_текст  -- вложенный доступ, результат - текст
FROM пример_json;
```

#### Работа с JSONB (более эффективный формат)

```sql
-- Работа с JSONB
WITH пример_jsonb AS (
    SELECT 
        1 AS id,
        JSONB_BUILD_OBJECT(
            'фамилия', 'Иванов',
            'имя', 'Иван',
            'возраст', 30,
            'адрес', JSONB_BUILD_OBJECT(
                'город', 'Москва',
                'улица', 'Тверская',
                'дом', 1
            ),
            'навыки', JSONB_BUILD_ARRAY('SQL', 'Python', 'PostgreSQL')
        ) AS данные
)
SELECT 
    id,
    данные->>'фамилия' AS фамилия,
    (данные->>'возраст')::INTEGER AS возраст,
    данные->'адрес'->>'город' AS город,
    данные->'навыки' AS навыки_массив,
    JSONB_ARRAY_LENGTH(данные->'навыки') AS количество_навыков
FROM пример_jsonb;
```

### Функции для работы с JSON

#### JSONB_ARRAY_ELEMENTS

Разбирает JSON массив на отдельные элементы:

```sql
WITH навыки AS (
    SELECT 
        1 AS id,
        JSONB_BUILD_ARRAY('SQL', 'Python', 'PostgreSQL', 'JavaScript') AS список_навыков
    UNION ALL
    SELECT 
        2 AS id,
        JSONB_BUILD_ARRAY('Java', 'Spring', 'PostgreSQL') AS список_навыков
)
SELECT 
    id,
    JSONB_ARRAY_ELEMENTS(список_навыков) AS отдельный_навык
FROM навыки;
```

#### JSONB_EACH

Разбирает JSON объект на ключ-значение:

```sql
WITH профиль AS (
    SELECT 
        1 AS id,
        JSONB_BUILD_OBJECT(
            'фамилия', 'Иванов',
            'имя', 'Иван',
            'возраст', 30,
            'активный', true
        ) AS данные
)
SELECT 
    id,
    key,
    value
FROM профиль, JSONB_EACH(данные);
```

#### JSONB_EXTRACT_PATH

Более явное извлечение по пути:

```sql
WITH пользователи AS (
    SELECT 
        1 AS id,
        JSONB_BUILD_OBJECT(
            'личные_данные', 
            JSONB_BUILD_OBJECT(
                'фамилия', 'Иванов',
                'имя', 'Иван',
                'контакты', 
                JSONB_BUILD_OBJECT(
                    'email', 'ivan@example.com',
                    'телефоны', 
                    JSONB_BUILD_ARRAY(
                        '+79161234567',
                        '+79167654321'
                    )
                )
            )
        ) AS профиль
)
SELECT 
    id,
    JSONB_EXTRACT_PATH(proфиль, 'личные_данные', 'фамилия') AS фамилия,
    JSONB_EXTRACT_PATH(proфиль, 'личные_данные', 'контакты', 'email') AS email
FROM пользователи;
```

### Обновление JSON данных

#### JSONB_SET

Обновление значений в JSONB:

```sql
WITH данные AS (
    SELECT 
        1 AS id,
        JSONB_BUILD_OBJECT(
            'фамилия', 'Иванов',
            'имя', 'Иван',
```

#### JSONB_INSERT

Вставка новых значений:

```sql

        JSONB_BUILD_OBJECT(

            'имя', 'Иван'
```

### Поиск и фильтрация JSON данных

#### Операторы поиска

```sql
-- Создание таблицы с JSON данными
CREATE TEMPORARY TABLE клиенты_json AS
SELECT 
    id,
    JSONB_BUILD_OBJECT(
        'фамилия', фамилия,
        'имя', имя,
        'город', город,
        'возраст', EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения),
        'регистрация', дата_регистрации,
        'категории', 
        CASE 
            WHEN EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения) < 30 THEN 
                JSONB_BUILD_ARRAY('молодежь')
            WHEN EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения) BETWEEN 30 AND 50 THEN
                JSONB_BUILD_ARRAY('средний возраст')
            ELSE
                JSONB_BUILD_ARRAY('зрелый возраст')
        END
    ) AS профиль
FROM клиенты
WHERE фамилия IS NOT NULL AND имя IS NOT NULL;

-- Поиск по JSON данным
SELECT 
    профиль->>'фамилия' AS фамилия,
    (профиль->>'возраст')::INTEGER AS возраст,
    профиль->'категории' AS категории
FROM клиенты_json
WHERE (профиль->>'город')::TEXT = 'Москва'
  AND (профиль->>'возраст')::INTEGER > 25;
```

#### Использование оператора @> (содержит)

```sql
-- Найти клиентов с определенной категорией
SELECT 
    профиль->>'фамилия' AS фамилия,
    профиль->'категории' AS категории
FROM клиенты_json
WHERE профиль->'категории' @> '["молодежь"]'::JSONB;
```

## Глава 46: Window функции (расширенное использование)

### Введение

В предыдущих главах мы рассмотрели основы оконных функций. В этой главе мы углубимся в расширенные возможности оконных функций, включая сложные рамки окон, расширенные статистические функции и продвинутые сценарии использования.

### Продвинутые рамки окон (Window Frames)

#### ROWS vs RANGE

```sql
-- ROWS: определяет рамки по количеству строк
-- RANGE: определяет рамки по значению упорядочивания
WITH заказы_с_рейтингом AS (
    SELECT 
        дата_заказа,
        общая_сумма,
        ROW_NUMBER() OVER (ORDER BY общая_сумма) AS номер
    FROM заказы
    WHERE общая_сумма IS NOT NULL
    LIMIT 10
)
SELECT 
    дата_заказа,
    общая_сумма,
    -- Скользящее среднее за 3 строки (текущая + 1 до и 1 после)
    AVG(общая_сумма) OVER (
        ORDER BY общая_сумма
        ROWS BETWEEN 1 PRECEDING AND 1 FOLLOWING
    ) AS среднее_3_строки,
    -- Сумма для всех строк с той же и меньшей суммой (RANGE)
    SUM(общая_сумма) OVER (
        ORDER BY общая_сумма
        RANGE BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS сумма_с_начала
FROM заказы_с_рейтингом
ORDER BY общая_сумма;
```

#### Комплексные рамки окон

```sql
-- Пример с более сложными рамками
SELECT 
    дата_заказа,
    общая_сумма,
    -- Среднее значение для 5 ближайших по значению заказов
    AVG(общая_сумма) OVER (
        ORDER BY общая_сумма
        ROWS BETWEEN 2 PRECEDING AND 2 FOLLOWING
    ) AS среднее_5_соседей,
    -- Среднее для всех заказов с суммой в диапазоне +/- 10000 от текущего
    AVG(общая_сумма) OVER (
        ORDER BY общая_сумма
        RANGE BETWEEN 10000 PRECEDING AND 10000 FOLLOWING
    ) AS среднее_в_диапазоне,
    -- Текущий заказ в сравнении с рамками
    COUNT(*) OVER (
        ORDER BY общая_сумма
        ROWS BETWEEN 5 PRECEDING AND CURRENT ROW
    ) AS количество_в_рамке_6_заказов
FROM заказы
WHERE общая_сумма IS NOT NULL
ORDER BY общая_сумма
LIMIT 15;
```

### Расширенные статистические функции

#### PERCENT_RANK и CUME_DIST

```sql
SELECT 
    фамилия,
    имя,
    (SELECT SUM(общая_сумма) FROM заказы WHERE id_клиента = клиенты.id) AS общая_сумма_заказов,
    -- Процентный ранг (от 0 до 1)
    PERCENT_RANK() OVER (ORDER BY (SELECT SUM(общая_сумма) FROM заказы WHERE id_клиента = клиенты.id)) AS процентный_ранг,
    -- Кумулятивное распределение (тоже от 0 до 1)
    CUME_DIST() OVER (ORDER BY (SELECT SUM(общая_сумма) FROM заказы WHERE id_клиента = клиенты.id)) AS кумулятивное_распределение
FROM клиенты
WHERE EXISTS (SELECT 1 FROM заказы WHERE id_клиента = клиенты.id)
ORDER BY общая_сумма_заказов DESC
LIMIT 10;
```

#### NTILE - разбиение на группы

```sql
-- Разбиение клиентов на 4 группы (квартили) по общей сумме заказов
WITH клиенты_с_суммами AS (
    SELECT 
        к.id,
        к.фамилия,
        к.имя,
        COALESCE((SELECT SUM(общая_сумма) FROM заказы WHERE id_клиента = к.id), 0) AS общая_сумма
    FROM клиенты к
)
SELECT 
    фамилия,
    имя,
    общая_сумма,
    NTILE(4) OVER (ORDER BY общая_сумма DESC) AS квартиль,
    NTILE(10) OVER (ORDER BY общая_сумма DESC) AS дециль
FROM клиенты_с_суммами
ORDER BY общая_сумма DESC;
```

#### CORR, REGR_* функции (корреляция и регрессия)

```sql
-- Пример корреляции (PostgreSQL поддерживает статистические оконные функции)
WITH клиенты_с_активностью AS (
    SELECT 
        к.id AS клиент_id,
        к.фамилия,
        COUNT(з.id) AS количество_заказов,
        SUM(з.общая_сумма) AS общая_сумма,
        AVG(з.общая_сумма) AS средний_чек
    FROM клиенты к
    LEFT JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.id, к.фамилия
)
SELECT 
    фамилия,
    количество_заказов,
    общая_сумма,
    -- Можно использовать статистические функции для анализа корреляции
    CORR(количество_заказов, общая_сумма) OVER () AS корреляция_заказы_сумма
FROM клиенты_с_активностью
ORDER BY общая_сумма DESC
LIMIT 10;
```

### Сложные сценарии использования оконных функций

#### Пример 1: Скользящие метрики с фильтрацией

```sql
-- Скользящее среднее с фильтрацией определенных значений
WITH заказы_с_фильтром AS (
    SELECT 
        дата_заказа,
        общая_сумма,
        -- Пропустить заказы меньше 10000 при вычислении скользящего среднего
        CASE WHEN общая_сумма >= 10000 THEN общая_сумма END AS подходящая_сумма
    FROM заказы
)
SELECT 
    дата_заказа,
    общая_сумма,
    подходящая_сумма,
    -- Скользящее среднее только подходящих значений за 5 предыдущих заказов
    AVG(подходящая_сумма) OVER (
        ORDER BY дата_заказа, общая_сумма
        ROWS BETWEEN 4 PRECEDING AND CURRENT ROW
    ) AS среднее_подходящих_за_5
FROM заказы_с_фильтром
ORDER BY дата_заказа
LIMIT 15;
```

#### Пример 2: Сравнение с групповыми агрегатами

```sql
-- Сравнение клиента с его группой по городу, используя оконные функции
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    клиентская_статистика.общая_сумма,
    клиентская_статистика.количество_заказов,
    -- Среднее по городу
    AVG(клиентская_статистика.общая_сумма) OVER (PARTITION BY к.город) AS среднее_в_городе,
    -- Отклонение от среднего по городу
    (клиентская_статистика.общая_сумма - AVG(клиентская_статистика.общая_сумма) OVER (PARTITION BY к.город)) AS отклонение_от_города,
    -- Ранг в городе
    RANK() OVER (PARTITION BY к.город ORDER BY клиентская_статистика.общая_сумма DESC) AS ранг_в_городе,
    -- Процентиль в городе
    PERCENT_RANK() OVER (PARTITION BY к.город ORDER BY клиентская_статистика.общая_сумма) AS процентиль_в_городе
FROM клиенты к
JOIN (
    SELECT 
        id_клиента,
        SUM(общая_сумма) AS общая_сумма,
        COUNT(*) AS количество_заказов
    FROM заказы
    GROUP BY id_клиента
) AS клиентская_статистика ON к.id = клиентская_статистика.id_клиента
ORDER BY к.город, клиентская_статистика.общая_сумма DESC;
```

#### Пример 3: Рекурсивное накопление с условиями

```sql
-- Сложная логика накопления с условиями
WITH заказы_с_событиями AS (
    SELECT 
        id,
        id_клиента,
        дата_заказа,
        общая_сумма,
        -- Определяем "событие" - заказ выше среднего
        CASE WHEN общая_сумма > (SELECT AVG(общая_сумма) FROM заказы) THEN 1 ELSE 0 END AS высокий_заказ
    FROM заказы
)
SELECT 
    id_клиента,
    дата_заказа,
    общая_сумма,
    высокий_заказ,
    -- Накопительное количество высоких заказов
    SUM(высокий_заказ) OVER (
        PARTITION BY id_клиента 
        ORDER BY дата_заказа 
        ROWS UNBOUNDED PRECEDING
    ) AS накопительное_высоких_заказов,
    -- Номер текущего "события" (высокого заказа) для клиента
    SUM(высокий_заказ) OVER (
        PARTITION BY id_клиента 
        ORDER BY дата_заказа 
        ROWS UNBOUNDED PRECEDING
    ) * высокий_заказ AS номер_события,
    -- Скользящее среднее за последние 3 заказа
    AVG(общая_сумма) OVER (
        PARTITION BY id_клиента 
        ORDER BY дата_заказа 
        ROWS BETWEEN 2 PRECEDING AND CURRENT ROW
    ) AS среднее_за_3_заказа
FROM заказы_с_событиями
ORDER BY id_клиента, дата_заказа
LIMIT 20;
```

### Оконные функции в сложных аналитических запросах

#### Пример 4: Бизнес-логика с оконными функциями

```sql
-- Модель для определения "валидных" периодов активности клиентов
WITH клиенты_с_активностью AS (
    SELECT 
        id_клиента,
        дата_заказа,
        общая_сумма,
        -- Определяем активный день: если был заказ
        1 AS активный_день,
        -- Считаем дни с последнего заказа
        дата_заказа - LAG(дата_заказа) OVER (
            PARTITION BY id_клиента 
            ORDER BY дата_заказа
        ) AS дни_с_последнего_заказа
    FROM заказы
)
SELECT 
    id_клиента,
    дата_заказа,
    общая_сумма,
    активный_день,
    дни_с_последнего_заказа,
    -- Определяем, активен ли клиент (менее 30 дней с последнего заказа)
    CASE WHEN дни_с_последнего_заказа <= INTERVAL '30 days' OR дни_с_последнего_заказа IS NULL 
         THEN 1 ELSE 0 END AS условно_активен,
    -- Накопительное количество "активных" периодов
    SUM(CASE WHEN дни_с_последнего_заказа <= INTERVAL '30 days' OR дни_с_последнего_заказа IS NULL 
             THEN 1 ELSE 0 END) 
    OVER (
        PARTITION BY id_клиента 
        ORDER BY дата_заказа 
        ROWS UNBOUNDED PRECEDING
    ) AS накопительная_активность
FROM клиенты_с_активностью
ORDER BY id_клиента, дата_заказа
LIMIT 25;
```

#### Пример 5: Сегментация клиентов с использованием оконных функций

```sql
-- Сегментация клиентов по сложной логике с оконными функциями
WITH клиенты_с_историей AS (
    SELECT 
        к.id,
        к.фамилия,
        к.имя,
        COUNT(з.id) AS всего_заказов,
        SUM(з.общая_сумма) AS общая_сумма,
        AVG(з.общая_сумма) AS средний_чек,
        MIN(з.дата_заказа) AS первый_заказ,
        MAX(з.дата_заказа) AS последний_заказ,
        -- Частота заказов (дней между первым и последним / количество заказов)
        CASE 
            WHEN COUNT(з.id) > 1 THEN 
                EXTRACT(DAY FROM (MAX(з.дата_заказа) - MIN(з.дата_заказа))) / (COUNT(з.id) - 1)
            ELSE NULL
        END AS средняя_частота_в_днях
    FROM клиенты к
    LEFT JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.id, к.фамилия, к.имя
)
SELECT 
    фамилия,
    имя,
    всего_заказов,
    общая_сумма,
    средний_чек,
    средняя_частота_в_днях,
    -- Ранги по разным показателям
    PERCENT_RANK() OVER (ORDER BY общая_сумма) AS ранг_по_сумме,
    PERCENT_RANK() OVER (ORDER BY всего_заказов) AS ранг_по_количеству,
    PERCENT_RANK() OVER (ORDER BY средний_чек) AS ранг_по_среднему,
    -- Комбинированный скор (усредненный процентный ранг)
    (PERCENT_RANK() OVER (ORDER BY общая_сумма) +
     PERCENT_RANK() OVER (ORDER BY всего_заказов) +
     PERCENT_RANK() OVER (ORDER BY средний_чек)) / 3 AS комбинированный_скор,
    -- Сегментация
    CASE 
        WHEN 
            PERCENT_RANK() OVER (ORDER BY общая_сумма) > 0.8 AND
            PERCENT_RANK() OVER (ORDER BY всего_заказов) > 0.8
        THEN 'VIP'
        WHEN 
            PERCENT_RANK() OVER (ORDER BY общая_сумма) > 0.5 OR
            PERCENT_RANK() OVER (ORDER BY всего_заказов) > 0.5
        THEN 'Постоянный'
        WHEN 
            PERCENT_RANK() OVER (ORDER BY общая_сумма) > 0.2
        THEN 'Перспективный'
        ELSE 'Новый'
    END AS сегмент_клиента
FROM клиенты_с_историей
WHERE всего_заказов > 0  -- Только клиенты с заказами
ORDER BY комбинированный_скор DESC
LIMIT 15;
```

### Эффективное использование оконных функций

#### Оптимизация производительности

```sql
-- Плохо: несколько оконных функций с одинаковым окном
SELECT 
    фамилия,
    -- Эти функции используют одно и то же окно, лучше объединить
    ROW_NUMBER() OVER (ORDER BY дата_регистрации) AS rn1,
    RANK() OVER (ORDER BY дата_регистрации) AS rk1,
    DENSE_RANK() OVER (ORDER BY дата_регистрации) AS dr1
FROM клиенты;

-- Лучше: использовать CTE для сложных оконных вычислений
WITH клиенты_с_окнами AS (
    SELECT 
        *,
        ROW_NUMBER() OVER (ORDER BY дата_регистрации) AS rn,
        RANK() OVER (ORDER BY дата_регистрации) AS rk,
        DENSE_RANK() OVER (ORDER BY дата_регистрации) AS dr
    FROM клиенты
)
SELECT фамилия, rn, rk, dr
FROM клиенты_с_окнами;
```

#### Использование FILTER с оконными функцими

```sql
-- PostgreSQL поддерживает FILTER для агрегатных функций в окнах
SELECT 
    id_клиента,
    дата_заказа,
    общая_сумма,
    -- Средняя сумма заказов только для заказов выше 50000
    AVG(общая_сумма) FILTER (WHERE общая_сумма > 50000) 
    OVER (PARTITION BY id_клиента) AS среднее_высоких_заказов,
    -- Количество высоких заказов
    COUNT(*) FILTER (WHERE общая_сумма > 50000) 
    OVER (PARTITION BY id_клиента) AS количество_высоких_заказов
FROM заказы
ORDER BY id_клиента, дата_заказа
LIMIT 20;
```

### Практические советы

#### Совет 1: Понимание порядка выполнения

```sql
-- Оконные функции вычисляются перед ORDER BY в целом запросе
-- Но ORDER BY внутри OVER() влияет на результат оконной функции
SELECT 
    общая_сумма,
    ROW_NUMBER() OVER (ORDER BY дата_заказа) AS ранг_по_дате,
    ROW_NUMBER() OVER (ORDER BY общая_сумма DESC) AS ранг_по_сумме
FROM заказы
ORDER BY дата_заказа;  -- Этот ORDER BY не влияет на оконные функции
```

#### Совет 2: Использование PARTITION BY для группировки

```sql
-- PARTITION BY создает отдельные "окна" для вычислений
SELECT 
    к.город,
    к.фамилия,
    -- Ранг в пределах каждого города
    ROW_NUMBER() OVER (PARTITION BY к.город ORDER BY (SELECT SUM(общая_сумма) FROM заказы WHERE id_клиента = к.id) DESC) AS ранг_в_городе
FROM клиенты к
WHERE EXISTS (SELECT 1 FROM заказы WHERE id_клиента = к.id)
ORDER BY к.город, ранг_в_городе;
```

#### Совет 3: Объединение оконных и обычных функций

```sql
-- Можно комбинировать оконные функции с обычными агрегатами в подзапросах
WITH статистика AS (
    SELECT 
        id_клиента,
        COUNT(*) AS кол_заказов,
        SUM(общая_сумма) AS общая_сумма,
        AVG(общая_сумма) AS средний_чек
    FROM заказы
    GROUP BY id_клиента
)
SELECT 
    id_клиента,
    кол_заказов,
    общая_сумма,
    -- Оконные функции для анализа статистики
    PERCENT_RANK() OVER (ORDER BY общая_сумма) AS процентиль_по_сумме,
    CASE 
        WHEN PERCENT_RANK() OVER (ORDER BY общая_сумма) > 0.8 THEN 'Топ'
        WHEN PERCENT_RANK() OVER (ORDER BY общая_сумма) > 0.5 THEN 'Выше среднего'
        ELSE 'Ниже среднего'
    END AS категория_по_объему
FROM статистика
ORDER BY общая_сумма DESC;
```

### Заключение главы

Оконные функции - один из самых мощных инструментов в SQL, позволяющий выполнять сложные аналитические вычисления без необходимости в сложных соединениях или подзапросах. Расширенное использование оконных функций, включая сложные рамки, статистические функции и комбинации с другими возможностями SQL, открывает широкие возможности для анализа данных.

Владение оконными функциями на продвинутом уровне - важный навык для специалистов по анализу данных и позволяет решать сложные задачи, которые в противном случае потребовали бы сложной логики на уровне приложения.
