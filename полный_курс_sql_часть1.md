## Глава 2: Введение в реляционные базы данных

### Что такое базы данных?

Представьте себе огромную электронную таблицу, в которой хранится вся информация о клиентах вашей компании, их заказах, товарах, поставщиках и т.д. Это и есть база данных. База данных - это организованное хранилище информации, которое позволяет эффективно сохранять, находить, обновлять и управлять данными.

### Типы баз данных

Существует несколько типов баз данных, но мы сосредоточимся на реляционных базах данных (RDBMS), которые используются в большинстве крупных организаций:

1. **Реляционные базы данных**:
   - Используют структуру таблиц с рядами и столбцами
   - Примеры: PostgreSQL, MySQL, Oracle, Microsoft SQL Server
   - Идеально подходят для структурированных данных с четкими взаимосвязями

2. **Нереляционные базы данных (NoSQL)**:
   - Предназначены для неструктурированных или полуструктурированных данных
   - Примеры: MongoDB, Redis, Cassandra
   - Подходят для больших объемов данных с гибкой структурой

### Почему именно реляционные базы данных?

Реляционные базы данных особенно популярны в бизнес-среде по следующим причинам:

- **Надежность**: Сохраняют целостность данных даже при сбоях
- **Безопасность**: Встроенные механизмы защиты информации
- **Масштабируемость**: Возможность работы с миллиардами записей
- **Стандартизация**: SQL - это общепринятый стандарт
- **Поддержка транзакций**: Гарантия целостности сложных операций

### Основные компоненты реляционной базы данных:

1. **Таблицы** - основные структуры для хранения данных
2. **Поля (столбцы)** - атрибуты данных
3. **Записи (строки)** - отдельные экземпляры данных
4. **Ключи** - уникальные идентификаторы для установления связей
5. **Связи** - отношения между таблицами

### Пример из российской практики:

Представьте, что вы работаете в крупной российской сети магазинов "Магнолия". В базе данных этой сети есть:

- Таблица "Клиенты" - с именами, телефонами, e-mail и адресами
- Таблица "Товары" - с названиями, ценами, категориями и остатками
- Таблица "Чеки" - с ID клиента, ID товаров, датой покупки и суммой
- Таблица "Сотрудники" - с ФИО, должностью, зарплатой и отделом

Эти таблицы связаны между собой, позволяя получить полную картину бизнеса.

### Преимущества реляционных баз данных:

- **Структурированное хранение данных**: Четкая организация информации
- **Целостность данных**: Встроенные правила проверки
- **Гибкость запросов**: Возможность извлекать нужные данные разными способами
- **Многопользовательский доступ**: Несколько человек могут работать одновременно
- **Безопасность**: Разграничение прав доступа к информации

### Основные принципы реляционных баз данных:

1. **Нормализация** - процесс организации данных для уменьшения избыточности
2. **Целостность сущностей** - каждая запись имеет уникальный идентификатор
3. **Целостность ссылок** - связи между таблицами поддерживаются корректно
4. **Транзакции** - группы операций выполняются как единое целое

### Заключение главы:

Понимание основ реляционных баз данных - фундамент для изучения SQL. В следующей главе мы установим PostgreSQL и PgAdmin - программное обеспечение, которое будем использовать для практики. Вы узнаете, как создать свою первую базу данных и выполнить первые SQL-запросы.

## Глава 3: Установка PostgreSQL и PgAdmin

### Введение

PostgreSQL - одна из самых мощных и гибких систем управления реляционными базами данных с открытым исходным кодом. Она широко используется в крупных российских компаниях, таких как Яндекс, Mail.ru Group и других. В этой главе вы узнаете, как установить PostgreSQL и PgAdmin на ваш компьютер.

### Почему именно PostgreSQL?

PostgreSQL был выбран для этого курса по следующим причинам:

- **Современные возможности**: Поддержка JSON, полнотекстового поиска, географических данных
- **Безопасность**: Высокий уровень защиты данных
- **Надежность**: Восстановление после сбоев, репликация
- **Производительность**: Отличная работа с большими объемами данных
- **Бесплатность**: Полностью бесплатная система с открытым исходным кодом
- **Поддержка стандартов**: Полное соответствие SQL-стандартам

### Подготовка к установке

Прежде чем начать установку, проверьте системные требования:

**Для Windows:**
- Операционная система: Windows 7/8/10/11 (64-разрядная)
- Процессор: Современный многоядерный процессор
- ОЗУ: Минимум 2 ГБ (рекомендуется 4 ГБ и более)
- Свободное место: Минимум 200 МБ для установки

**Для macOS:**
- macOS версии 10.13 и выше
- Процессор: Intel или Apple Silicon
- ОЗУ: Минимум 2 ГБ
- Свободное место: Минимум 200 МБ

### Установка PostgreSQL на Windows

1. **Скачивание установщика:**
   - Перейдите на официальный сайт PostgreSQL: https://www.postgresql.org/
   - Нажмите "Download" и выберите вашу операционную систему
   - Скачайте установочный файл (обычно "postgresql-15.x-x64.exe")

2. **Запуск установки:**
   - Запустите скачанный файл от имени администратора
   - Следуйте пошаговому мастеру установки
   - На главном экране нажмите "Next"

3. **Выбор компонентов:**
   - Установите все компоненты по умолчанию (Server, Client, Documentation)
   - Нажмите "Next"

4. **Указание директории установки:**
   - Примите предложенный путь или укажите свой
   - Нажмите "Next"

5. **Указание директории данных:**
   - Укажите место, где будут храниться данные базы
   - Рекомендуется использовать путь без кириллицы
   - Нажмите "Next"

6. **Установка пароля суперпользователя:**
   - Установите надежный пароль для пользователя "postgres"
   - Запомните его или сохраните в надежном месте
   - Нажмите "Next"

7. **Указание порта:**
   - Примите порт по умолчанию (обычно 5432)
   - Нажмите "Next"

8. **Выбор региона:**
   - Выберите "Default locale: Russian_Russia.1251" или "English_United States.1252"
   - Нажмите "Next"

9. **Завершение установки:**
   - Установите галочку "Stack Builder" если хотите установить дополнительные компоненты
   - Нажмите "Finish"

### Установка PgAdmin

PgAdmin - это веб-интерфейс для управления PostgreSQL. Он особенно удобен для новичков.

1. **Скачивание PgAdmin:**
   - Перейдите на https://www.pgadmin.org/
   - Скачайте версию для вашей операционной системы

2. **Установка PgAdmin:**
   - Запустите установочный файл
   - Следуйте инструкциям мастера установки
   - Примите лицензионное соглашение
   - Выберите компоненты установки
   - Укажите директорию установки
   - Завершите установку

### Проверка установки

1. **Запустите PgAdmin:**
   - Найдите PgAdmin в меню "Пуск" (Windows) или Launchpad (macOS)
   - Запустите приложение

2. **Подключение к серверу:**
   - В левой панели нажмите правой кнопкой мыши на "Servers"
   - Выберите "Create" → "Server"
   - В открывшемся окне перейдите на вкладку "Connection"
   - Введите следующие данные:
     - Host name/address: localhost
     - Port: 5432 (или другой, если изменяли при установке)
     - Maintenance database: postgres
     - Username: postgres
     - Password: введите пароль, который вы установили при установке PostgreSQL

3. **Создание первой базы данных:**
   - Правой кнопкой мыши нажмите на "Databases"
   - Выберите "Create" → "Database"
   - Введите имя базы данных (например, "my_first_db")
   - Нажмите "Save"

### Тестирование подключения

После создания базы данных дважды щелкните по ней в дереве слева. Если все установлено правильно, вы увидите структуру базы данных.

### Решение типичных проблем

1. **Ошибка подключения:**
   - Проверьте, запущен ли сервис PostgreSQL
   - Убедитесь, что порт 5432 не заблокирован брандмауэром
   - Проверьте правильность введенных данных

2. **Проблемы с паролем:**
   - Попробуйте использовать пароль, установленный при установке
   - Если забыли пароль, можно его сбросить через командную строку

3. **Проблемы с PgAdmin:**
   - Убедитесь, что PgAdmin совместим с вашей версией PostgreSQL
   - Попробуйте запустить PgAdmin от имени администратора

### Альтернативные инструменты

Хотя мы рекомендуем PgAdmin для новичков, существуют и другие инструменты:

- **DBeaver** - универсальный инструмент для работы с разными СУБД
- **DataGrip** - коммерческий инструмент от JetBrains
- **psql** - командная строка PostgreSQL (для продвинутых пользователей)

## Глава 4: Базовые концепции SQL и терминология

### Что такое SQL?

SQL (Structured Query Language) - это язык структурированных запросов, используемый для управления и манипулирования реляционными базами данных. SQL не является языком программирования в полном смысле слова, а представляет собой декларативный язык, в котором вы описываете, что хотите получить, а не как это получить.

### Основные категории SQL-команд:

1. **DDL (Data Definition Language)** - языки определения данных:
   - CREATE - создание объектов базы данных
   - ALTER - изменение структуры объектов
   - DROP - удаление объектов
   - TRUNCATE - удаление всех записей из таблицы

2. **DML (Data Manipulation Language)** - языки манипулирования данными:
   - SELECT - выборка данных
   - INSERT - вставка данных
   - UPDATE - обновление данных
   - DELETE - удаление данных

3. **DCL (Data Control Language)** - языки контроля данных:
   - GRANT - предоставление прав
   - REVOKE - отмена прав

4. **TCL (Transaction Control Language)** - языки управления транзакциями:
   - COMMIT - фиксация изменений
   - ROLLBACK - отмена изменений
   - SAVEPOINT - создание точки сохранения

### Основные элементы SQL-запроса:

1. **Ключевые слова (Keywords)**:
   - Зарезервированные слова, которые имеют специальное значение (SELECT, FROM, WHERE, etc.)
   - В SQL регистр не имеет значения, но общепринято писать ключевые слова заглавными буквами

2. **Идентификаторы (Identifiers)**:
   - Имена таблиц, столбцов, пользователей, баз данных
   - Могут содержать буквы, цифры и подчеркивания
   - Не должны начинаться с цифры

3. **Литералы (Literals)**:
   - Конкретные значения в запросе
   - Например: 'Иванов', 1000, '2023-01-01'

4. **Операторы (Operators)**:
   - Специальные символы для выполнения операций
   - Арифметические: +, -, *, /
   - Сравнения: =, !=, <>, <, >, <=, >=
   - Логические: AND, OR, NOT

### Структура типичного SQL-запроса:

```
SELECT [столбцы или выражения]
FROM [таблица]
[WHERE условие]
[GROUP BY группировка]
[HAVING условие для групп]
[ORDER BY сортировка]
[LIMIT ограничение];
```

### Основные термины SQL:

1. **Таблица (Table)**:
   - Основной объект для хранения данных
   - Представляет собой двумерную структуру из строк и столбцов

2. **Строка (Row)**:
   - Горизонтальная запись в таблице
   - Соответствует одной записи или экземпляру данных

3. **Столбец (Column)**:
   - Вертикальная структура в таблице
   - Определяет тип данных и атрибуты записи

4. **Ключ (Key)**:
   - Поле или комбинация полей, используемых для идентификации записей
   - Первичный ключ (Primary Key) - уникально идентифицирует каждую строку
   - Внешний ключ (Foreign Key) - устанавливает связи между таблицами

5. **Индекс (Index)**:
   - Структура, ускоряющая поиск данных
   - Подобен оглавлению в книге

6. **Запрос (Query)**:
   - Команда, отправляемая базе данных для получения или изменения данных

### Типы данных в PostgreSQL:

1. **Числовые типы:**
   - INTEGER, BIGINT - целые числа
   - DECIMAL, NUMERIC - числа с фиксированной точностью
   - REAL, DOUBLE PRECISION - числа с плавающей точкой

2. **Текстовые типы:**
   - CHAR(n) - фиксированная длина
   - VARCHAR(n) - переменная длина до n символов
   - TEXT - неограниченная длина

3. **Типы даты и времени:**
   - DATE - только дата
   - TIME - только время
   - TIMESTAMP - дата и время

4. **Логический тип:**
   - BOOLEAN - значения true/false

### Основные соглашения о форматировании:

1. **Ключевые слова** - заглавными буквами
2. **Имена таблиц и столбцов** - строчными (или как определено в базе)
3. **Значения строк** - в одинарных кавычках
4. **Отступы** - для улучшения читаемости сложных запросов
5. **Комментарии**:
   - Однострочные: --
   - Многострочные: /* ... */

# Раздел 2: Основы SQL

## Глава 6: Шпаргалка по SQL

Для удобства изучения SQL, ниже приведена краткая шпаргалка по основным командам. Эта шпаргалка будет полезна на протяжении всего курса и в дальнейшей практике.

### Основные команды выборки данных

1. **SELECT** - выборка данных из таблицы
   - `SELECT * FROM имя_таблицы;` - выбрать все данные
   - `SELECT столбец1, столбец2 FROM имя_таблицы;` - выбрать конкретные столбцы
   - `SELECT DISTINCT столбец FROM имя_таблицы;` - выбрать уникальные значения

2. **WHERE** - фильтрация данных
   - `WHERE условие` - добавить условие к выборке
   - `WHERE столбец = 'значение'` - равенство
   - `WHERE столбец > значение` - больше
   - `WHERE столбец BETWEEN нач_значение AND кон_значение` - в диапазоне
   - `WHERE столбец IN ('знач1', 'знач2')` - в списке
   - `WHERE столбец LIKE 'шаблон%'` - по шаблону

3. **ORDER BY** - сортировка
   - `ORDER BY столбец ASC` - по возрастанию
   - `ORDER BY столбец DESC` - по убыванию

4. **LIMIT и OFFSET** - ограничение количества результатов
   - `LIMIT 10` - получить первые 10 строк
   - `OFFSET 5` - пропустить первые 5 строк

### Основные агрегатные функции

1. **COUNT()** - подсчет количества строк
2. **SUM()** - сумма значений
3. **AVG()** - среднее значение
4. **MIN()** - минимальное значение
5. **MAX()** - максимальное значение

### Основные команды изменения данных

1. **INSERT** - вставка данных
   - `INSERT INTO имя_таблицы (столбец1, столбец2) VALUES (знач1, знач2);`

2. **UPDATE** - обновление данных
   - `UPDATE имя_таблицы SET столбец1 = знач1 WHERE условие;`

3. **DELETE** - удаление данных
   - `DELETE FROM имя_таблицы WHERE условие;`

### Основные команды определения данных

1. **CREATE TABLE** - создание таблицы
2. **ALTER TABLE** - изменение структуры таблицы
3. **DROP TABLE** - удаление таблицы

### Основные логические операторы

1. **AND** - логическое И
2. **OR** - логическое ИЛИ
3. **NOT** - логическое НЕ

### Основные функции строк

1. **UPPER()** - преобразование в верхний регистр
2. **LOWER()** - преобразование в нижний регистр
3. **LENGTH()** - длина строки
4. **SUBSTRING()** - подстрока

### Основные функции дат

1. **CURRENT_DATE** - текущая дата
2. **CURRENT_TIMESTAMP** - текущая дата и время
3. **EXTRACT()** - извлечение части даты (год, месяц, день и т.д.)

### Основы группировки

1. **GROUP BY** - группировка данных
2. **HAVING** - фильтрация групп (аналог WHERE для групп)

### Основы соединения таблиц

1. **INNER JOIN** - внутреннее соединение
2. **LEFT JOIN** - левое внешнее соединение
3. **RIGHT JOIN** - правое внешнее соединение
4. **FULL OUTER JOIN** - полное внешнее соединение

### Основы управления транзакциями

1. **BEGIN** - начало транзакции
2. **COMMIT** - фиксация изменений
3. **ROLLBACK** - отмена изменений

### Примеры часто используемых запросов

1. **Выбрать все данные из таблицы:**
   ```sql
   SELECT * FROM клиенты;
   ```

2. **Выбрать определенные столбцы с фильтрацией:**
   ```sql

## Глава 8: Оператор SELECT

### Введение

Оператор `SELECT` - это основной инструмент для извлечения данных из базы данных. Он позволяет получать информацию из одной или нескольких таблиц и формировать результаты в необходимом виде. В этой главе мы подробно рассмотрим все аспекты использования оператора `SELECT`.

### Базовый синтаксис SELECT

```sql
SELECT столбцы
FROM таблица
[WHERE условие]
[ORDER BY сортировка]
[LIMIT ограничение];
```

Каждая часть запроса играет свою роль:
- `SELECT` - определяет, какие столбцы нужно выбрать
- `FROM` - указывает таблицу, из которой берутся данные
- `WHERE` - фильтрует строки по заданным условиям
- `ORDER BY` - упорядочивает результаты
- `LIMIT` - ограничивает количество возвращаемых строк

### Выбор всех столбцов

```sql
SELECT * FROM клиенты;
```

Символ `*` означает "все столбцы". Это удобно для просмотра всей структуры таблицы, но не рекомендуется в производственных запросах, так как может повлиять на производительность.

### Выбор конкретных столбцов

```sql
SELECT фамилия, имя, город FROM клиенты;
```

Это более предпочтительный способ, особенно если вам нужны только определенные данные.

### Выбор с вычислениями и выражениями

```sql
SELECT 
    фамилия, 
    имя, 
    дата_рождения,
    EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения) AS возраст
FROM клиенты;
```

В этом примере мы вычисляем возраст клиента на основе его даты рождения.

### Работа с литералами

Иногда нужно добавить постоянное значение в результаты:

```sql
SELECT 
    фамилия, 
    имя, 
    'Клиент' AS тип_записи, 
    '+7' AS код_страны
FROM клиенты;
```

### Использование DISTINCT для уникальных значений

```sql
SELECT DISTINCT город FROM клиенты;
```

Этот запрос вернет только уникальные значения городов, исключая дубликаты.

### Псевдонимы (Aliases)

Псевдонимы позволяют давать временные имена столбцам или таблицам:

```sql
SELECT 
    фамилия AS "Фамилия клиента",
    имя AS "Имя клиента",
    (цена * 0.85) AS "Цена со скидкой 15%"
FROM товары;
```

### Работа с NULL значениями

```sql
SELECT 
    фамилия, 
    имя, 
    COALESCE(отчество, 'Нет отчества') AS отчество
FROM клиенты;
```

Функция `COALESCE` возвращает первое ненулевое значение из списка аргументов.

### Примеры из российской практики

Представим, что мы работаем в компании, которая анализирует продажи в различных городах России:

```sql
-- Получить список клиентов с указанием их полного имени
SELECT 
    CONCAT(фамилия, ' ', имя, ' ', COALESCE(отчество, '')) AS полное_имя,
    телефон,
    город
FROM клиенты
ORDER BY фамилия;
```

## Глава 10: SELECT DISTINCT

### Введение

В предыдущих главах мы использовали оператор `SELECT` для получения данных из таблиц. Однако часто нам нужны только уникальные значения, без дубликатов. Для этого используется команда `SELECT DISTINCT`, которая позволяет исключить повторяющиеся строки из результата запроса.

### Что такое DISTINCT?

`DISTINCT` - это ключевое слово, которое указывается после `SELECT` и до списка выбираемых столбцов. Оно удаляет дублирующиеся строки из результата запроса, оставляя только уникальные комбинации значений указанных столбцов.

### Базовый синтаксис

```sql
SELECT DISTINCT столбец1, столбец2, ...
FROM таблица;
```

### Простой пример использования

Предположим, мы хотим получить список всех городов, в которых живут наши клиенты:

```sql
SELECT DISTINCT город
FROM клиенты;
```

Этот запрос вернет только уникальные значения городов, исключая дубликаты.

### Применение DISTINCT к нескольким столбцам

Когда вы указываете несколько столбцов с `DISTINCT`, дубликаты определяются на основе комбинации значений этих столбцов:

```sql
SELECT DISTINCT город, статус
FROM клиенты;
```

Этот запрос вернет все уникальные комбинации значений "город" и "статус".

### Сравнение с GROUP BY

`SELECT DISTINCT` часто можно заменить на `GROUP BY` без использования агрегатных функций:

```sql
-- Использование DISTINCT
SELECT DISTINCT город
FROM клиенты;

-- Эквивалентный запрос с GROUP BY
SELECT город
FROM клиенты
GROUP BY город;
```

Оба запроса дают одинаковый результат, но могут иметь разные показатели производительности в зависимости от базы данных.

### Примеры из российской практики

#### Пример 1: Уникальные категории товаров

```sql
SELECT DISTINCT категория
FROM товары
ORDER BY категория;
```

Этот запрос возвращает все уникальные категории товаров, что может быть полезно для формирования меню на сайте интернет-магазина.

#### Пример 2: Уникальные комбинации город-категория

```sql
SELECT DISTINCT к.город, т.категория
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
JOIN товары т ON з.товар_id = т.id
ORDER BY к.город, т.категория;
```

Этот запрос показывает, какие категории товаров покупают клиенты из разных городов.

#### Пример 3: Уникальные диапазоны цен

```sql
SELECT DISTINCT 
    CASE 
        WHEN цена < 5000 THEN 'до 5000'
        WHEN цена BETWEEN 5000 AND 15000 THEN '5000-15000'
        WHEN цена BETWEEN 15000 AND 50000 THEN '15000-50000'
        ELSE 'более 50000'
    END AS "Диапазон цены"
FROM товары;
```

Этот запрос возвращает уникальные диапазоны цен товаров, полезные для сегментации ассортимента.

   ```

2. **Создание отчетов по уникальным клиентам:**

   ```

3. **Определение уникальных значений для анализа:**

   FROM заказы
   ORDER BY год, месяц;
   ```

### Потенциальные проблемы и решения

#### Проблема: DISTINCT с большим количеством столбцов

При использовании `DISTINCT` с множеством столбцов производительность может снижаться, так как база данных должна сравнивать все комбинации значений. В таких случаях может быть полезно:

1. **Использовать индексы** на столбцах, по которым выполняется `DISTINCT`
2. **Ограничивать количество возвращаемых столбцов**, если это возможно
3. **Применять фильтрацию** до использования `DISTINCT`

#### Пример оптимизации:

```sql
-- Неоптимальный запрос
SELECT DISTINCT *
FROM клиенты;

-- Более оптимальный запрос
SELECT DISTINCT фамилия, имя, отчество, город
FROM клиенты
WHERE дата_регистрации > '2023-01-01';
```

### DISTINCT и NULL-значения

`DISTINCT` обрабатывает `NULL`-значения как равные друг другу:

```sql
SELECT DISTINCT статус
FROM заказы;
```

Если в столбце `статус` есть несколько `NULL`-значений, `DISTINCT` оставит только одно из них в результате.

### Сравнение с другими подходами

| Подход | Когда использовать |
|--------|-------------------|
| `DISTINCT` | Когда нужно получить уникальные значения без дополнительных вычислений |
| `GROUP BY` | Когда нужно использовать агрегатные функции или дополнительные вычисления |
| `ROW_NUMBER()` | Когда нужно оставить один из дубликатов и удалить остальные |

ORDER BY возрастная_группа;
```

#### Задание 9: Уникальные сочетания статусов заказов и городов клиентов

**Сценарий:** Служба логистики хочет понять распределение статусов заказов по регионам.

**Задача:** Выведите все уникальные сочетания статусов заказов и городов клиентов, которые сделали эти заказы.

**Решение:**
```sql
SELECT DISTINCT з.статус, к.город
FROM заказы з
JOIN клиенты к ON з.id_клиента = к.id
ORDER BY з.статус, к.город;
```

#### Задание 10: Уникальные диапазоны общей суммы заказов

**Сценарий:** Финансисты хотят сегментировать заказы по суммовым диапазонам для анализа.

**Задача:** Выведите все уникальные диапазоны общей суммы заказов: "до 10000", "10000-50000", "50000-100000", "100000 и выше".

**Решение:**
```sql
SELECT DISTINCT
    CASE 
        WHEN общая_сумма < 10000 THEN 'до 10000'
        WHEN общая_сумма BETWEEN 10000 AND 50000 THEN '10000-50000'
        WHEN общая_сумма BETWEEN 50000 AND 100000 THEN '50000-100000'
        ELSE '100000 и выше'
    END AS суммовой_диапазон
FROM заказы
ORDER BY суммовой_диапазон;
```

### Продвинутые задания

#### Задание 11: Уникальные сочетания года заказа, города клиента и категории товара

**Сценарий:** Аналитики хотят получить комплексный взгляд на покупательское поведение по годам, регионам и категориям товаров.

**Задача:** Выведите все уникальные сочетания года заказа, города клиента и категории товара. Используйте соединение таблиц клиентов, заказов и товаров.

**Решение:**
```sql
SELECT DISTINCT
    EXTRACT(YEAR FROM з.дата_заказа) AS год,
    к.город,
    т.категория
FROM заказы з
JOIN клиенты к ON з.id_клиента = к.id
JOIN товары т ON т.категория IS NOT NULL
ORDER BY год, к.город, т.категория;
```

#### Задание 12: Уникальные комбинации признаков для сегментации

**Сценарий:** Отдел маркетинга хочет создать сложную систему сегментации клиентов.

**Задача:** Выведите уникальные комбинации: возрастная группа клиента, город проживания и диапазон общей суммы заказов клиента.

**Решение:**
```sql
SELECT DISTINCT
    CASE 
        WHEN EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM к.дата_рождения) < 25 THEN 'до 25'
        WHEN EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM к.дата_рождения) BETWEEN 25 AND 40 THEN '25-40'
        WHEN EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM к.дата_рождения) BETWEEN 40 AND 60 THEN '40-60'
        ELSE 'старше 60'
    END AS возрастная_группа,
    к.город,
    CASE 
        WHEN з.общая_сумма < 10000 THEN 'до 10000'
        WHEN з.общая_сумма BETWEEN 10000 AND 50000 THEN '10000-50000'
        WHEN з.общая_сумма BETWEEN 50000 AND 100000 THEN '50000-100000'
        ELSE '100000 и выше'
    END AS суммовой_диапазон
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
ORDER BY возрастная_группа, к.город, суммовой_диапазон;
```

## Глава 12: COUNT и другие агрегатные функции

### Введение

Агрегатные функции - это одна из самых мощных возможностей SQL, позволяющая анализировать данные на уровне групп, а не отдельных записей. В этой главе мы рассмотрим основные агрегатные функции: COUNT, SUM, AVG, MIN, MAX и другие.

### Что такое агрегатные функции?

Агрегатные функции принимают набор значений и возвращают одно значение. Они особенно полезны при анализе данных, подсчете статистики и создании отчетов.

### Основные агрегатные функции

1. **COUNT()** - подсчет количества строк
2. **SUM()** - суммирование числовых значений
3. **AVG()** - вычисление среднего значения
4. **MIN()** - нахождение минимального значения
5. **MAX()** - нахождение максимального значения

### COUNT()

Функция `COUNT()` возвращает количество строк в результирующем наборе. Она может использоваться несколькими способами:

#### COUNT(*)

Подсчитывает общее количество строк, включая строки с `NULL` значениями:

```sql
SELECT COUNT(*) AS "Общее количество клиентов"
FROM клиенты;
```

#### COUNT(столбец)

Подсчитывает количество строк, в которых столбец не равен `NULL`:

```sql
SELECT COUNT(отчество) AS "Количество клиентов с отчеством"
FROM клиенты;
```

#### COUNT(DISTINCT)

Подсчитывает количество уникальных значений:

```sql
SELECT COUNT(DISTINCT город) AS "Количество уникальных городов"
FROM клиенты;
```

### SUM()

Функция `SUM()` складывает все значения в столбце. Используется только для числовых данных:

```sql
SELECT SUM(общая_сумма) AS "Общая сумма всех заказов"
FROM заказы;
```

### AVG()

Функция `AVG()` вычисляет среднее значение для числового столбца:

```sql
SELECT AVG(цена) AS "Средняя цена товара"
FROM товары;
```

### MIN() и MAX()

Функции `MIN()` и `MAX()` находят минимальное и максимальное значение соответственно:

```sql
SELECT 
    MIN(цена) AS "Минимальная цена",
    MAX(цена) AS "Максимальная цена"
FROM товары;
```

### Практические примеры из российской практики

#### Пример 1: Статистика по заказам

```sql
SELECT 
    COUNT(*) AS "Количество заказов",
    SUM(общая_сумма) AS "Общая сумма заказов",
    AVG(общая_сумма) AS "Средняя сумма заказа",
    MIN(дата_заказа) AS "Дата первого заказа",
    MAX(дата_заказа) AS "Дата последнего заказа"
FROM заказы;
```

#### Пример 2: Анализ клиентов

```sql
SELECT 
    COUNT(*) AS "Общее количество клиентов",
    COUNT(отчество) AS "Количество клиентов с отчеством",
    COUNT(DISTINCT город) AS "Количество уникальных городов",
    MIN(EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) AS "Минимальный возраст",
    MAX(EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) AS "Максимальный возраст"
FROM клиенты;
```

#### Пример 3: Анализ товаров

```sql
SELECT 
    AVG(цена) AS "Средняя цена",
    MIN(цена) AS "Минимальная цена",
    MAX(цена) AS "Максимальная цена",
    SUM(цена * количество_на_складе) AS "Общая стоимость товаров на складе",
    COUNT(*) AS "Количество товаров"
FROM товары;
```

### Агрегатные функции с условиями

Агрегатные функции можно комбинировать с `WHERE` для фильтрации данных:

```sql
SELECT 
    COUNT(*) AS "Количество заказов в 2023 году",
    AVG(общая_сумма) AS "Средняя сумма заказа в 2023 году"
FROM заказы
WHERE EXTRACT(YEAR FROM дата_заказа) = 2023;
```

### Условные агрегатные функции

Иногда нужно подсчитать или вычислить что-то только при выполнении определенного условия. Для этого можно использовать `CASE` внутри агрегатных функций:

```sql
SELECT 
    COUNT(*) AS "Общее количество заказов",
    COUNT(CASE WHEN статус = 'доставлен' THEN 1 END) AS "Количество доставленных заказов",
    COUNT(CASE WHEN статус = 'новый' THEN 1 END) AS "Количество новых заказов"
FROM заказы;
```

### Комбинация агрегатных функций

Агрегатные функции можно комбинировать в одном запросе:

```sql
SELECT 
    COUNT(*) AS "Всего товаров",
    AVG(цена) AS "Средняя цена",
    SUM(цена * количество_на_складе) AS "Общая стоимость на складе",
    MIN(цена) AS "Минимальная цена",
    MAX(цена) AS "Максимальная цена",
    COUNT(DISTINCT категория) AS "Количество категорий"
FROM товары;
```

### Работа с датами в агрегатных функциях

Агрегатные функции можно использовать и с датами:

```sql
SELECT 
    MIN(дата_регистрации) AS "Дата первой регистрации",
    MAX(дата_регистрации) AS "Дата последней регистрации",
    COUNT(DISTINCT EXTRACT(YEAR FROM дата_регистрации)) AS "Количество лет регистрации"
FROM клиенты;
```

### Часто используемые шаблоны с агрегатными функциями

#### Подсчет соотношений

```sql
SELECT 
    COUNT(*) AS "Всего заказов",
    COUNT(CASE WHEN статус = 'доставлен' THEN 1 END) AS "Доставлено",
    ROUND(
        COUNT(CASE WHEN статус = 'доставлен' THEN 1 END) * 100.0 / COUNT(*), 
        2
    ) AS "Процент доставленных"
FROM заказы;
```

#### Временной анализ

```sql
SELECT 
    EXTRACT(YEAR FROM дата_заказа) AS год,
    COUNT(*) AS "Количество заказов",
    SUM(общая_сумма) AS "Общая сумма",
    AVG(общая_сумма) AS "Средний чек"
FROM заказы
GROUP BY EXTRACT(YEAR FROM дата_заказа)
ORDER BY год;
```

### Заключение главы

Агрегатные функции - это фундаментальный инструмент для анализа данных. Они позволяют получать обобщенную информацию из больших объемов данных, что особенно важно при создании отчетов и анализе бизнес-показателей. В следующих главах мы рассмотрим, как комбинировать агрегатные функции с группировкой данных.

## Глава 13: SELECT WHERE - Часть 1

### Введение

Оператор `WHERE` - это ключевой инструмент для фильтрации данных в SQL. Он позволяет извлекать только те строки, которые соответствуют определенным условиям. В этой части мы рассмотрим основы использования `WHERE` и простые условия фильтрации.

### Базовый синтаксис

```sql
SELECT столбцы
FROM таблица
WHERE условие;
```

### Основные операторы сравнения

1. **=** - равно
2. **!=** или **<>** - не равно
3. **>** - больше
4. **<** - меньше
5. **>=** - больше или равно
6. **<=** - меньше или равно

### Простые условия

#### Равенство

```sql
SELECT * FROM клиенты
WHERE город = 'Москва';
```

#### Неравенство

```sql
SELECT * FROM клиенты
WHERE город != 'Москва';
```

#### Числовые сравнения

```sql
SELECT * FROM товары
WHERE цена > 10000;
```

```sql
SELECT * FROM заказы
WHERE общая_сумма >= 50000;
```

### Фильтрация по датам

```sql
SELECT * FROM заказы
WHERE дата_заказа >= '2023-01-01';
```

```sql
SELECT * FROM клиенты
WHERE дата_регистрации < '2023-06-01';
```

### Фильтрация по нескольким условиям

#### С помощью AND

Оператор `AND` требует истинности всех условий:

```sql
SELECT * FROM клиенты
WHERE город = 'Москва' AND возраст > 30;
```

Или для вычисления возраста:

```sql
SELECT * FROM клиенты
WHERE город = 'Москва' 
AND (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) > 30;
```

#### С помощью OR

Оператор `OR` требует истинности хотя бы одного условия:

```sql
SELECT * FROM клиенты
WHERE город = 'Москва' OR город = 'Санкт-Петербург';
```

### Комбинирование AND и OR

При комбинировании `AND` и `OR` важно использовать скобки для определения приоритета:

```sql
SELECT * FROM клиенты
WHERE (город = 'Москва' OR город = 'Санкт-Петербург') 
AND (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) > 25;
```

### Проверка на NULL

Для проверки значений на `NULL` используются специальные операторы:

```sql
SELECT * FROM клиенты
WHERE отчество IS NULL;
```

```sql
SELECT * FROM клиенты
WHERE отчество IS NOT NULL;
```

### Строковые операции

#### Точное совпадение строк

```sql
SELECT * FROM клиенты
WHERE фамилия = 'Иванов';
```

#### Регистронезависимое сравнение

PostgreSQL регистронезависимо по умолчанию для некоторых операций, но можно явно указать:

```sql
SELECT * FROM клиенты
WHERE LOWER(фамилия) = LOWER('иванов');
```

### Практические примеры

#### Пример 1: Фильтрация клиентов по городу и возрасту

```sql
SELECT фамилия, имя, город, 
       (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) AS возраст
FROM клиенты
WHERE город IN ('Москва', 'Санкт-Петербург', 'Новосибирск')
AND (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) BETWEEN 25 AND 45;
```

#### Пример 2: Фильтрация товаров по цене

```sql
SELECT наименование, цена, категория
FROM товары
WHERE цена > 5000 AND цена < 50000
ORDER BY цена;
```

#### Пример 3: Фильтрация заказов по дате и сумме

```sql
SELECT id, дата_заказа, общая_сумма, статус
FROM заказы
WHERE дата_заказа >= '2023-01-01' 
AND общая_сумма > 10000
ORDER BY дата_заказа DESC;
```

### Практические советы

1. **Размещайте наиболее ограничивающие условия первыми** - это может улучшить производительность запроса
2. **Используйте скобки при сложных условиях** - для ясности и правильного порядка выполнения
3. **Избегайте функций в левой части условий** - это может мешать использованию индексов

### Примеры, которых следует избегать

Неэффективный запрос (функция в левой части условия):
```sql
SELECT * FROM клиенты
WHERE EXTRACT(YEAR FROM дата_регистрации) = 2023;
```

Более эффективный запрос:
```sql
SELECT * FROM клиенты
WHERE дата_регистрации >= '2023-01-01' AND дата_регистрации < '2024-01-01';
```

### Ошибки новичков

1. **Использование `=` вместо `IS` для проверки NULL**
   - Неправильно: `WHERE отчество = NULL`
   - Правильно: `WHERE отчество IS NULL`

2. **Забытые кавычки для строковых значений**
   - Неправильно: `WHERE фамилия = Иванов`
   - Правильно: `WHERE фамилия = 'Иванов'`

3. **Путаница между `AND` и `OR`**
   - Всегда проверяйте логику условий

### Заключение части 1

В этой части мы изучили основы оператора `WHERE` и простые условия фильтрации. В следующей части мы рассмотрим более сложные условия, такие как `IN`, `BETWEEN`, `LIKE` и другие. Понимание `WHERE` критично для эффективной работы с базами данных, так как позволяет извлекать только нужные данные.

## Глава 14: SELECT WHERE - Часть 2

### Введение

В предыдущей главе мы рассмотрели основы оператора `WHERE` и простые условия фильтрации. В этой части мы продолжим изучение операторов `WHERE`, рассмотрев более продвинутые возможности: `IN`, `BETWEEN`, `LIKE`, `EXISTS`, и другие полезные операторы.

### Оператор IN

Оператор `IN` позволяет проверить, соответствует ли значение столбца любому значению из списка:

```sql
SELECT * FROM клиенты
WHERE город IN ('Москва', 'Санкт-Петербург', 'Екатеринбург');
```

Эквивалентный запрос с использованием `OR`:
```sql
SELECT * FROM клиенты
WHERE город = 'Москва' OR город = 'Санкт-Петербург' OR город = 'Екатеринбург';
```

#### IN с подзапросами

```sql
SELECT * FROM заказы
WHERE id_клиента IN (SELECT id FROM клиенты WHERE город = 'Москва');
```

#### NOT IN

Обратный оператор - `NOT IN`:

```sql
SELECT * FROM клиенты
WHERE город NOT IN ('Москва', 'Санкт-Петербург');
```

### Оператор BETWEEN

Оператор `BETWEEN` используется для проверки, находится ли значение в определенном диапазоне (включая границы):

```sql
SELECT * FROM товары
WHERE цена BETWEEN 10000 AND 50000;
```

Эквивалентный запрос:
```sql
SELECT * FROM товары
WHERE цена >= 10000 AND цена <= 50000;
```

#### BETWEEN с датами

```sql
SELECT * FROM заказы
WHERE дата_заказа BETWEEN '2023-01-01' AND '2023-12-31';
```

#### NOT BETWEEN

```sql
SELECT * FROM товары
WHERE цена NOT BETWEEN 10000 AND 50000;
```

### Оператор LIKE

Оператор `LIKE` используется для поиска по шаблону в строковых данных. Он поддерживает два специальных символа:
- `%` - соответствует нулю или более символам
- `_` - соответствует одному символу

#### Примеры с LIKE

```sql
-- Найти клиентов, чья фамилия начинается на 'Ив'
SELECT * FROM клиенты
WHERE фамилия LIKE 'Ив%';
```

```sql
-- Найти клиентов, у которых имя содержит 'ри'
SELECT * FROM клиенты
WHERE имя LIKE '%ри%';
```

```sql
-- Найти клиентов, у которых фамилия из 6 букв и начинается на 'Козл'
SELECT * FROM клиенты
WHERE фамилия LIKE 'Козл__';
```

#### ILIKE (регистронезависимый вариант)

В PostgreSQL есть регистронезависимый вариант `LIKE` - `ILIKE`:

```sql
SELECT * FROM клиенты
WHERE фамилия ILIKE 'иванов';
```

#### NOT LIKE

```sql
SELECT * FROM клиенты
WHERE фамилия NOT LIKE 'Ив%';
```

### Практические примеры использования WHERE

#### Пример 1: Поиск товаров по частичному названию

```sql
SELECT наименование, цена, категория
FROM товары
WHERE ни
