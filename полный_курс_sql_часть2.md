## Глава 14: SELECT WHERE - Часть 2 (продолжение)

### Практические примеры использования WHERE (продолжение)

#### Пример 1: Поиск товаров по частичному названию

```sql
SELECT наименование, цена, категория
FROM товары
WHERE наименование ILIKE '%iphone%';
```

#### Пример 2: Поиск товаров по шаблону артикула

Если бы у нас были артикулы, можно было бы использовать:

```sql
SELECT * FROM товары
WHERE артикул LIKE '___-####' -- 3 буквы, тире, 4 цифры
```

### Регулярные выражения (PostgreSQL)

В PostgreSQL также доступны регулярные выражения с оператором `~`:

```sql
-- Найти товары, название которых начинается с 'К'
SELECT * FROM товары
WHERE наименование ~ '^[Кк]';
```

### EXISTS и NOT EXISTS

Оператор `EXISTS` проверяет, возвращает ли подзапрос какие-либо строки:

```sql
SELECT * FROM клиенты
WHERE EXISTS (
    SELECT 1 FROM заказы 
    WHERE заказы.id_клиента = клиенты.id
);
```

```sql
SELECT * FROM клиенты
WHERE NOT EXISTS (
    SELECT 1 FROM заказы 
    WHERE заказы.id_клиента = клиенты.id
);
```

### ALL, ANY и SOME

Эти операторы используются с подзапросами:

```sql
-- Клиенты, у которых есть заказы на сумму больше, чем у всех заказов клиента с id=1
SELECT * FROM клиенты
WHERE id IN (
    SELECT id_клиента FROM заказы 
    WHERE общая_сумма > ALL (
        SELECT общая_сумма FROM заказы WHERE id_клиента = 1
    )
);
```

```sql
-- Клиенты, у которых есть заказы на сумму больше, чем хотя бы один заказ клиента с id=1
SELECT * FROM клиенты
WHERE id IN (
    SELECT id_клиента FROM заказы 
    WHERE общая_сумма > ANY (
        SELECT общая_сумма FROM заказы WHERE id_клиента = 1
    )
);
```

### Проверка диапазонов дат

```sql
SELECT * FROM заказы
WHERE дата_заказа + INTERVAL '30 days' > CURRENT_DATE; -- Заказы за последние 30 дней
```

### Практические советы по оптимизации WHERE

1. **Используйте индексы** на столбцах, по которым часто фильтруете
2. **Избегайте функций в левой части условий**, если это возможно:
   ```sql
   -- Неэффективно
   WHERE EXTRACT(YEAR FROM дата) = 2023
   
   -- Более эффективно
   WHERE дата >= '2023-01-01' AND дата < '2024-01-01'
   ```

3. **Размещайте наиболее ограничивающие условия первыми**
4. **Избегайте NOT в условиях**, так как они могут мешать использованию индексов

## Глава 15: Задание: SELECT WHERE

### Введение

В этой главе вы получите практические задания на использование оператора WHERE с различными условиями. Задания охватывают все изученные операторы: =, !=, <, >, BETWEEN, IN, LIKE, IS NULL, AND, OR и другие.

### Сценарии и задачи

#### Задание 1: Фильтрация по точному совпадению

**Сценарий:** Менеджер по работе с клиентами хочет найти всех клиентов из Москвы.

**Задача:** Выведите фамилию, имя и город для всех клиентов, проживающих в Москве.

**Решение:**
```sql
SELECT фамилия, имя, город
FROM клиенты
WHERE город = 'Москва';
```

#### Задание 2: Фильтрация по нескольким значениям

**Сценарий:** Отдел маркетинга хочет провести кампанию в крупных городах.

**Задача:** Выведите всех клиентов из Москвы, Санкт-Петербурга и Новосибирска. Показывайте фамилию, имя, телефон и город.

**Решение:**
```sql
SELECT фамилия, имя, телефон, город
FROM клиенты
WHERE город IN ('Москва', 'Санкт-Петербург', 'Новосибирск');
```

#### Задание 3: Числовые фильтры

**Сценарий:** Финансисты хотят проанализировать дорогие заказы.

**Задача:** Выведите все заказы с общей суммой больше 50000. Показывайте id заказа, id клиента, дату и сумму.

**Решение:**
```sql
SELECT id, id_клиента, дата_заказа, общая_сумма
FROM заказы
WHERE общая_сумма > 50000;
```

#### Задание 4: Фильтрация по диапазону значений

**Сценарий:** Менеджеры хотят найти товары по средней ценовой категории.

**Задача:** Найдите все товары с ценой от 10000 до 30000 включительно. Выведите наименование, цену и категорию.

**Решение:**
```sql
SELECT наименование, цена, категория
FROM товары
WHERE цена BETWEEN 10000 AND 30000;
```

#### Задание 5: Фильтрация по датам

**Сценарий:** Аналитики хотят получить данные за определенный период.

**Задача:** Выведите все заказы, сделанные в 2023 году. Показывайте id заказа, дату, сумму и статус.

**Решение:**
```sql
SELECT id, дата_заказа, общая_сумма, статус
FROM заказы
WHERE дата_заказа >= '2023-01-01' AND дата_заказа <= '2023-12-31';
```

#### Задание 6: Поиск по шаблону

**Сценарий:** Нужно найти клиентов с определенными фамилиями.

**Задача:** Найдите всех клиентов, у которых фамилия начинается на 'Ив'. Выведите фамилию, имя и email.

**Решение:**
```sql
SELECT фамилия, имя, email
FROM клиенты
WHERE фамилия LIKE 'Ив%';
```

#### Задание 7: Фильтрация с комбинацией условий

**Сценарий:** Отдел логистики хочет найти заказы для определенного региона со специфическим статусом.

**Задача:** Выведите заказы из Москвы со статусом 'в_доставке'. Показывайте id заказа, фамилию клиента, дату и статус.

**Решение:**
```sql
SELECT з.id AS "ID заказа", к.фамилия, з.дата_заказа, з.статус
FROM заказы з
JOIN клиенты к ON з.id_клиента = к.id
WHERE к.город = 'Москва' AND з.статус = 'в_доставке';
```

#### Задание 8: Проверка на NULL

**Сценарий:** HR отдел хочет найти клиентов без отчества.

**Задача:** Выведите фамилию, имя и город всех клиентов, у которых не указано отчество.

**Решение:**
```sql
SELECT фамилия, имя, город
FROM клиенты
WHERE отчество IS NULL;
```

#### Задание 9: Комплексная фильтрация

**Сценарий:** Менеджеры хотят найти клиентов определенного возраста из определенных городов.

**Задача:** Найдите клиентов младше 35 лет из Москвы или Санкт-Петербурга. Выведите фамилию, имя, возраст и город.

**Решение:**
```sql
SELECT 
    фамилия,
    имя,
    (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) AS возраст,
    город
FROM клиенты
WHERE (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) < 35
  AND город IN ('Москва', 'Санкт-Петербург');
```

#### Задание 10: Фильтрация по нескольким условиям с NOT

**Сценарий:** Нужно исключить определенные категории товаров.

**Задача:** Выведите все товары, кроме тех, что в категории 'Книги' и 'Одежда'. Показывайте наименование, цену и категорию.

**Решение:**
```sql
SELECT наименование, цена, категория
FROM товары
WHERE категория NOT IN ('Книги', 'Одежда');
```

#### Задание 11: Поиск товаров по частичному названию

**Сценарий:** Клиенты ищут конкретный бренд.

**Задача:** Найдите все товары, в названии которых содержится 'iPhone'. Выведите наименование и цену.

**Решение:**
```sql
SELECT наименование, цена
FROM товары
WHERE наименование ILIKE '%iPhone%';
```

#### Задание 12: Фильтрация заказов по диапазону суммы и дате

**Сценарий:** Финансисты хотят проанализировать заказы за квартал.

**Задача:** Выведите заказы за первый квартал 2023 года с суммой от 10000 до 60000. Показывайте id, дату, сумму и статус.

**Решение:**
```sql
SELECT id, дата_заказа, общая_сумма, статус
FROM заказы
WHERE дата_заказа BETWEEN '2023-01-01' AND '2023-03-31'
  AND общая_сумма BETWEEN 10000 AND 60000;
```

#### Задание 13: Поиск клиентов с определенным форматом email

**Сценарий:** Маркетологи хотят найти клиентов с gmail адресами.

**Задача:** Выведите клиентов, у которых email заканчивается на '@gmail.com'. Покажите фамилию, имя и email.

**Решение:**
```sql
SELECT фамилия, имя, email
FROM клиенты
WHERE email LIKE '%@gmail.com';
```

#### Задание 14: Комбинация OR и AND

**Сценарий:** Требуется найти клиентов с определенными критериями.

**Задача:** Найдите клиентов из Москвы или Санкт-Петербурга, которые зарегистрировались до 2023 года. Выведите фамилию, имя, город и дату регистрации.

**Решение:**
```sql
SELECT фамилия, имя, город, дата_регистрации
FROM клиенты
WHERE (город = 'Москва' OR город = 'Санкт-Петербург')
  AND дата_регистрации < '2023-01-01';
```

#### Задание 15: Сложное условие с подзапросом

**Сценарий:** Нужно найти клиентов, которые делали дорогие заказы.

**Задача:** Выведите клиентов, у которых хотя бы один заказ был больше 60000. Покажите фамилию, имя, город и максимальную сумму их заказов.

**Решение:**
```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    MAX(з.общая_сумма) AS максимальный_заказ
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя, к.город
HAVING MAX(з.общая_сумма) > 60000;
```

## Глава 16: ORDER BY

### Введение

Оператор `ORDER BY` используется для сортировки результатов запроса по одному или нескольким столбцам. Это важный инструмент для представления данных в удобном для восприятия виде, особенно при создании отчетов или выводе списков.

### Базовый синтаксис

```sql
SELECT столбцы
FROM таблица
WHERE условие
ORDER BY столбец1 [ASC|DESC], столбец2 [ASC|DESC], ...;
```

- `ASC` - по возрастанию (по умолчанию)
- `DESC` - по убыванию

### Простая сортировка

#### По одному столбцу

```sql
SELECT фамилия, имя, город
FROM клиенты
ORDER BY фамилия;
```

Это отсортирует результаты по фамилии в алфавитном порядке (ASC по умолчанию).

#### По возрастанию и убыванию

```sql
SELECT фамилия, имя, дата_регистрации
FROM клиенты
ORDER BY дата_регистрации DESC;
```

Это отсортирует клиентов по дате регистрации, начиная с последнего зарегистрированного.

### Сортировка по нескольким столбцам

При сортировке по нескольким столбцам сортировка происходит по первому столбцу, а затем по второму (и т.д.) в пределах одинаковых значений первого столбца:

```sql
SELECT фамилия, имя, город
FROM клиенты
ORDER BY город, фамилия;
```

Этот запрос сначала отсортирует по городу, а внутри каждого города - по фамилии.

#### Смешанная сортировка

```sql
SELECT фамилия, имя, город, дата_регистрации
FROM клиенты
ORDER BY город ASC, дата_регистрации DESC;
```

Это отсортирует по городу по возрастанию, а внутри каждого города - по дате регистрации по убыванию.

### Сортировка по вычисленным значениям

```sql
SELECT 
    фамилия, 
    имя, 
    (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) AS возраст
FROM клиенты
ORDER BY возраст DESC;
```

### Сортировка по позиции столбца

Вместо имени столбца можно использовать его порядковый номер:

```sql
SELECT фамилия, имя, город
FROM клиенты
ORDER BY 3, 1;  -- Сортировка по 3-му столбцу (город), затем по 1-му (фамилия)
```

> Примечание: Использование номеров столбцов не рекомендуется в производственном коде, так как может затруднить понимание и поддержку запроса.

### Сортировка строковых данных

#### Регистрочувствительная сортировка

В PostgreSQL строковая сортировка зависит от локали, но обычно является регистронезависимой для латинских букв:

```sql
SELECT наименование, цена
FROM товары
ORDER BY наименование;
```

#### Регистронезависимая сортировка

Для полной регистронезависимой сортировки:

```sql
SELECT наименование, цена
FROM товары
ORDER BY LOWER(наименование);
```

### Сортировка с учетом NULL значений

В PostgreSQL по умолчанию:
- При `ASC` сортировке: `NULL` значения выводятся последними
- При `DESC` сортировке: `NULL` значения выводятся первыми

#### Управление позицией NULL значений

```sql
-- NULL значения первыми при ASC сортировке
SELECT фамилия, отчество
FROM клиенты
ORDER BY отчество ASC NULLS FIRST;

-- NULL значения последними при DESC сортировке
SELECT фамилия, отчество
FROM клиенты
ORDER BY отчество DESC NULLS LAST;
```

### Практические примеры

#### Пример 1: Топ дорогих товаров

```sql
SELECT наименование, цена, категория
FROM товары
ORDER BY цена DESC
LIMIT 10;  -- Топ-10 самых дорогих товаров
```

#### Пример 2: Клиенты с сортировкой по нескольким критериям

```sql
SELECT фамилия, имя, город, дата_регистрации
FROM клиенты
ORDER BY 
    город ASC,
    дата_регистрации DESC,
    фамилия ASC;
```

#### Пример 3: Сортировка по агрегатным функциям

```sql
SELECT 
    город,
    COUNT(*) AS количество_клиентов
FROM клиенты
GROUP BY город
ORDER BY количество_клиентов DESC;
```

### Сортировка с JOIN

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    з.общая_сумма
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
ORDER BY з.общая_сумма DESC;
```

### Особенности сортировки в разных СУБД

Хотя `ORDER BY` является стандартом SQL, есть некоторые особенности:

1. **После GROUP BY**: В большинстве СУБД нельзя использовать столбцы, которые не входят в `GROUP BY`, если они не агрегируются
2. **С DISTINCT**: Столбцы в `ORDER BY` должны быть в `SELECT` (если используется `DISTINCT`)
3. **С LIMIT**: `ORDER BY` обычно используется перед `LIMIT` для получения предсказуемого результата

### Практические советы по использованию ORDER BY

1. **Создавайте индексы** на столбцах, по которым часто сортируете, для повышения производительности
2. **Избегайте сортировки по вычисляемым выражениям**, если это возможно, так как это может замедлить запрос
3. **Учитывайте объем данных** - сортировка больших наборов данных может быть ресурсоемкой

### Примеры из российской практики

#### Пример 1: Рейтинг клиентов по сумме покупок

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    SUM(з.общая_сумма) AS общая_сумма_покупок
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя, к.город
ORDER BY общая_сумма_покупок DESC;
```

#### Пример 2: Категории товаров по средней цене

```sql
SELECT 
    категория,
    COUNT(*) AS количество_товаров,
    AVG(цена) AS средняя_цена
FROM товары
GROUP BY категория
ORDER BY средняя_цена DESC;
```

### Заключение главы

Оператор `ORDER BY` - важный инструмент для организации и представления данных. Правильное использование сортировки значительно улучшает читаемость результатов запроса и помогает находить нужную информацию быстрее.

## Глава 17: LIMIT и OFFSET

### Введение

Операторы `LIMIT` и `OFFSET` используются для ограничения количества возвращаемых строк из результата запроса. Это особенно полезно при работе с большими наборами данных, реализации постраничного вывода или при необходимости получения только определенного количества записей (например, топ-10).

### Базовый синтаксис

```sql
SELECT столбцы
FROM таблица
WHERE условие
ORDER BY столбец
LIMIT количество_строк
OFFSET смещение;
```

### Оператор LIMIT

`LIMIT` указывает максимальное количество строк, которое должно быть возвращено запросом.

#### Простое ограничение

```sql
SELECT фамилия, имя, город
FROM клиенты
LIMIT 5;
```

Этот запрос вернет только первые 5 строк из результата.

### Оператор OFFSET

`OFFSET` указывает, сколько строк следует пропустить перед возвратом результата.

```sql
SELECT фамилия, имя, город
FROM клиенты
ORDER BY фамилия
OFFSET 10;
```

Этот запрос пропустит первые 10 строк и вернет остальные.

### Совместное использование LIMIT и OFFSET

```sql
SELECT фамилия, имя, город
FROM клиенты
ORDER BY фамилия
LIMIT 5
OFFSET 10;
```

Этот запрос пропустит первые 10 строк и вернет следующие 5 строк (строки с 11 по 15).

### Практические применения

#### Постраничный вывод (пагинация)

Пагинация - это распространенный способ отображения больших объемов данных:

```sql
-- Страница 1 (строки 1-10)
SELECT * FROM товары
ORDER BY наименование
LIMIT 10
OFFSET 0;

-- Страница 2 (строки 11-20)
SELECT * FROM товары
ORDER BY наименование
LIMIT 10
OFFSET 10;

-- Страница 3 (строки 21-30)
SELECT * FROM товары
ORDER BY наименование
LIMIT 10
OFFSET 20;
```

Формула для вычисления OFFSET:
```
OFFSET = (номер_страницы - 1) * размер_страницы
```

#### Получение топ-N результатов

```sql
-- Топ-5 самых дорогих товаров
SELECT наименование, цена
FROM товары
ORDER BY цена DESC
LIMIT 5;
```

```sql
-- Топ-10 клиентов по сумме заказов
SELECT 
    к.фамилия,
    к.имя,
    SUM(з.общая_сумма) AS общая_сумма
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя
ORDER BY общая_сумма DESC
LIMIT 10;
```

### Важные особенности

#### Необходимость ORDER BY

При использовании `LIMIT` и `OFFSET` крайне важно использовать `ORDER BY`, иначе порядок строк может быть произвольным:

```sql
-- НЕПРАВИЛЬНО: результат может быть произвольным
SELECT * FROM клиенты
LIMIT 10;

-- ПРАВИЛЬНО: результат предсказуем
SELECT * FROM клиенты
ORDER BY фамилия
LIMIT 10;
```

#### Производительность

- `LIMIT` может улучшить производительность, так как СУБД может прекратить обработку, как только будет достигнут лимит
- `OFFSET` с большими значениями может замедлять запросы, так как СУБД все равно должна пройти все пропускаемые строки

#### LIMIT без OFFSET

```sql
-- Просто ограничение количества возвращаемых строк
SELECT * FROM заказы
ORDER BY дата_заказа DESC
LIMIT 1;
```

Этот запрос вернет только самый последний заказ.

### Практические примеры

#### Пример 1: Пагинация для веб-приложения

Допустим, у нас есть веб-страница с товарами, и мы хотим отображать по 20 товаров на странице:

```sql
-- Страница N (где N - номер страницы)
-- Псевдокод: LIMIT 20 OFFSET (N-1)*20
SELECT * FROM товары
ORDER BY наименование
LIMIT 20
OFFSET 40; -- Для 3-й страницы (3-1)*20 = 40
```

#### Пример 2: Случайные записи

Для получения случайных записей можно использовать `ORDER BY RANDOM()`:

```sql
SELECT * FROM товары
ORDER BY RANDOM()
LIMIT 5;
```

> Примечание: `RANDOM()` может быть ресурсоемкой операцией для больших таблиц.

#### Пример 3: Последние N операций

```sql
-- 5 последних заказов
SELECT id, дата_заказа, общая_сумма, статус
FROM заказы
ORDER BY дата_заказа DESC, id DESC
LIMIT 5;
```

### Использование параметров

При использовании `LIMIT` и `OFFSET` в приложениях часто используются параметры:

```sql
-- Псевдокод для параметризованного запроса
SELECT * FROM клиенты
ORDER BY фамилия
LIMIT $1
OFFSET $2;
```

Где `$1` - размер страницы, `$2` - смещение.

### Альтернативы LIMIT и OFFSET

Для очень больших наборов данных существуют альтернативные методы пагинации:

#### Курсорная пагинация

Вместо `OFFSET` можно использовать значение последней записи предыдущей страницы:

```sql
-- После получения id последнего элемента предыдущей страницы (например, id = 150)
SELECT * FROM заказы
WHERE id > 150
ORDER BY id
LIMIT 20;
```

### Практические советы

1. **Всегда используйте `ORDER BY`** с `LIMIT` и `OFFSET` для предсказуемого результата
2. **Не используйте большие значения `OFFSET`** для пагинации, так как это снижает производительность
3. **Рассмотрите курсорную пагинацию** для больших наборов данных
4. **Проверяйте, что используемый столбец для сортировки уникален** (или добавьте уникальный столбец в `ORDER BY`) для стабильной пагинации

### Заключение главы

Операторы `LIMIT` и `OFFSET` - важные инструменты для управления объемом возвращаемых данных. Они особенно полезны при реализации пагинации, получении топ-N результатов и работе с большими наборами данных. Важно правильно использовать их в сочетании с `ORDER BY` и учитывать производительность при работе с большими смещениями.

## Глава 19: BETWEEN

### Введение

Оператор `BETWEEN` используется для проверки, находится ли значение в определенном диапазоне. Он эквивалентен комбинации операторов сравнения `>=` и `<=`, но делает код более читаемым и компактным.

### Базовый синтаксис

```sql
SELECT столбцы
FROM таблица
WHERE столбец BETWEEN начальное_значение AND конечное_значение;
```

Важно отметить, что `BETWEEN` включает границы диапазона, то есть значения, равные начальному и конечному, также учитываются.

### BETWEEN с числовыми значениями

#### Простое числовое сравнение

```sql
SELECT наименование, цена
FROM товары
WHERE цена BETWEEN 10000 AND 50000;
```

Этот запрос вернет все товары с ценой от 10000 до 50000 включительно.

#### Эквивалентный запрос без BETWEEN

```sql
SELECT наименование, цена
FROM товары
WHERE цена >= 10000 AND цена <= 50000;
```

### BETWEEN с датами

#### Диапазон дат

```sql
SELECT * FROM заказы
WHERE дата_заказа BETWEEN '2023-01-01' AND '2023-12-31';
```

#### Диапазон с вычисляемыми датами

```sql
SELECT * FROM заказы
WHERE дата_заказа BETWEEN CURRENT_DATE - INTERVAL '30 days' AND CURRENT_DATE;
```

Этот запрос вернет заказы за последние 30 дней.

### BETWEEN с текстовыми значениями

```sql
SELECT фамилия, имя
FROM клиенты
WHERE фамилия BETWEEN 'Иванов' AND 'Петров';
```

> Важно: При сравнении текстов в алфавитном порядке учитывается локаль базы данных.

### Использование NOT BETWEEN

Для получения значений, находящихся вне диапазона, используется `NOT BETWEEN`:

```sql
SELECT наименование, цена
FROM товары
WHERE цена NOT BETWEEN 10000 AND 50000;
```

### Практические примеры

#### Пример 1: Возрастные группы клиентов

```sql
SELECT 
    фамилия,
    имя,
    (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) AS возраст
FROM клиенты
WHERE (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) BETWEEN 25 AND 40;
```

#### Пример 2: Квартальные продажи

```sql
SELECT * FROM заказы
WHERE дата_заказа BETWEEN '2023-04-01' AND '2023-06-30'; -- Второй квартал 2023
```

#### Пример 3: Средняя ценовая категория

```sql
SELECT наименование, цена, категория
FROM товары
WHERE цена BETWEEN (
    (SELECT AVG(цена) FROM товары) * 0.8
) AND (
    (SELECT AVG(цена) FROM товары) * 1.2
);
```

### BETWEEN с другими операторами

`BETWEEN` можно комбинировать с другими условиями:

```sql
SELECT * FROM заказы
WHERE общая_сумма BETWEEN 10000 AND 50000
  AND дата_заказа >= '2023-01-01'
  AND статус != 'отменен';
```

### Практические советы

#### Избегайте функций в условиях BETWEEN

```sql
-- Неэффективно
WHERE EXTRACT(YEAR FROM дата_заказа) BETWEEN 2023 AND 2023

-- Более эффективно
WHERE дата_заказа BETWEEN '2023-01-01' AND '2023-12-31'
```

#### Проверка диапазонов с NULL

Если один из операндов `BETWEEN` равен `NULL`, результат всегда будет `NULL`:

```sql
-- Результат будет NULL
SELECT * FROM товары
WHERE цена BETWEEN 10000 AND NULL;
```

### Примеры из российской практики

#### Пример 1: Работа с НДС

```sql
-- Товары с ценой от 1000 до 100000 (обычный диапазон)
SELECT 
    наименование,
    цена,
    цена * 1.2 AS "Цена с НДС 20%"
FROM товары
WHERE цена BETWEEN 1000 AND 100000
ORDER BY цена;
```

#### Пример 2: Анализ по кварталам

```sql
-- Заказы за разные кварталы
SELECT 
    COUNT(*) AS "Количество заказов",
    SUM(общая_сумма) AS "Общая сумма",
    'Q1 2023' AS "Период"
FROM заказы
WHERE дата_заказа BETWEEN '2023-01-01' AND '2023-03-31'

UNION ALL

SELECT 
    COUNT(*) AS "Количество заказов",
    SUM(общая_сумма) AS "Общая сумма",
    'Q2 2023' AS "Период"
FROM заказы
WHERE дата_заказа BETWEEN '2023-04-01' AND '2023-06-30'

ORDER BY "Период";
```

#### Пример 3: Возрастные сегменты

```sql
SELECT 
    CASE 
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) BETWEEN 18 AND 25 THEN 'Молодежь'
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) BETWEEN 26 AND 40 THEN 'Молодые профессионалы'
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) BETWEEN 41 AND 60 THEN 'Зрелые профессионалы'
        ELSE 'Опытные специалисты'
    END AS "Возрастная группа",
    COUNT(*) AS "Количество клиентов"
FROM клиенты
GROUP BY 
    CASE 
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) BETWEEN 18 AND 25 THEN 'Молодежь'
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) BETWEEN 26 AND 40 THEN 'Молодые профессионалы'
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) BETWEEN 41 AND 60 THEN 'Зрелые профессионалы'
        ELSE 'Опытные специалисты'
    END
ORDER BY "Количество клиентов" DESC;
```

### Часто допускаемые ошибки

#### Ошибка 1: Перепутанные границы

```sql
-- Неправильно: начальное значение больше конечного
WHERE цена BETWEEN 50000 AND 10000

-- Правильно: начальное значение меньше или равно конечному
WHERE цена BETWEEN 10000 AND 50000
```

#### Ошибка 2: Непонимание включения границ

```sql
-- Включает значения 10000 и 50000
WHERE цена BETWEEN 10000 AND 50000

-- Если нужно исключить границы, используйте:
WHERE цена > 10000 AND цена < 50000
```

### Заключение главы

Оператор `BETWEEN` - удобный инструмент для проверки принадлежности значений к определенному диапазону. Он улучшает читаемость запросов и может быть эффективно использован с числовыми значениями, датами и текстовыми строками. Понимание работы `BETWEEN` особенно важно при анализе данных с использованием диапазонов значений, таких как возраст, цена и даты.

## Глава 20: IN

### Введение

Оператор `IN` используется для проверки, содержится ли значение в заданном списке значений или результатах подзапроса. Это удобная альтернатива множественным операторам `OR`, особенно когда нужно проверить принадлежность к большому количеству значений.

### Базовый синтаксис

```sql
SELECT столбцы
FROM таблица
WHERE столбец IN (значение1, значение2, ...);

-- Или с подзапросом:
SELECT столбцы
FROM таблица
WHERE столбец IN (SELECT столбец FROM другая_таблица WHERE условие);
```

### IN со списком значений

#### Простое использование IN

```sql
SELECT фамилия, имя, город
FROM клиенты
WHERE город IN ('Москва', 'Санкт-Петербург', 'Новосибирск');
```

Этот запрос эквивалентен следующему:

```sql
SELECT фамилия, имя, город
FROM клиенты
WHERE город = 'Москва' OR город = 'Санкт-Петербург' OR город = 'Новосибирск';
```

### IN с подзапросами

#### Поиск клиентов с заказами

```sql
SELECT * FROM клиенты
WHERE id IN (SELECT id_клиента FROM заказы);
```

#### Поиск товаров определенных категорий

```sql
SELECT * FROM товары
WHERE категория IN (SELECT DISTINCT категория FROM товары WHERE цена > 50000);
```

### NOT IN

Для получения записей, которые НЕ находятся в списке значений, используется `NOT IN`:

```sql
SELECT фамилия, имя, город
FROM клиенты
WHERE город NOT IN ('Москва', 'Санкт-Петербург');
```

> Важно: Если подзапрос возвращает хотя бы одно значение `NULL`, `NOT IN` может не вернуть ожидаемые результаты. В таких случаях лучше использовать `NOT EXISTS`.

### Практические примеры

#### Пример 1: Товары по нескольким категориям

```sql
SELECT наименование, цена, категория
FROM товары
WHERE категория IN ('Электроника', 'Бытовая техника', 'Книги');
```

#### Пример 2: Клиенты из определенных городов с высоким порогом суммы заказов

```sql
SELECT к.фамилия, к.имя, к.город, SUM(з.общая_сумма) AS общая_сумма
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
WHERE к.город IN ('Москва', 'Санкт-Петербург', 'Екатеринбург')
GROUP BY к.id, к.фамилия, к.имя, к.город
HAVING SUM(з.общая_сумма) > 100000;
```

#### Пример 3: Заказы с определенными статусами

```sql
SELECT id, дата_заказа, общая_сумма, статус
FROM заказы
WHERE статус IN ('доставлен', 'оплачен', 'в_доставке');
```

### IN с числовыми значениями

```sql
SELECT * FROM товары
WHERE id IN (1, 5, 10, 15, 20);
```

### IN с датами

```sql
SELECT * FROM заказы
WHERE дата_заказа IN ('2023-01-15', '2023-02-20', '2023-03-10');
```

### Использование IN в подзапросах

#### Поиск клиентов без заказов

```sql
SELECT * FROM клиенты
WHERE id NOT IN (SELECT id_клиента FROM заказы WHERE id_клиента IS NOT NULL);
```

> Обратите внимание на `IS NOT NULL` - это необходимо, когда в подзапросе могут быть `NULL` значения.

### Оптимизация IN

#### Сравнение IN и EXISTS

Для сложных подзапросов может быть более эффективным использовать `EXISTS` вместо `IN`:

```sql
-- Менее эффективно при наличии NULL в подзапросе
SELECT * FROM клиенты
WHERE id IN (SELECT id_клиента FROM заказы);

-- Более предсказуемо и эффективно
SELECT * FROM клиенты
WHERE EXISTS (SELECT 1 FROM заказы WHERE заказы.id_клиента = клиенты.id);
```

### Практические советы

#### Совет 1: Использование индексов

Для эффективной работы `IN` с большими списками значений убедитесь, что столбец, по которому происходит проверка, индексирован.

#### Совет 2: Ограничение списка значений

Если список значений для `IN` очень большой, подумайте о создании временной таблицы и использовании `JOIN`:

```sql
-- Вместо этого:
WHERE id IN (очень, большой, список, значений)

-- Лучше создать временную таблицу и использовать JOIN:
SELECT основная_таблица.* 
FROM основная_таблица
JOIN временная_таблица ON основная_таблица.id = временная_таблица.id;
```

#### Совет 3: Обработка NULL значений

Помните, что `IN` возвращает `NULL`, если проверяемое значение равно `NULL`, и не возвращает строки с `NULL` значениями из списка:

```sql
-- Это никогда не вернет строки, даже если в таблице есть NULL
WHERE столбец IN (1, 2, NULL, 4);
```

### Примеры из российской практики

#### Пример 1: Аналитика по ключевым городам

```sql
-- Анализ заказов в ключевых городах
SELECT 
    к.город,
    COUNT(*) AS "Количество заказов",
    AVG(з.общая_сумма) AS "Средний чек",
    SUM(з.общая_сумма) AS "Общий объем"
FROM заказы з
JOIN клиенты к ON з.id_клиента = к.id
WHERE к.город IN ('Москва', 'Санкт-Петербург', 'Новосибирск', 'Екатеринбург', 'Казань')
GROUP BY к.город
ORDER BY "Общий объем" DESC;
```

#### Пример 2: Мониторинг популярных категорий

```sql
-- Популярные категории товаров (те, что входят в топ-5 по количеству продаж)
SELECT DISTINCT категория
FROM товары
WHERE категория IN (
    SELECT т.категория
    FROM заказы з
    JOIN товары т ON т.категория IS NOT NULL
    GROUP BY т.категория
    ORDER BY COUNT(*) DESC
    LIMIT 5
);
```

#### Пример 3: Фильтрация заказов по статусам

```sql
-- Отчет по активным заказам (не отмененные и не доставленные)
SELECT 
    з.id,
    к.фамилия,
    к.имя,
    з.дата_заказа,

    з.статус

JOIN клиенты к ON з.id_клиента = к.id
```

### Часто допускаемые ошибки

#### Ошибка 1: Проблемы с NULL в подзапросе

```sql
-- Неправильно: может не вернуть ожидаемые результаты из-за NULL
SELECT * FROM клиенты
WHERE id NOT IN (SELECT id_клиента FROM заказы);  -- Если в заказах есть NULL

-- Правильно: фильтруем NULL значения
SELECT * FROM клиенты
WHERE id NOT IN (SELECT id_клиента FROM заказы WHERE id_клиента IS NOT NULL);
```

#### Ошибка 2: Смешивание типов данных

```sql
-- Ошибка: смешивание чисел и строк
WHERE id IN ('1', '2', 3)  -- если id - числовой столбец
```

### Заключение главы

Оператор `IN` - мощный инструмент для проверки принадлежности значений к списку. Он упрощает запросы с множественными условиями `OR` и удобен как для фиксированных списков значений, так и для результатов подзапросов. Понимание особенностей использования `IN`, особенно с подзапросами и `NULL` значениями, помогает избежать распространенных ошибок и создавать более эффективные запросы.

## Глава 21: LIKE и ILIKE

### Введение

Операторы `LIKE` и `ILIKE` используются для поиска шаблонов в текстовых данных. Они особенно полезны при выполнении частичного поиска, поиска с помощью подстановочных символов и других задач, где нужно найти строки, соответствующие определенному шаблону.

### Базовый синтаксис

```sql
SELECT столбцы
FROM таблица
WHERE столбец LIKE 'шаблон';

-- В PostgreSQL:
SELECT столбцы
FROM таблица
WHERE столбец ILIKE 'шаблон';  -- регистронезависимый поиск
```

### Подстановочные символы

#### Символ %

Символ `%` соответствует нулю или более символам:

```sql
-- Найти всех клиентов, фамилия которых начинается на 'Ив'
SELECT фамилия, имя
FROM клиенты
WHERE фамилия LIKE 'Ив%';

-- Найти всех клиентов, email которых содержит 'mail'
SELECT фамилия, email
FROM клиенты
WHERE email LIKE '%mail%';
```

#### Символ _

Символ `_` соответствует ровно одному символу:

```sql
-- Найти фамилии, начинающиеся на 'К' и имеющие 5 букв
SELECT фамилия
FROM клиенты
WHERE фамилия LIKE 'К____';  -- 4 подчеркивания = 4 символа после 'К'
```

### LIKE (регистрозависимый)

В большинстве СУБД `LIKE` чувствителен к регистру:

```sql
-- Найдет только 'Иванов', но не 'иванов' или 'ИВАНОВ'
SELECT * FROM клиенты
WHERE фамилия LIKE 'Иванов';
```

### ILIKE (регистронезависимый в PostgreSQL)

PostgreSQL предоставляет регистронезависимый вариант `LIKE` - `ILIKE`:

```sql
-- Найдет 'Иванов', 'иванов', 'ИВАНОВ', 'ИвАнОв' и т.д.
SELECT * FROM клиенты
WHERE фамилия ILIKE 'иванов';
```

### Практические примеры

#### Пример 1: Поиск по началу строки

```sql
-- Найти всех клиентов, имя которых начинается на 'Ан'
SELECT фамилия, имя
FROM клиенты
WHERE имя LIKE 'Ан%';
```

#### Пример 2: Поиск по окончанию строки

```sql
-- Найти email-адреса, заканчивающиеся на '.ru'
SELECT email
FROM клиенты
WHERE email LIKE '%.ru';
```

#### Пример 3: Поиск с использованием одного символа

```sql
-- Найти фамилии из 6 букв, начинающиеся на 'Петр'
SELECT фамилия
FROM клиенты
WHERE фамилия LIKE 'Петр__';  -- Ровно 2 символа после 'Петр'
```

#### Пример 4: Поиск с пропуском одного символа

```sql
-- Найти фамилии, где 4-й символ 'р'
SELECT фамилия
FROM клиенты
WHERE фамилия LIKE '___р%';  -- 3 любых символа, затем 'р', затем что угодно
```

### ESCAPE для специальных символов

Если нужно искать буквально символы `%` или `_`, используется `ESCAPE`:

```sql
-- Найти строки, содержащие буквально символ %
SELECT * FROM товары
WHERE наименование LIKE '%\%%' ESCAPE '\';

-- Найти строки, содержащие буквально символ _
SELECT * FROM товары
WHERE наименование LIKE '%\_%' ESCAPE '\';
```

### NOT LIKE и NOT ILIKE

Для поиска строк, которые НЕ соответствуют шаблону, используются `NOT LIKE` и `NOT ILIKE`:

```sql
-- Найти клиентов, у которых email НЕ заканчивается на '.com'
SELECT фамилия, email
FROM клиенты
WHERE email NOT LIKE '%.com';
```

```sql
-- Регистронезависимый поиск: найти клиентов, фамилия которых НЕ начинается с 'Ив'
SELECT фамилия
FROM клиенты
WHERE фамилия NOT ILIKE 'ив%';
```

### Практические применения

#### Поиск по нескольким шаблонам

```sql
-- Клиенты с фамилией, начинающейся на 'Ив' или 'Петр'
SELECT фамилия, имя
FROM клиенты
WHERE фамилия LIKE 'Ив%' OR фамилия LIKE 'Петр%';
```

#### Комбинация с другими условиями

```sql
-- Клиенты из Москвы с фамилией, начинающейся на 'С'
SELECT фамилия, имя, город
FROM клиенты
WHERE город = 'Москва' AND фамилия LIKE 'С%';
```

### Регулярные выражения в PostgreSQL

В PostgreSQL также доступны регулярные выражения, которые предоставляют более мощные возможности поиска по шаблону:

```sql
-- Найти фамилии, начинающиеся с 'И' или 'П'
SELECT фамилия
FROM клиенты
WHERE фамилия ~ '^[ИП]';

-- Регистронезависимо
SELECT фамилия
FROM клиенты
WHERE фамилия ~* '^[иа]';
```

### Практические советы

#### Совет 1: Производительность

Использование `LIKE` с шаблоном, начинающимся с `%`, может быть медленным, так как не может эффективно использовать индексы:

```sql
-- Медленно (не может использовать индекс эффективно)
WHERE имя LIKE '%анна%'

-- Быстрее (может использовать индекс)
WHERE имя LIKE 'анна%'
```

#### Совет 2: Использование ILIKE в PostgreSQL

В PostgreSQL предпочтительно использовать `ILIKE` для регистронезависимых сравнений, так как это встроенный оператор:

```sql
-- PostgreSQL: предпочтительно
WHERE фамилия ILIKE 'иванов'

-- Вместо
WHERE LOWER(фамилия) = LOWER('иванов')
```

#### Совет 3: Индексы для шаблонного поиска

Для эффективного шаблонного поиска можно создать специальные индексы:

```sql
-- Создание индекса для эффективного префиксного поиска
CREATE INDEX idx_clients_lastname_prefix ON клиенты (фамилия text_pattern_ops);
```

### Примеры из российской практики

#### Пример 1: Поиск по доменным именам

```sql
-- Найти клиентов с популярными доменами

FROM клиенты
WHERE email ILIKE '%@gmail.com' 
   OR email ILIKE '%@yandex.ru'
   OR email ILIKE '%@mail.ru';
```

#### Пример 2: Поиск по маркам товаров

```sql
-- Найти товары, содержащие 'iPhone', 'Samsung' или 'Xiaomi'
SELECT наименование, цена
FROM товары
WHERE наименование ILIKE '%iPhone%' 
   OR наименование ILIKE '%Samsung%'
   OR наименование ILIKE '%Xiaomi%';
```

#### Пример 3: Анализ телефонных номеров

```sql
-- Найти клиентов с московскими номерами
SELECT фамилия, имя, телефон
FROM клиенты
WHERE телефон LIKE '+7(9%)%' AND SUBSTRING(телефон, 4, 3) IN ('903', '905', '906', '909', '910', '915', '916', '917', '919', '925', '926', '929');
```

### Часто допускаемые ошибки

#### Ошибка 1: Забытые кавычки

```sql
-- ОШИБКА: Нет кавычек вокруг шаблона
WHERE имя LIKE Иван%

-- ПРАВИЛЬНО: Шаблон в кавычках
WHERE имя LIKE 'Иван%'
```

#### Ошибка 2: Неправильное понимание подстановочных символов

```sql
-- Предположим, мы ищем фамилии, начинающиеся на 'К' и длиной 3 символа
-- НЕПРАВИЛЬНО:
WHERE фамилия LIKE 'К%'  -- Находит любые фамилии, начинающиеся на 'К'

-- ПРАВИЛЬНО:
WHERE фамилия LIKE 'К__'  -- Ровно 3 символа: 'К' и еще 2
```

### Заключение главы

Операторы `LIKE` и `ILIKE` обеспечивают мощный, хотя и относительно простой способ поиска по шаблону в текстовых данных. Они особенно полезны для задач, связанных с частичным совпадением строк, и являются важным инструментом при создании поисковых функций и анализе текстовых данных. Понимание подстановочных символов и влияния шаблонов на производительность запроса поможет в эффективном использовании этих операторов.

# Раздел 3: Работа с агрегатами и группировками

## Глава 22: Введение в GROUP BY

### Введение

Оператор `GROUP BY` - один из самых важных инструментов в SQL для анализа данных. Он позволяет группировать строки с одинаковыми значениями в одной или нескольких колонках, что особенно полезно при использовании агрегатных функций (COUNT, SUM, AVG, MAX, MIN). `GROUP BY` позволяет переходить от работы с отдельными строками к работе с группами данных.

### Базовый синтаксис

```sql
SELECT столбцы, агрегатная_функция(столбец)
FROM таблица
WHERE условие
GROUP BY столбец1, столбец2, ...;
```

### Принцип работы GROUP BY

Когда вы используете `GROUP BY`, SQL объединяет все строки, у которых одинаковые значения в указанных столбцах, в одну группу. Затем агрегатные функции применяются к каждой группе, а не к отдельным строкам.

### Простой пример GROUP BY

```sql
SELECT город, COUNT(*) AS количество_клиентов
FROM клиенты
GROUP BY город;
```

Этот запрос сгруппирует всех клиентов по городу и подсчитает количество клиентов в каждом городе.

### GROUP BY с несколькими столбцами

Вы можете группировать по нескольким столбцам:

```sql
SELECT город, пол, COUNT(*) AS количество
FROM клиенты
GROUP BY город, пол;
```

Этот запрос создаст отдельную группу для каждой уникальной комбинации "город-пол".

### GROUP BY с ORDER BY

Часто `GROUP BY` используется вместе с `ORDER BY`:

```sql
SELECT город, COUNT(*) AS количество_клиентов
FROM клиенты
GROUP BY город
ORDER BY количество_клиентов DESC;
```

### GROUP BY с агрегатными функциями

Вот несколько примеров использования `GROUP BY` с различными агрегатными функциями:

#### COUNT()

```sql
SELECT категория, COUNT(*) AS количество_товаров
FROM товары
GROUP BY категория;
```

#### SUM()

```sql
SELECT id_клиента, SUM(общая_сумма) AS общая_сумма_заказов
FROM заказы
GROUP BY id_клиента;
```

#### AVG()

```sql
SELECT категория, AVG(цена) AS средняя_цена
FROM товары
GROUP BY категория;
```

#### MAX() и MIN()

```sql
SELECT категория, 
       MIN(цена) AS минимальная_цена, 
       MAX(цена) AS максимальная_цена
FROM товары
GROUP BY категория;
```

### Правила использования GROUP BY

#### Правило 1: Неагрегированные столбцы в SELECT

Все столбцы в `SELECT`, которые не являются результатом агрегатной функции, должны быть указаны в `GROUP BY`:

```sql
-- ПРАВИЛЬНО
SELECT город, COUNT(*) AS количество
FROM клиенты
GROUP BY город;

-- НЕПРАВИЛЬНО
SELECT город, фамилия, COUNT(*) AS количество
FROM клиенты
GROUP BY город;
```

#### Правило 2: Порядок выполнения

Порядок выполнения частей запроса:
1. `FROM` - определение таблиц
2. `WHERE` - фильтрация строк
3. `GROUP BY` - группировка строк
4. `HAVING` - фильтрация групп
5. `SELECT` - выбор столбцов
6. `ORDER BY` - сортировка результатов

### Примеры из российской практики

#### Пример 1: Отчет по городам клиентов

```sql
SELECT 
    город,
    COUNT(*) AS "Количество клиентов",
    MIN(дата_регистрации) AS "Первая регистрация",
    MAX(дата_регистрации) AS "Последняя регистрация"
FROM клиенты
GROUP BY город
ORDER BY "Количество клиентов" DESC;
```

#### Пример 2: Анализ продаж по категориям товаров

```sql
SELECT 
    т.категория,
    COUNT(*) AS "Количество товаров",
    AVG(т.цена) AS "Средняя цена",
    MIN(т.цена) AS "Минимальная цена",
    MAX(т.цена) AS "Максимальная цена"
FROM товары т
GROUP BY т.категория
ORDER BY "Средняя цена" DESC;
```

#### Пример 3: Анализ заказов по статусам

```sql
SELECT 
    статус,
    COUNT(*) AS "Количество заказов",
    SUM(общая_сумма) AS "Общая сумма",
    AVG(общая_сумма) AS "Средний чек"
FROM заказы
GROUP BY статус
ORDER BY "Общая сумма" DESC;
```

### GROUP BY с JOIN

`GROUP BY` часто используется с `JOIN` для анализа данных из нескольких таблиц:

```sql
SELECT 
    к.город,
    COUNT(з.id) AS "Количество заказов",
    SUM(з.общая_сумма) AS "Общая сумма заказов"
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
ORDER BY "Общая сумма заказов" DESC;
```

### Практические советы

#### Совет 1: Использование осмысленных названий

При использовании агрегатных функций давайте понятные имена столбцам:

```sql
-- ПЛОХО
SELECT город, COUNT(*) FROM клиенты GROUP BY город;

-- ХОРОШО
SELECT город, COUNT(*) AS количество_клиентов FROM клиенты GROUP BY город;
```

#### Совет 2: Порядок столбцов в GROUP BY

Порядок столбцов в `GROUP BY` не влияет на результат, но для читаемости лучше следовать порядку, в котором они идут в `SELECT`.

#### Совет 3: Фильтрация до и после группировки

- Используйте `WHERE` для фильтрации строк *до* группировки
- Используйте `HAVING` для фильтрации групп *после* группировки

### Часто допускаемые ошибки

#### Ошибка 1: Пропущенный столбец в GROUP BY

```sql
-- ОШИБКА: фамилия не указана в GROUP BY
SELECT фамилия, город, COUNT(*) AS количество
FROM клиенты
GROUP BY город;
```

#### Ошибка 2: Неправильное понимание группировки

Помните, что `GROUP BY` объединяет строки в группы, и в результирующем наборе будет одна строка на каждую группу.

### Заключение главы

Оператор `GROUP BY` - ключевой инструмент для анализа данных на уровне групп, а не отдельных записей. Он позволяет выполнять статистический анализ, создавать отчеты и получать обобщенную информацию из больших наборов данных. Понимание принципов работы `GROUP BY` и его взаимодействия с другими частями запроса критически важно для эффективной работы с базами данных.

## Глава 23: Агрегатные функции (COUNT, SUM, AVG, MIN, MAX)

### Введение

Агрегатные функции являются основой для анализа данных в SQL. Они позволяют вычислять обобщенные метрики, такие как количество, сумма, среднее значение, минимум и максимум, по группе строк. В сочетании с `GROUP BY`, агрегатные функции становятся мощным инструментом для создания аналитических отчетов и получения бизнес-инсайтов.

### Основные агрегатные функции

#### COUNT()

Функция `COUNT()` используется для подсчета количества строк в группе. Она может использоваться несколькими способами:

```sql
-- Подсчет всех строк (включая строки с NULL значениями)
SELECT COUNT(*) AS общее_количество
FROM клиенты;

-- Подсчет строк, где столбец не равен NULL
SELECT COUNT(отчество) AS количество_с_отчеством
FROM клиенты;

-- Подсчет уникальных значений
SELECT COUNT(DISTINCT город) AS уникальные_города
FROM клиенты;
```

#### SUM()

Функция `SUM()` вычисляет сумму значений в числовом столбце:

```sql
SELECT SUM(общая_сумма) AS общая_сумма_всех_заказов
FROM заказы;

-- Сумма с группировкой
SELECT id_клиента, SUM(общая_сумма) AS сумма_заказов
FROM заказы
GROUP BY id_клиента;
```

#### AVG()

Функция `AVG()` вычисляет среднее арифметическое значение:

```sql
SELECT AVG(цена) AS средняя_цена_товара
FROM товары;

-- Среднее с группировкой
SELECT категория, AVG(цена) AS средняя_цена
FROM товары
GROUP BY категория;
```

#### MIN() и MAX()

Функции `MIN()` и `MAX()` находят минимальное и максимальное значение соответственно:

```sql
SELECT MIN(цена) AS минимальная_цена, MAX(цена) AS максимальная_цена
FROM товары;

-- С группировкой
SELECT 
    категория,
    MIN(цена) AS минимальная_цена,
    MAX(цена) AS максимальная_цена
FROM товары
GROUP BY категория;
```

### Расширенные возможности агрегатных функций

#### COUNT с условиями

Используя `CASE`, можно подсчитывать строки с определенными характеристиками:

```sql
SELECT 
    COUNT(*) AS "Всего заказов",
    COUNT(CASE WHEN статус = 'доставлен' THEN 1 END) AS "Доставленные",
    COUNT(CASE WHEN статус = 'новый' THEN 1 END) AS "Новые"
FROM заказы;
```

#### Суммирование с условиями

```sql
SELECT 
    SUM(общая_сумма) AS "Общая сумма",
    SUM(CASE WHEN статус = 'доставлен' THEN общая_сумма ELSE 0 END) AS "Сумма доставленных"
FROM заказы;
```

#### Среднее значение с условиями

```sql
SELECT 
    AVG(общая_сумма) AS "Средний чек",
    AVG(CASE WHEN статус = 'доставлен' THEN общая_сумма END) AS "Средний чек доставленных"
FROM заказы;
```

### Практические примеры использования агрегатных функций

#### Пример 1: Комплексный анализ клиентов

```sql

    COUNT(*) AS "Общее количество клиентов",
    COUNT(DISTINCT город) AS "Количество уникальных городов",
    AVG(EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) AS "Средний возраст",

```

```sql

    EXTRACT(YEAR FROM дата_заказа) AS год,
    EXTRACT(MONTH FROM дата_заказа) AS месяц,
    COUNT(*) AS "Количество заказов",
    SUM(общая_сумма) AS "Общая сумма",
    AVG(общая_сумма) AS "Средний чек",
```

### Агрегатные функции в разных контекстах

#### Без GROUP BY

Когда агрегатные функции используются без `GROUP BY`, они применяются ко всем строкам:

```sql
SELECT 
    COUNT(*) AS "Общее количество товаров",
    AVG(цена) AS "Средняя цена",
    MIN(цена) AS "Минимальная цена",
    MAX(цена) AS "Максимальная цена"

```

#### С JOIN

Агрегатные функции часто используются с соединениями таблиц:

```sql
SELECT 
    к.город,
    COUNT(з.id) AS "Количество заказов",
    SUM(з.общая_сумма) AS "Общая сумма заказов",
```

### Практические советы

#### Совет 1: Обработка NULL значений

Агрегатные функции по-разному обрабатывают `NULL`:

- `COUNT(*)` - считает все строки, включая те, где есть `NULL`
- `COUNT(столбец)` - не считает строки, где `столбец` равен `NULL`
- `SUM()`, `AVG()`, `MIN()`, `MAX()` - игнорируют `NULL` значения

#### Совет 2: Использование ROUND() с AVG()

При работе с денежными значениями часто нужно округлять:

```sql
SELECT категория, ROUND(AVG(цена), 2) AS средняя_цена
FROM товары
GROUP BY категория;
```

#### Совет 3: Комбинация агрегатных функций

Можно использовать несколько агрегатных функций в одном запросе:

```sql
SELECT 
    категория,
    COUNT(*) AS кол_во,
    SUM(цена) AS сумма,
    AVG(цена) AS среднее,
    MIN(цена) AS минимум,
    MAX(цена) AS максимум
FROM товары
GROUP BY категория;
```

```sql
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) < 25 THEN 'до 25'
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) BETWEEN 25 AND 40 THEN '25-40'
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) BETWEEN 41 AND 60 THEN '41-60'
        ELSE 'старше 60'

    FROM заказы
    GROUP BY id_клиента
) AS возрастной_средний_чек ON клиенты.id = возрастной_средний_чек.id_клиента
GROUP BY 
    CASE 
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) < 25 THEN 'до 25'
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) BETWEEN 25 AND 40 THEN '25-40'
        WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) BETWEEN 41 AND 60 THEN '41-60'
        ELSE 'старше 60'
    END
ORDER BY "Количество клиентов" DESC;
```

## Глава 24: GROUP BY - Часть 1

### Введение

В предыдущих главах мы познакомились с основами `GROUP BY` и агрегатных функций. В этой части мы более подробно рассмотрим различные аспекты использования `GROUP BY`, включая практические примеры, распространенные ошибки и лучшие практики.

### Основной принцип GROUP BY

Оператор `GROUP BY` позволяет объединять строки с одинаковыми значениями в указанных столбцах в группы. Затем к каждой группе можно применить агрегатные функции для получения обобщенной информации.

### Простые примеры GROUP BY

#### Пример 1: Подсчет клиентов по городам

```sql
SELECT 
    город,
    COUNT(*) AS количество_клиентов
FROM клиенты
GROUP BY город
ORDER BY количество_клиентов DESC;
```

#### Пример 2: Средняя цена товаров по категориям

```sql
SELECT 
    категория,
    AVG(цена) AS средняя_цена
FROM товары
GROUP BY категория
ORDER BY средняя_цена DESC;
```

### GROUP BY с несколькими столбцами

Можно группировать по нескольким столбцам одновременно:

```sql
SELECT 
    город,
    пол,
    COUNT(*) AS количество
FROM клиенты
GROUP BY город, пол
ORDER BY город, пол;
```

Каждая уникальная комбинация значений в указанных столбцах становится отдельной группой.

### GROUP BY с различными агрегатными функциями

```sql
SELECT 
    категория,
    COUNT(*) AS количество_товаров,
    MIN(цена) AS минимальная_цена,
    MAX(цена) AS максимальная_цена,
    AVG(цена) AS средняя_цена,
    SUM(цена) AS суммарная_цена_всех_товаров
FROM товары
GROUP BY категория
ORDER BY средняя_цена DESC;
```

### GROUP BY с вычисляемыми значениями

Можно группировать по результатам выражений:

```sql
SELECT 
    EXTRACT(YEAR FROM дата_заказа) AS год,
    COUNT(*) AS количество_заказов,
    SUM(общая_сумма) AS общая_сумма
FROM заказы
GROUP BY EXTRACT(YEAR FROM дата_заказа)
ORDER BY год;
```

```sql
SELECT 
    CASE 
        WHEN цена < 10000 THEN 'до 10000'
        WHEN цена BETWEEN 10000 AND 50000 THEN '10000-50000'
        ELSE 'свыше 50000'
    END AS ценовая_категория,
    COUNT(*) AS количество_товаров
FROM товары
GROUP BY 
    CASE 
        WHEN цена < 10000 THEN 'до 10000'
        WHEN цена BETWEEN 10000 AND 50000 THEN '10000-50000'
        ELSE 'свыше 50000'
    END
ORDER BY ценовая_категория;
```

### GROUP BY с JOIN

Часто `GROUP BY` используется с соединениями таблиц:

```sql
SELECT 
    к.город,
    COUNT(з.id) AS количество_заказов,
    AVG(з.общая_сумма) AS средний_чек
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
ORDER BY количество_заказов DESC;
```

### Порядок выполнения запроса с GROUP BY

Важно понимать порядок выполнения частей SQL-запроса:

1. `FROM` - определение таблиц
2. `WHERE` - фильтрация строк (до группировки)
3. `GROUP BY` - группировка строк
4. `HAVING` - фильтрация групп (рассматривается в следующей главе)
5. `SELECT` - выбор и вычисление столбцов
6. `ORDER BY` - сортировка результатов

### WHERE vs HAVING

`WHERE` фильтрует строки до группировки, а `HAVING` (рассматривается позже) фильтрует группы после группировки:

```sql
-- Фильтрация до группировки (по отдельным строкам)
SELECT 
    город,
    COUNT(*) AS количество_клиентов
FROM клиенты
WHERE дата_регистрации > '2023-01-01'  -- Фильтр до группировки
GROUP BY город
ORDER BY количество_клиентов DESC;
```

### Практические примеры

#### Пример 1: Анализ заказов по месяцам

```sql
SELECT 
    EXTRACT(YEAR FROM дата_заказа) AS год,
    EXTRACT(MONTH FROM дата_заказа) AS месяц,
    COUNT(*) AS количество_заказов,
    SUM(общая_сумма) AS общая_сумма,
    AVG(общая_сумма) AS средний_чек
FROM заказы
GROUP BY 
    EXTRACT(YEAR FROM дата_заказа),
    EXTRACT(MONTH FROM дата_заказа)
ORDER BY год, месяц;
```

#### Пример 2: Клиенты и их статистика заказов

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    COUNT(з.id) AS количество_заказов,
    COALESCE(SUM(з.общая_сумма), 0) AS общая_сумма_заказов,
    COALESCE(AVG(з.общая_сумма), 0) AS средний_чек
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя, к.город
ORDER BY общая_сумма_заказов DESC
LIMIT 10;
```

#### Пример 3: Анализ товаров по категориям и ценовым диапазонам

```sql
SELECT 
    категория,
    CASE 
        WHEN цена < 10000 THEN 'Низкая'
        WHEN цена BETWEEN 10000 AND 50000 THEN 'Средняя'
        ELSE 'Высокая'
    END AS ценовой_диапазон,
    COUNT(*) AS количество_товаров,
    AVG(цена) AS средняя_цена_в_диапазоне
FROM товары
GROUP BY 
    категория,
    CASE 
        WHEN цена < 10000 THEN 'Низкая'
        WHEN цена BETWEEN 10000 AND 50000 THEN 'Средняя'
        ELSE 'Высокая'
    END
ORDER BY категория, ценовой_диапазон;
```

### Проблемы с GROUP BY

#### Проблема 1: Не все столбцы в SELECT указаны в GROUP BY

```sql
-- ОШИБКА: фамилия не входит в GROUP BY
SELECT 
    фамилия,
    город,
    COUNT(*) AS количество
FROM клиенты
GROUP BY город;
```

#### Проблема 2: Неправильное понимание группировки

После `GROUP BY` в результирующем наборе будет столько строк, сколько уникальных комбинаций значений в группировке.

### Практические советы

#### Совет 1: Использование полных списков столбцов

При группировке по нескольким столбцам убедитесь, что все неагрегированные столбцы из `SELECT` указаны в `GROUP BY`:

```sql
-- ПРАВИЛЬНО
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    COUNT(з.id) AS количество_заказов
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя, к.город
ORDER BY количество_заказов DESC;
```

#### Совет 2: Использование уникального идентификатора при группировке

Часто для корректной группировки нужно включить уникальный идентификатор сущности:

```sql
-- Для корректной группировки клиентов
SELECT 
    к.id,
    к.фамилия,
    к.имя,
    COUNT(з.id) AS количество_заказов
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя;
```

## Глава 25: GROUP BY - Часть 2

### Введение

Продолжаем изучение оператора `GROUP BY`. В этой части мы рассмотрим более продвинутые применения `GROUP BY`, включая его использование с оконными функциями, расширенные примеры из практики и сложные сценарии группировки.

### GROUP BY с условными агрегатами

Используя `CASE` внутри агрегатных функций, можно вычислять условные метрики:

```sql
SELECT 
    город,
    COUNT(*) AS "Все клиенты",
    COUNT(CASE WHEN пол = 'М' THEN 1 END) AS "Мужчины",
    COUNT(CASE WHEN пол = 'Ж' THEN 1 END) AS "Женщины",
    ROUND(
        COUNT(CASE WHEN пол = 'М' THEN 1 END) * 100.0 / COUNT(*), 
        2
    ) AS "Процент мужчин"
FROM клиенты
GROUP BY город
ORDER BY "Все клиенты" DESC;
```

### GROUP BY со статистическими функциями

PostgreSQL предоставляет расширенные статистические функции, которые можно использовать с `GROUP BY`:

```sql
SELECT 
    категория,
    COUNT(*) AS "Количество",
    AVG(цена) AS "Среднее",
    MEDIAN(цена) AS "Медиана",
    MODE() WITHIN GROUP (ORDER BY цена) AS "Мода",
    STDDEV(цена) AS "Стандартное отклонение",
    VARIANCE(цена) AS "Дисперсия"
FROM товары
GROUP BY категория;
```

> Примечание: `MEDIAN` и `MODE` могут потребовать дополнительных расширений в некоторых версиях PostgreSQL.

### GROUP BY с ROLLUP, CUBE и GROUPING SETS

PostgreSQL поддерживает расширенные возможности группировки:

#### ROLLUP

`ROLLUP` создает иерархические группы и итоги:

```sql
SELECT 
    город,
    пол,
    COUNT(*) AS количество
FROM клиенты
GROUP BY ROLLUP(город, пол)
ORDER BY город, пол;
```

Этот запрос создаст:
- Группы по городу и полу
- Подытоги по каждому городу
- Общий итог

#### GROUPING SETS

Позволяет явно указать, какие группы создавать:

```sql
SELECT 
    город,
    пол,
    COUNT(*) AS количество
FROM клиенты
GROUP BY GROUPING SETS ((город), (пол), ())
ORDER BY GROUPING(город), GROUPING(пол), город, пол;
```

Этот запрос создаст:
- Группировку по городу
- Группировку по полу
- Общий итог

### GROUP BY с подзапросами

#### Внутренний GROUP BY

Сначала группируем данные, затем снова группируем результат:

```sql
SELECT 
    возрастная_группа,
    COUNT(*) AS количество_клиентов,
    AVG(средний_чек) AS средний_чек_в_группе
FROM (
    SELECT 
        к.id,
        CASE 
            WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM к.дата_рождения)) < 25 THEN 'до 25'
            WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM к.дата_рождения)) BETWEEN 25 AND 40 THEN '25-40'
            WHEN (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM к.дата_рождения)) BETWEEN 41 AND 60 THEN '41-60'
            ELSE 'старше 60'
        END AS возрастная_группа,
        COALESCE(
            (SELECT AVG(общая_сумма) 
             FROM заказы 
             WHERE id_клиента = к.id), 
            0
        ) AS средний_чек
    FROM клиенты к
) AS клиенты_с_группами
GROUP BY возрастная_группа
ORDER BY количество_клиентов DESC;
```

### GROUP BY с оконными функциями

Можно сочетать `GROUP BY` с оконными функциями:

```sql
SELECT 
    категория,
    COUNT(*) AS количество_товаров,
    AVG(цена) AS средняя_цена_в_категории,
    AVG(AVG(цена)) OVER() AS средняя_цена_по_всем_категориям,
    RANK() OVER (ORDER BY AVG(цена) DESC) AS ранг_по_цене
FROM товары
GROUP BY категория
ORDER BY ранг_по_цене;
```

### GROUP BY с фильтрацией результатов

#### Использование HAVING (подробнее в следующей главе)

```sql
SELECT 
    город,
    COUNT(*) AS количество_клиентов
FROM клиенты
GROUP BY город
HAVING COUNT(*) > 1;  -- Только города с более чем 1 клиентом
```

```sql
WHERE з.дата_заказа >= '2022-01-01'
```

#### Пример 2: Анализ жизненного цикла клиентов

```sql
SELECT 
    клиентская_группа.группа,
    COUNT(*) AS "Количество клиентов",
    AVG(клиентская_группа.общая_сумма) AS "Средняя сумма заказов",
    AVG(клиентская_группа.количество_заказов) AS "Среднее количество заказов",
    AVG(
        EXTRACT(DAY FROM (клиентская_группа.последний_заказ - клиентская_группа.первый_заказ))
    ) AS "Средняя продолжительность отношений (дней)"
FROM (
    SELECT 
        к.id AS клиент_id,
        к.город,
        COUNT(з.id) AS количество_заказов,
        SUM(з.общая_сумма) AS общая_сумма,
        MIN(з.дата_заказа) AS первый_заказ,
        MAX(з.дата_заказа) AS последний_заказ,
        CASE 
            WHEN SUM(з.общая_сумма) > 100000 THEN 'VIP'
            WHEN SUM(з.общая_сумма) BETWEEN 50000 AND 100000 THEN 'Премиум'
            WHEN SUM(з.общая_сумма) BETWEEN 10000 AND 50000 THEN 'Стандарт'
            ELSE 'Новичок'
        END AS группа
    FROM клиенты к
    LEFT JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.id
) AS клиентская_группа
GROUP BY клиентская_группа.группа

```

#### Пример 3: Сравнение с предыдущим периодом

```sql
SELECT 
    текущий.месяц,
    текущий.год,
    текущий.доход AS "Доход текущий",
    предыдущий.доход AS "Доход предыдущий",
    текущий.доход - COALESCE(предыдущий.доход, 0) AS "Разница",
    ROUND(
        (текущий.доход - COALESCE(предыдущий.доход, 0)) * 100.0 / 
        NULLIF(COALESCE(предыдущий.доход, 0), 0), 
        2
    ) AS "Рост (%)"
FROM (
    SELECT 
        EXTRACT(YEAR FROM дата_заказа) AS год,
        EXTRACT(MONTH FROM дата_заказа) AS месяц,
        SUM(общая_сумма) AS доход
    FROM заказы
    GROUP BY EXTRACT(YEAR FROM дата_заказа), EXTRACT(MONTH FROM дата_заказа)
) AS текущий
LEFT JOIN (
    SELECT 
        EXTRACT(YEAR FROM дата_заказа) + 
        CASE WHEN EXTRACT(MONTH FROM дата_заказа) = 1 THEN -1 ELSE 0 END AS год,
        CASE 
            WHEN EXTRACT(MONTH FROM дата_заказа) = 1 THEN 12 
            ELSE EXTRACT(MONTH FROM дата_заказа) - 1 
        END AS месяц,
        SUM(общая_сумма) AS доход
    FROM заказы
    GROUP BY 
        EXTRACT(YEAR FROM дата_заказа), 
        EXTRACT(MONTH FROM дата_заказа)
) AS предыдущий 
ON текущий.месяц = предыдущий.месяц AND текущий.год = предыдущий.год
ORDER BY текущий.год DESC, текущий.месяц DESC;
```

### Проблемы и решения при использовании GROUP BY

#### Проблема 1: Неоднозначность в выражениях

Когда в `SELECT` есть сложные выражения, которые не входят в `GROUP BY`:

```sql
-- Потенциальная проблема
SELECT 
    CONCAT(фамилия, ' ', имя) AS полное_имя,
    COUNT(*) AS количество
FROM клиенты
GROUP BY фамилия;  -- имя не входит в GROUP BY!
```

#### Решение 1: Включить все используемые столбцы в GROUP BY

```sql
SELECT 
    CONCAT(фамилия, ' ', имя) AS полное_имя,
    COUNT(*) AS количество
FROM клиенты
GROUP BY фамилия, имя
ORDER BY количество DESC;
```

#### Проблема 2: Смешивание детальных и агрегированных данных

```sql
-- ОШИБКА: нельзя одновременно показывать детали и агрегаты без правильной группировки
SELECT 
    фамилия,  -- детальный уровень
    COUNT(*)  -- агрегированный уровень
FROM клиенты;
```

### Лучшие практики GROUP BY

#### Практика 1: Использование осмысленных названий для групп

```sql
-- ХОРОШО
SELECT 
    CASE 
        WHEN возраст < 25 THEN 'Молодежь'
        WHEN возраст BETWEEN 25 AND 40 THEN 'Молодые профессионалы'
        ELSE 'Опытные специалисты'
    END AS возрастная_группа,
    COUNT(*) AS количество
FROM (
    SELECT 
        id,
        (EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения)) AS возраст
    FROM клиенты
) AS клиенты_с_возрастом
GROUP BY 
    CASE 
        WHEN возраст < 25 THEN 'Молодежь'
        WHEN возраст BETWEEN 25 AND 40 THEN 'Молодые профессионалы'
        ELSE 'Опытные специалисты'
    END;
```

#### Практика 2: Тестирование результатов группировки

Всегда проверяйте, что количество строк в результатах соответствует ожиданиям:

```sql
-- Проверка: сколько уникальных комбинаций городов и полов?
SELECT COUNT(*) 
FROM (
    SELECT DISTINCT город, пол 
    FROM клиенты
) AS уникальные_комбинации;
```

#### Практика 3: Использование CTE для сложных группировок

Для сложных запросов используйте выражения общего табличного вида (CTE):

```sql
WITH клиенты_с_заказами AS (
    SELECT 
        к.id,
        к.фамилия,
        к.имя,
        к.город,
        COUNT(з.id) AS количество_заказов,
        COALESCE(SUM(з.общая_сумма), 0) AS общая_сумма
    FROM клиенты к
    LEFT JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.id, к.фамилия, к.имя, к.город
),
категории_по_доходу AS (
    SELECT 
        *,
        CASE 
            WHEN общая_сумма > 100000 THEN 'Высокий доход'
            WHEN общая_сумма BETWEEN 50000 AND 100000 THEN 'Средний доход'
            ELSE 'Низкий доход'
        END AS категория_дохода
    FROM клиенты_с_заказами
)
SELECT 
    город,
    категория_дохода,
    COUNT(*) AS количество_клиентов,
    AVG(количество_заказов) AS среднее_количество_заказов,
    AVG(общая_сумма) AS средняя_сумма
FROM категории_по_доходу
GROUP BY город, категория_дохода
ORDER BY город, категория_дохода;
```

### Заключение части 2

`GROUP BY` - мощный инструмент для анализа данных, позволяющий создавать сложные аналитические запросы. Понимание его возможностей, особенно в сочетании с агрегатными функциями, подзапросами и оконными функциями, открывает широкие возможности для извлечения значимой информации из баз данных.     COUNT(*) AS "Всего заказов",
```sql
    COUNT(CASE WHEN з.статус = 'новый' THEN 1 END) AS "Новые",
    COUNT(CASE WHEN з.статус = 'оплачен' THEN 1 END) AS "Оплачены",
    COUNT(CASE WHEN з.статус = 'в_доставке' THEN 1 END) AS "В доставке",
    COUNT(CASE WHEN з.статус = 'доставлен' THEN 1 END) AS "Доставлены"
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
ORDER BY "Всего заказов" DESC;
```

#### Задание 13: Статистика по периодам

**Сценарий:** Финансисты хотят квартальный отчет.

**Задача:** Выведите год, квартал и по каждому кварталу посчитайте количество заказов, общую сумму и средний чек. Ограничьте 2023 годом.

**Решение:**
```sql
SELECT 
    EXTRACT(YEAR FROM дата_заказа) AS год,
    EXTRACT(QUARTER FROM дата_заказа) AS квартал,
    COUNT(*) AS количество_заказов,
    SUM(общая_сумма) AS общая_сумма,
    ROUND(AVG(общая_сумма), 2) AS средний_чек
FROM заказы
WHERE EXTRACT(YEAR FROM дата_заказа) = 2023
GROUP BY 
    EXTRACT(YEAR FROM дата_заказа),
    EXTRACT(QUARTER FROM дата_заказа)
ORDER BY год, квартал;
```

#### Задание 14: Сложная группировка с соединением таблиц

**Сценарий:** Нужен детальный анализ покупательской активности.

**Задача:** Выведите категорию товара, город клиента и для каждой пары покажите общую сумму покупок. Включите только пары, где общая сумма больше 0.

**Решение:**
```sql
SELECT 
    т.категория,
    к.город,
    SUM(з.общая_сумма) AS общая_сумма_покупок
FROM заказы з
JOIN клиенты к ON з.id_клиента = к.id
JOIN товары т ON т.категория IS NOT NULL -- предполагаем соединение через какую-то связь
GROUP BY т.категория, к.город
HAVING SUM(з.общая_сумма) > 0
ORDER BY общая_сумма_покупок DESC;
```

#### Задание 15: Комплексный аналитический запрос

**Сценарий:** Руководство хочет полный обзор бизнеса по городам.

**Задача:** Выведите город и по каждому городу рассчитайте: количество клиентов, количество заказов, общую сумму заказов, средний чек, количество уникальных категорий товаров, купленных клиентами из этого города.

**Решение:**
```sql
SELECT 
    к.город,
    COUNT(DISTINCT к.id) AS количество_клиентов,
    COUNT(з.id) AS количество_заказов,
    SUM(з.общая_сумма) AS общая_сумма,
    ROUND(AVG(з.общая_сумма), 2) AS средний_чек,
    COUNT(DISTINCT т.категория) AS уникальных_категорий
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
LEFT JOIN (
    -- Предполагаем наличие связи заказов с товарами
    SELECT DISTINCT 
        з.id AS заказ_id, 
        т.категория
    FROM заказы з
    JOIN товары т ON т.категория IS NOT NULL
) т ON т.заказ_id = з.id
GROUP BY к.город
ORDER BY количество_клиентов DESC;
```

## Глава 27: HAVING

### Введение

Оператор `HAVING` используется для фильтрации групп, созданных с помощью `GROUP BY`. Тогда как `WHERE` фильтрует строки до группировки, `HAVING` фильтрует результаты после группировки. Это позволяет применять условия к агрегатным функциям, что невозможно сделать с помощью `WHERE`.

### Базовый синтаксис

```sql
SELECT столбцы, агрегатная_функция(столбец)
FROM таблица
WHERE условие_до_группировки
GROUP BY столбец
HAVING условие_после_группировки
ORDER BY столбцы;
```

### Отличие WHERE от HAVING

#### WHERE
- Фильтрует строки до группировки
- Не может использовать агрегатные функции
- Применяется к отдельным строкам

#### HAVING
- Фильтрует группы после группировки
- Может использовать агрегатные функции
- Применяется к результатам группировки

### Простые примеры HAVING

#### Пример 1: Города с более чем 1 клиентом

```sql
SELECT 
    город,
    COUNT(*) AS количество_клиентов
FROM клиенты
GROUP BY город
HAVING COUNT(*) > 1;
```

#### Пример 2: Категории товаров со средней ценой выше 20000

```sql
SELECT 
    категория,
    AVG(цена) AS средняя_цена
FROM товары
GROUP BY категория
HAVING AVG(цена) > 20000;
```

### HAVING с несколькими условиями

```sql
SELECT 
    город,
    COUNT(*) AS количество_клиентов,
    AVG(возраст) AS средний_возраст
FROM (
    SELECT 
        *,
        EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения) AS возраст
    FROM клиенты
) AS клиенты_с_возрастом
GROUP BY город
HAVING COUNT(*) >= 2 AND AVG(возраст) > 30;
```

### HAVING с различными агрегатными функциями

#### COUNT в HAVING

```sql
-- Категории с более чем 3 товарами
SELECT 
    категория,
    COUNT(*) AS количество_товаров
FROM товары
GROUP BY категория
HAVING COUNT(*) > 3;
```

#### SUM в HAVING

```sql
-- Клиенты с общей суммой заказов более 100000
SELECT 
    id_клиента,
    SUM(общая_сумма) AS общая_сумма_заказов
FROM заказы
GROUP BY id_клиента
HAVING SUM(общая_сумма) > 100000;
```

#### AVG в HAVING

```sql
-- Категории товаров со средней ценой от 10000 до 50000
SELECT 
    категория,
    AVG(цена) AS средняя_цена
FROM товары
GROUP BY категория
HAVING AVG(цена) BETWEEN 10000 AND 50000;
```

#### MIN и MAX в HAVING

```sql
-- Города, где максимальная цена товара больше 50000
SELECT 
    к.город,
    MAX(т.цена) AS максимальная_цена
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
JOIN товары т ON т.цена IS NOT NULL -- предполагаем косвенное соединение
GROUP BY к.город
HAVING MAX(т.цена) > 50000;
```

### HAVING с условиями OR

```sql
SELECT 
    категория,
    COUNT(*) AS количество_товаров,
    AVG(цена) AS средняя_цена
FROM товары
GROUP BY категория
HAVING COUNT(*) > 5 OR AVG(цена) > 30000;
```

### Сочетание WHERE и HAVING

Часто `WHERE` и `HAVING` используются вместе:

```sql
SELECT 
    к.город,
    COUNT(з.id) AS количество_заказов,
    AVG(з.общая_сумма) AS средний_чек
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
WHERE EXTRACT(YEAR FROM з.дата_заказа) = 2023  -- фильтр до группировки
GROUP BY к.город
HAVING COUNT(з.id) >= 3;  -- фильтр после группировки
```

### HAVING с выражениями

```sql
SELECT 
    категория,
    COUNT(*) AS количество_товаров,
    AVG(цена) AS средняя_цена,
    MIN(цена) AS минимальная_цена,
    MAX(цена) AS максимальная_цена
FROM товары
GROUP BY категория
HAVING MAX(цена) - MIN(цена) > 20000;  -- разница между макс и мин ценой > 20000
```

### Практические примеры

#### Пример 1: Активные клиенты по городам

### Продвинутые примеры из российской практики

#### Пример 1: Анализ клиентской активности по регионам

```sql
WITH клиенты_с_активностью AS (
    SELECT 
        к.id AS клиент_id,
        к.город,
        COUNT(з.id) AS количество_заказов,
        SUM(з.общая_сумма) AS общая_сумма,
        MIN(з.дата_заказа) AS первый_заказ,
        MAX(з.дата_заказа) AS последний_заказ,

    FROM клиенты к
    LEFT JOIN заказы з ON к.id = з.id_клиента
    GROUP BY к.id, к.город
)
SELECT 
    город,
    COUNT(*) AS количество_клиентов,
    AVG(количество_заказов) AS среднее_заказов_на_клиента,

FROM клиенты_с_активностью
WHERE количество_заказов > 0  -- только активные клиенты
GROUP BY город
HAVING 
    COUNT(*) >= 2  -- только города с 2+ клиентами
    AND AVG(количество_заказов) >= 2  -- среднее не менее 2 заказов на клиента
    AND AVG(активных_месяцев) >= 3  -- среднее не менее 3 активных месяцев
ORDER BY средняя_сумма_на_клиента DESC;
```

#### Пример 2: Фильтрация по сложным агрегатным условиям

```sql
SELECT 
    к.город,
    COUNT(DISTINCT к.id) AS количество_клиентов,
    COUNT(з.id) AS количество_заказов,
    SUM(з.общая_сумма) AS общая_сумма,
    AVG(з.общая_сумма) AS средний_чек,
    MAX(з.общая_сумма) AS максимальный_заказ
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
WHERE з.дата_заказа >= '2023-01-01'
GROUP BY к.город
HAVING 
    COUNT(DISTINCT к.id) >= 3  -- минимум 3 уникальных клиента
    AND COUNT(з.id) >= 5       -- минимум 5 заказов
    AND SUM(з.общая_сумма) >= 100000  -- общая сумма не менее 100 000
    AND AVG(з.общая_сумма) >= 20000   -- средний чек не менее 20 000
    AND MAX(з.общая_сумма) >= 50000   -- максимальный заказ не менее 50 000
ORDER BY общая_сумма DESC;
```

### Практические советы

#### Совет 1: Использование WHERE когда это возможно

Когда фильтр может быть применен до группировки, используйте `WHERE` вместо `HAVING` для повышения производительности:

```sql
-- БОЛЕЕ эффективно
SELECT 
    город,
    COUNT(*) AS количество
FROM клиенты
WHERE дата_регистрации > '2023-01-01'
GROUP BY город
HAVING COUNT(*) > 1;

-- МЕНЕЕ эффективно (но дает тот же результат)
SELECT 
    город,
    COUNT(*) AS количество
FROM клиенты
GROUP BY город
HAVING 
    COUNT(*) > 1 
    AND COUNT(CASE WHEN дата_регистрации > '2023-01-01' THEN 1 END) > 0;
```

#### Совет 2: Порядок условий в HAVING

При сложных условиях в `HAVING` старайтесь помещать более ограничивающие условия первыми:

```sql
-- Более ограничивающее условие первым
HAVING COUNT(*) > 10 AND AVG(цена) > 50000
```

#### Совет 3: Использование подзапросов в HAVING

Можно использовать подзапросы в условиях `HAVING`:

```sql
SELECT 
    категория,
    AVG(цена) AS средняя_цена
FROM товары
GROUP BY категория
HAVING AVG(цена) > (
    SELECT AVG(цена) FROM товары
);  -- Только категории со средней ценой выше общей средней
```

### Часто допускаемые ошибки

#### Ошибка 1: Использование столбцов без агрегации в HAVING

```sql
-- ОШИБКА: нельзя использовать фамилию в HAVING без группировки или агрегации
SELECT 
    город,
    COUNT(*) AS количество
FROM клиенты
GROUP BY город
HAVING фамилия = 'Иванов';
```

#### Ошибка 2: Попытка использовать HAVING без GROUP BY

```sql
-- ОШИБКА: HAVING требует GROUP BY
SELECT * FROM заказы
HAVING общая_сумма > 10000;
```

#### Ошибка 3: Неправильное понимание последовательности

Помните, что сначала применяется `WHERE`, затем `GROUP BY`, потом `HAVING`:

```sql
-- Правильно: сначала фильтруем заказы за 2023 год, затем группируем, затем фильтруем группы
SELECT 
    id_клиента,
    COUNT(*) AS количество_заказов
FROM заказы
WHERE EXTRACT(YEAR FROM дата_заказа) = 2023
GROUP BY id_клиента
HAVING COUNT(*) > 5;
```

### Заключение главы

Оператор `HAVING` - важный инструмент для фильтрации результатов группировки. Он позволяет применять условия к результатам агрегатных функций, что невозможно сделать с помощью `WHERE`. Правильное понимание различий между `WHERE` и `HAVING`, а также уместное их сочетание - ключ к созданию эффективных и информативных аналитических запросов.

## Глава 28: Задание: HAVING

### Введение

В этой главе вы получите практические задания, которые помогут закрепить знания об использовании оператора `HAVING` для фильтрации групп, созданных с помощью `GROUP BY`. Задания охватывают различные сценарии использования `HAVING` с различными агрегатными функциями.

### Сценарии и задачи

#### Задание 1: Города с более чем 1 клиентом

**Сценарий:** Руководство хочет видеть только те города, где зарегистрировано более одного клиента.

**Задача:** Выведите город и количество клиентов в каждом городе, но только для городов, где зарегистрировано более одного клиента.

```sql
SELECT
```

#### Задание 2: Категории товаров с высокой средней ценой

**Сценарий:** Маркетологи интересуются только категориями товаров со средней ценой выше 30000.

**Задача:** Выведите категорию и среднюю цену товаров только для тех категорий, где средняя цена превышает 30000.

**Решение:**
```sql
SELECT 
    категория,
    ROUND(AVG(цена), 2) AS средняя_цена
FROM товары
GROUP BY категория
HAVING AVG(цена) > 30000
ORDER BY средняя_цена DESC;
```

#### Задание 3: Клиенты с более чем 2 заказами

**Сценарий:** Отдел лояльности хочет идентифицировать постоянных клиентов.

**Задача:** Выведите ID клиента, фамилию, имя и количество заказов, но только для клиентов, у которых более 2 заказов.

**Решение:**
```sql
SELECT 
    к.id,
    к.фамилия,
    к.имя,
    COUNT(з.id) AS количество_заказов
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя
HAVING COUNT(з.id) > 2
ORDER BY количество_заказов DESC;
```

#### Задание 4: Города с высоким средним чеком

**Сценарий:** Финансисты хотят выделить города с высоким средним чеком заказов.

**Задача:** Выведите город и средний чек заказов, но только для городов, где средний чек больше 40000.

**Решение:**
```sql
SELECT 
    к.город,

FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента

```

#### Задание 5: Категории с широким ценовым диапазоном

**Сценарий:** Аналитики хотят выявить категории товаров с высокой вариативностью цен.

**Задача:** Выведите категорию, минимальную и максимальную цену, но только для категорий, где разница между максимальной и минимальной ценой превышает 70000.

```sql
SELECT 
    категория,
    MIN(цена) AS минимальная_цена,
    MAX(цена) AS максимальная_цена,
    MAX(цена) - MIN(цена) AS разница
```

#### Задание 6: Клиенты с высокой общей суммой заказов

**Задача:** Выведите ID клиента, фамилию, имя и общую сумму заказов, но только для клиентов с общей суммой заказов более 150000.

```sql
SELECT

    к.имя,
```

#### Задание 7: Месяцы с высокой активностью

**Сценарий:** Отдел анализа хочет выделить месяцы с интенсивной активностью.

**Задача:** Выведите год, месяц и количество заказов, но только для месяцев с более чем 2 заказами. Ограничьте данные 2023 годом.

```sql
ORDER BY год, месяц;
```

#### Задание 8: Категории с разнообразным ассортиментом

**Сценарий:** Отдел закупок интересуется категориями с широким ассортиментом товаров.

**Задача:** Выведите категорию и количество товаров, но только для категорий, содержащих более 3 товаров, средняя цена которых находится в диапазоне от 10000 до 50000.

**Решение:**
```sql
SELECT 
    категория,
    COUNT(*) AS количество_товаров,
    ROUND(AVG(цена), 2) AS средняя_цена
FROM товары
GROUP BY категория
HAVING 
    COUNT(*) > 3 
    AND AVG(цена) BETWEEN 10000 AND 50000
ORDER BY количество_товаров DESC;
```

#### Задание 9: Статусы заказов с высокой общей суммой

**Сценарий:** Финансисты хотят понять, какие статусы заказов приносят наибольшую выручку.

**Задача:** Выведите статус заказа, количество заказов и общую сумму, но только для статусов, где общая сумма превышает 50000.

**Решение:**
```sql
SELECT 
    статус,
    COUNT(*) AS количество_заказов,
    SUM(общая_сумма) AS общая_сумма
FROM заказы
GROUP BY статус
HAVING SUM(общая_сумма) > 50000
ORDER BY общая_сумма DESC;
```

#### Задание 10: Клиенты с редкими, но дорогими заказами

**Сценарий:** Отдел маркетинга хочет выделить клиентов, которые делают редкие, но дорогие покупки.

**Задача:** Выведите ID клиента, фамилию, имя, количество заказов и среднюю сумму заказа, но только для клиентов, у которых не более 3 заказов, но средняя сумма заказа превышает 60000.

**Решение:**
```sql
SELECT 
    к.id,
    к.фамилия,
    к.имя,
    COUNT(з.id) AS количество_заказов,
    ROUND(AVG(з.общая_сумма), 2) AS средняя_сумма_заказа
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя
HAVING 
    COUNT(з.id) <= 3 
    AND AVG(з.общая_сумма) > 60000
ORDER BY средняя_сумма_заказа DESC;
```

#### Задание 11: Условия с несколькими агрегатными функциями

**Сценарий:** Анализ продаж с комплексными критериями.

**Задача:** Выведите город, количество заказов и средний чек, но только для городов с не менее чем 3 заказами и средним чеком более 35000.

**Решение:**
```sql
SELECT 
    к.город,
    COUNT(з.id) AS количество_заказов,
    ROUND(AVG(з.общая_сумма), 2) AS средний_чек
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
HAVING 
    COUNT(з.id) >= 3 
    AND AVG(з.общая_сумма) > 35000
ORDER BY средний_чек DESC;
```

#### Задание 12: Города с высокой вариативностью заказов

**Сценарий:** Отдел анализа хочет выявить города с большой разницей между минимальным и максимальным заказом.

**Задача:** Выведите город, минимальную и максимальную сумму заказа, но только для городов, где разница между максимальным и минимальным заказом превышает 50000.

**Решение:**
```sql
SELECT 
    к.город,
    MIN(з.общая_сумма) AS минимальный_заказ,
    MAX(з.общая_сумма) AS максимальный_заказ,
    MAX(з.общая_сумма) - MIN(з.общая_сумма) AS разница
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
HAVING 
    MAX(з.общая_сумма) - MIN(з.общая_сумма) > 50000
ORDER BY разница DESC;
```

#### Задание 13: Сравнение с общими показателями

**Сценарий:** Нужно выделить города, превышающие общие показатели.

**Задача:** Выведите город и среднюю сумму заказа, но только для городов, где средняя сумма заказа выше общей средней по всем заказам.

**Решение:**
```sql
SELECT 
    к.город,
    ROUND(AVG(з.общая_сумма), 2) AS средняя_сумма_заказа
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
HAVING AVG(з.общая_сумма) > (
    SELECT AVG(общая_сумма) FROM заказы
)
ORDER BY средняя_сумма_заказа DESC;
```

#### Задание 14: Сложное условие с разными агрегатами

**Сценарий:** Комплексный анализ клиентов.

**Задача:** Выведите город, количество клиентов из этого города и среднюю сумму их заказов, но только для городов с не менее чем 2 клиентами, средняя сумма заказов которых превышает 45000, а максимальная сумма заказа превышает 80000.

**Решение:**
```sql
SELECT 
    к.город,
    COUNT(DISTINCT к.id) AS количество_клиентов,
    ROUND(AVG(з.общая_сумма), 2) AS средняя_сумма_заказа,
    MAX(з.общая_сумма) AS максимальный_заказ
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
HAVING 
    COUNT(DISTINCT к.id) >= 2
    AND AVG(з.общая_сумма) > 45000
    AND MAX(з.общая_сумма) > 80000
ORDER BY средняя_сумма_заказа DESC;
```

#### Задание 15: Комплексный отчет с несколькими условиями

**Сценарий:** Итоговый отчет по эффективности городов.

**Задача:** Выведите город и следующие метрики: количество клиентов, количество заказов, общая сумма заказов, средний чек, максимальный заказ. Покажите только те города, которые одновременно удовлетворяют всем условиям:
- Не менее 3 клиентов
- Не менее 5 заказов
- Общая сумма заказов более 200000
- Средний чек более 40000
- Максимальный заказ более 90000

**Решение:**
```sql
SELECT 
    к.город,
    COUNT(DISTINCT к.id) AS количество_клиентов,
    COUNT(з.id) AS количество_заказов,
    SUM(з.общая_сумма) AS общая_сумма_заказов,
    ROUND(AVG(з.общая_сумма), 2) AS средний_чек,
    MAX(з.общая_сумма) AS максимальный_заказ
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
HAVING 
    COUNT(DISTINCT к.id) >= 3
    AND COUNT(з.id) >= 5
    AND SUM(з.общая_сумма) > 200000
    AND AVG(з.общая_сумма) > 40000
    AND MAX(з.общая_сумма) > 90000
ORDER BY общая_сумма_заказов DESC;
```

Понимание и практика использования `HAVING` с различными агрегатными функциями и условиями критически важно для создания сложных аналитических запросов и получения значимых бизнес-инсайтов.

## Глава 29: Window функции

### Введение

Оконные функции (Window Functions) - это мощная возможность SQL, которая позволяет выполнять вычисления над набором строк, связанных с текущей строкой. В отличие от агрегатных функций с `GROUP BY`, оконные функции не уменьшают количество строк в результитах - каждая строка из исходного набора присутствует в выходных данных. Они особенно полезны для вычисления скользящих средних, ранжирования, вычисления накопительных итогов и других аналитических задач.

### Базовый синтаксис оконных функций

```sql
ФУНКЦИЯ(аргументы) OVER (
    PARTITION BY столбцы_для_разделения
    ORDER BY столбцы_для_сортировки
    ROWS/RANGE frame_clause
)
```

### Типы оконных функций

#### 1. Ранжирующие функции

##### ROW_NUMBER()
Назначает уникальный номер строке в пределах окна:

```sql
SELECT 
    фамилия,
    имя,
    город,
    ROW_NUMBER() OVER (ORDER BY фамилия) AS номер_по_алфавиту
FROM клиенты;
```

##### RANK()
Назначает ранг с пропусками:

```sql
SELECT 
    наименование,
    цена,
    RANK() OVER (ORDER BY цена DESC) AS ранг_по_цене
FROM товары;
```

##### DENSE_RANK()
Назначает ранг без пропусков:

```sql
SELECT 
    наименование,
    цена,
    DENSE_RANK() OVER (ORDER BY цена DESC) AS плотный_ранг_по_цене
FROM товары;
```

#### 2. Агрегатные оконные функции

Все обычные агрегатные функции могут использоваться как оконные:

```sql
SELECT 
    фамилия,
    имя,
    город,
    общая_сумма,
    AVG(общая_сумма) OVER (PARTITION BY город) AS средний_чек_по_городу,
    SUM(общая_сумма) OVER (PARTITION BY город) AS общий_объем_по_городу
FROM заказы
JOIN клиенты ON заказы.id_клиента = клиенты.id;
```

#### 3. Функции смещения

##### LAG()
Получает значение из предыдущей строки:

```sql
SELECT 
    EXTRACT(YEAR FROM дата_заказа) AS год,
    EXTRACT(MONTH FROM дата_заказа) AS месяц,
    SUM(общая_сумма) AS месячная_сумма,
    LAG(SUM(общая_сумма)) OVER (
        ORDER BY EXTRACT(YEAR FROM дата_заказа), EXTRACT(MONTH FROM дата_заказа)
    ) AS предыдущая_месячная_сумма
FROM заказы
GROUP BY 
    EXTRACT(YEAR FROM дата_заказа), 
    EXTRACT(MONTH FROM дата_заказа)
ORDER BY год, месяц;
```

##### LEAD()
Получает значение из следующей строки:

```sql
SELECT 
    фамилия,
    имя,
    цена,
    LEAD(цена) OVER (ORDER BY цена DESC) AS цена_следующего_по_цене
FROM товары
ORDER BY цена DESC;
```

##### FIRST_VALUE()
Получает первое значение в окне:

```sql
SELECT 
    наименование,
    категория,
    цена,
    FIRST_VALUE(цена) OVER (
        PARTITION BY категория 
        ORDER BY цена DESC
    ) AS максимальная_цена_в_категории
FROM товары;
```

##### LAST_VALUE()
Получает последнее значение в окне:

```sql
SELECT 
    наименование,
    категория,
    цена,
    LAST_VALUE(цена) OVER (
        PARTITION BY категория 
        ORDER BY цена DESC
        ROWS BETWEEN UNBOUNDED PRECEDING AND UNBOUNDED FOLLOWING
    ) AS минимальная_цена_в_категории
FROM товары;
```

### PARTITION BY

Оператор `PARTITION BY` делит строки на группы (окна), в пределах которых применяется оконная функция:

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    з.общая_сумма,
    ROW_NUMBER() OVER (
        PARTITION BY к.город 
        ORDER BY з.общая_сумма DESC
    ) AS ранг_в_городе
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
ORDER BY к.город, ранг_в_городе;
```

### ORDER BY в оконных функциях

Сортировка в `OVER` определяет порядок строк в окне:

```sql
SELECT 
    наименование,
    категория,
    цена,
    RANK() OVER (
        PARTITION BY категория 
        ORDER BY цена DESC
    ) AS ранг_в_категории,
    ROW_NUMBER() OVER (
        PARTITION BY категория 
        ORDER BY цена DESC
    ) AS номер_в_категории
FROM товары
ORDER BY категория, цена DESC;
```

### Классические примеры использования оконных функций

#### Пример 1: Топ-N в каждой категории

```sql
-- Топ-3 самых дорогих товаров в каждой категории
SELECT 
    наименование,
    категория,
    цена
FROM (
    SELECT 
        наименование,
        категория,
        цена,
        ROW_NUMBER() OVER (
            PARTITION BY категория 
            ORDER BY цена DESC
        ) AS rn
    FROM товары
) AS ranked
WHERE rn <= 3
ORDER BY категория, цена DESC;
```

#### Пример 2: Накопительные итоги

```sql
SELECT 
    дата_заказа,
    общая_сумма,
    SUM(общая_сумма) OVER (
        ORDER BY дата_заказа
        ROWS UNBOUNDED PRECEDING
    ) AS накопительная_сумма
FROM заказы
ORDER BY дата_заказа;
```

#### Пример 3: Скользящее среднее

```sql
SELECT 
    EXTRACT(DATE FROM дата_заказа) AS дата,
    COUNT(*) AS количество_заказов,
    AVG(COUNT(*)) OVER (
        ORDER BY EXTRACT(DATE FROM дата_заказа)
        ROWS BETWEEN 6 PRECEDING AND CURRENT ROW
    ) AS среднее_за_7_дней
FROM заказы
GROUP BY EXTRACT(DATE FROM дата_заказа)
ORDER BY дата;
```

### Рамки окна (Window Frame)

Определяют, какие строки относятся к текущему окну:

```sql
-- Скользящее среднее за 3 предыдущих и текущий период
SELECT 
    EXTRACT(MONTH FROM дата_заказа) AS месяц,
    SUM(общая_сумма) AS месячная_сумма,
    AVG(SUM(общая_сумма)) OVER (
        ORDER BY EXTRACT(MONTH FROM дата_заказа)
        ROWS BETWEEN 3 PRECEDING AND CURRENT ROW
    ) AS среднее_за_4_месяца
FROM заказы
GROUP BY EXTRACT(MONTH FROM дата_заказа)
ORDER BY месяц;
```

### Практические примеры из российской практики

#### Пример 1: Рейтинг клиентов внутри каждого города

```sql
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    SUM(з.общая_сумма) AS общая_сумма_заказов,
    RANK() OVER (
        PARTITION BY к.город 
        ORDER BY SUM(з.общая_сумма) DESC
    ) AS ранг_в_городе,
    PERCENT_RANK() OVER (
        PARTITION BY к.город 
        ORDER BY SUM(з.общая_сумма)
    ) AS процентиль
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.id, к.фамилия, к.имя, к.город
ORDER BY к.город, ранг_в_городе;
```

#### Пример 2: Сравнение с предыдущим периодом

```sql
WITH месячные_итоги AS (
    SELECT 
        EXTRACT(YEAR FROM дата_заказа) AS год,
        EXTRACT(MONTH FROM дата_заказа) AS месяц,
        SUM(общая_сумма) AS месячная_сумма,
        LAG(SUM(общая_сумма)) OVER (
            ORDER BY EXTRACT(YEAR FROM дата_заказа), EXTRACT(MONTH FROM дата_заказа)
        ) AS предыдущая_сумма
    FROM заказы
    GROUP BY 
        EXTRACT(YEAR FROM дата_заказа), 
        EXTRACT(MONTH FROM дата_заказа)
)
SELECT 
    год,
    месяц,
    месячная_сумма,
    предыдущая_сумма,
    месячная_сумма - COALESCE(предыдущая_сумма, 0) AS разница,
    ROUND(
        (месячная_сумма - COALESCE(предыдущая_сумма, 0)) * 100.0 / 
        NULLIF(предыдущая_сумма, 0), 
        2
    ) AS рост_в_процентах
FROM месячные_итоги
ORDER BY год, месяц;
```

#### Пример 3: Топ-товаров по категориям

```sql
WITH товары_с_рангом AS (
    SELECT 
        наименование,
        категория,
        цена,
        ROW_NUMBER() OVER (
            PARTITION BY категория 
            ORDER BY цена DESC
        ) AS цена_ранг,
        ROW_NUMBER() OVER (
            PARTITION BY категория 
            ORDER BY количество_на_складе ASC
        ) AS остаток_ранг
    FROM товары
    WHERE количество_на_складе > 0
)
SELECT 
    категория,
    MAX(CASE WHEN цена_ранг = 1 THEN наименование END) AS самый_дорогой_товар,
    MAX(CASE WHEN цена_ранг = 1 THEN цена END) AS его_цена,
    MAX(CASE WHEN остаток_ранг = 1 THEN наименование END) AS товар_с_мин_остатком,
    MAX(CASE WHEN остаток_ранг = 1 THEN количество_на_складе END) AS его_остаток
FROM товары_с_рангом
WHERE цена_ранг = 1 OR остаток_ранг = 1
GROUP BY категория;
```

### Практические советы

#### Совет 1: Разница между RANK() и ROW_NUMBER()

```sql
-- RANK(): присваивает одинаковый ранг одинаковым значениям, с пропусками
-- Если 3 товара имеют одинаковую высокую цену, они получат ранг 1, 1, 1, затем 4

-- ROW_NUMBER(): присваивает уникальные номера, даже при одинаковых значениях
-- Если 3 товара имеют одинаковую высокую цену, они получат номера 1, 2, 3
```

#### Совет 2: Использование подзапросов для фильтрации

Оконные функции нельзя использовать в `WHERE` напрямую, но можно в подзапросе:

```sql
-- Не работает:
-- SELECT * FROM заказы WHERE ROW_NUMBER() OVER (ORDER BY дата_заказа) <= 10;

-- Работает:
SELECT * FROM (
    SELECT *, ROW_NUMBER() OVER (ORDER BY дата_заказа) AS rn
    FROM заказы
) AS ranked
WHERE rn <= 10;
```

#### Совет 3: Производительность

Оконные функции могут быть ресурсоемкими на больших наборах данных. Используйте индексы на столбцах, используемых в `PARTITION BY` и `ORDER BY`.

### Часто допускаемые ошибки

#### Ошибка 1: Оконная функция без OVER

```sql
-- ОШИБКА
SELECT RANK(фамилия) FROM клиенты;

-- ПРАВИЛЬНО
SELECT RANK() OVER (ORDER BY фамилия) FROM клиенты;
```

#### Ошибка 2: Использование оконной функции в WHERE

```sql
-- ОШИБКА
SELECT * FROM заказы
WHERE ROW_NUMBER() OVER (ORDER BY дата_заказа) < 5;

-- ПРАВИЛЬНО
SELECT * FROM (
    SELECT *, ROW_NUMBER() OVER (ORDER BY дата_заказа) AS rn
    FROM заказы
) AS ranked
WHERE rn < 5;
```

#### Ошибка 3: Непонимание PARTITION BY

`PARTITION BY` создает отдельное "окно" для вычислений для каждой группы значений.

### Заключение главы

Оконные функции - мощный инструмент для анализа данных, позволяющий выполнять сложные вычисления без необходимости в сложных соединениях или подзапросах. Они особенно полезны для задач ранжирования, сравнения с предыдущими периодами, вычисления накопительных итогов и других аналитических задач. Понимание и правильное использование оконных функций значительно расширяет возможности SQL для анализа данных.
