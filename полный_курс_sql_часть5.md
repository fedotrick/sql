# Раздел 7: Условные выражения и аналитические функции (продолжение)

## Глава 57: Введение в условные выражения

### Введение

Условные выражения в SQL позволяют выполнять различные действия в зависимости от значений данных. Они являются мощным инструментом для трансформации данных, создания категорий, обработки NULL значений и реализации бизнес-логики прямо в запросах. Основные условные выражения в SQL - это CASE, COALESCE, NULLIF и CAST - предоставляют гибкие возможности для обработки данных на лету.

### Зачем нужны условные выражения?

Условные выражения важны по следующим причинам:

1. **Трансформация данных**: преобразование значений на основе условий
2. **Обработка NULL**: безопасная работа с пропущенными значениями
3. **Классификация**: создание категорий на основе значений
4. **Бизнес-логика**: реализация правил и условий в запросах
5. **Форматирование**: подготовка данных для отчетов

### Основные типы условных выражений

#### 1. CASE выражения

```sql
-- Простой CASE
SELECT 
    фамилия,
    имя,
    CASE пол
        WHEN 'М' THEN 'Мужской'
        WHEN 'Ж' THEN 'Женский'
        ELSE 'Не указан'
    END AS пол_человеческий
FROM клиенты;

-- Условный CASE
SELECT 
    фамилия,
    имя,
    CASE 
        WHEN возраст < 18 THEN 'Несовершеннолетний'
        WHEN возраст BETWEEN 18 AND 65 THEN 'Рабочий возраст'
        ELSE 'Пенсионер'
    END AS возрастная_категория
FROM (
    SELECT 
        фамилия, 
        имя, 
        EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения) AS возраст
    FROM клиенты
) AS клиенты_с_возрастом;
```

#### 2. COALESCE

```sql
-- Замена NULL значений
SELECT 
    фамилия,
    имя,
    COALESCE(отчество, 'Без отчества') AS отчество_или_заглушка
FROM клиенты;

-- Последовательная проверка нескольких значений
SELECT 
    email,
    COALESCE(альтернативный_email, резервный_email, 'Не указан') AS контактный_email
FROM клиенты;
```

#### 3. NULLIF

```sql
-- Возврат NULL если значения равны
SELECT 
    цена,
    NULLIF(цена, 0) AS цена_или_null_если_ноль  -- вернет NULL, если цена = 0
FROM товары;

-- Полезно для избежания деления на ноль
SELECT 
    продажи,
    план,
    CASE 
        WHEN NULLIF(план, 0) IS NOT NULL 
        THEN продажи / NULLIF(план, 0) * 100
        ELSE 0
    END AS выполнение_плана_в_процентах
FROM отчеты;
```

#### 4. CAST и преобразования типов

```sql
-- Преобразование типов
SELECT 
    цена,
    CAST(цена AS INTEGER) AS цена_целое,
    CAST(цена AS TEXT) AS цена_как_текст,
    ROUND(цена, 0)::INTEGER AS цена_округленная_до_целого
FROM товары;
```

### Практические примеры использования условных выражений

#### Пример 1: Сегментация клиентов

```sql
-- Классификация клиентов по объему покупок
SELECT 
    к.фамилия,
    к.имя,
    клиентская_статистика.общая_сумма,
    CASE 
        WHEN клиентская_статистика.общая_сумма > 100000 THEN 'Премиум'
        WHEN клиентская_статистика.общая_сумма > 50000 THEN 'Золотой'
        WHEN клиентская_статистика.общая_сумма > 10000 THEN 'Серебряный'
        ELSE 'Стандартный'
    END AS сегмент_клиента,
    CASE 
        WHEN клиентская_статистика.количество_заказов > 10 THEN 'Частый клиент'
        WHEN клиентская_статистика.количество_заказов > 5 THEN 'Регулярный'
        ELSE 'Новый'
    END AS категория_активности
FROM клиенты к
JOIN (
    SELECT 
        id_клиента,
        SUM(общая_сумма) AS общая_сумма,
        COUNT(*) AS количество_заказов
    FROM заказы
    GROUP BY id_клиента
) AS клиентская_статистика ON к.id = клиентская_статистика.id_клиента;
```

#### Пример 2: Обработка особых случаев

```sql
-- Обработка особых случаев в ценах товаров
SELECT 
    наименование,
    цена,
    CASE 
        WHEN цена = 0 THEN 'Бесплатно'
        WHEN цена IS NULL THEN 'Цена не указана'
        WHEN цена < 0 THEN 'Ошибка: отрицательная цена'
        WHEN цена > 100000 THEN 'Премиум-сегмент: ' || цена::TEXT
        ELSE цена::TEXT
    END AS цена_для_отчета,
    COALESCE(цена, 0) AS цена_для_расчетов
FROM товары;
```

#### Пример 3: Условная логика в агрегации

```sql
-- Условные агрегации
SELECT 
    город,
    COUNT(*) AS "Общее количество клиентов",
    COUNT(CASE WHEN пол = 'М' THEN 1 END) AS "Мужчины",
    COUNT(CASE WHEN пол = 'Ж' THEN 1 END) AS "Женщины",
    AVG(CASE WHEN возраст < 30 THEN возраст END) AS "Средний возраст молодежи",
    AVG(CASE WHEN возраст >= 30 THEN возраст END) AS "Средний возраст взрослых"
FROM (
    SELECT 
        *,
        EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения) AS возраст
    FROM клиенты
) AS клиенты_с_возрастом
GROUP BY город;
```

### Сравнение подходов

#### CASE против простых условий

```sql
-- CASE позволяет создавать сложные условия
SELECT 
    фамилия,
    имя,
    CASE 
        WHEN город = 'Москва' AND (SELECT SUM(общая_сумма) FROM заказы WHERE id_клиента = клиенты.id) > 100000 THEN 'VIP-клиент из Москвы'
        WHEN город = 'Санкт-Петербург' AND (SELECT COUNT(*) FROM заказы WHERE id_клиента = клиенты.id) > 5 THEN 'Активный клиент из Питера'
        ELSE 'Обычный клиент'
    END AS классификация
FROM клиенты;
```

### Вложенные условные выражения

```sql
-- Условные выражения могут быть вложенными
SELECT 
    наименование,
    цена,
    CASE 
        WHEN цена > 50000 THEN
            CASE 
                WHEN цена > 100000 THEN 'Супер-премиум'
                ELSE 'Премиум'
            END
        WHEN цена > 10000 THEN 'Средний сегмент'
        ELSE 'Бюджетный'
    END AS категория_по_цене
FROM товары;
```

### Практические советы по использованию условных выражений

#### 1. Читаемость кода

```sql
-- ХОРОШО: понятные имена столбцов результата
SELECT 
    фамилия,
    CASE 
        WHEN пол = 'М' THEN 'Мужской'
        WHEN пол = 'Ж' THEN 'Женский'
        ELSE 'Не указан'
    END AS гендер
FROM клиенты;

-- ПЛОХО: неинформативные имена
SELECT 
    фамилия,
    CASE WHEN пол = 'М' THEN 'Мужской' WHEN пол = 'Ж' THEN 'Женский' ELSE 'Не указан' END
FROM клиенты;
```

#### 2. Производительность

```sql
-- Для простых проверок часто лучше использовать WHERE
-- ВМЕСТО: SELECT *, CASE WHEN статус = 'активный' THEN 1 ELSE 0 END FROM таблица WHERE ...
-- ЛУЧШЕ: SELECT *, 1 AS активный FROM таблица WHERE статус = 'активный' UNION ALL SELECT *, 0 AS активный FROM таблица WHERE статус != 'активный'
```

#### 3. Обработка NULL

```sql
-- Всегда учитывайте возможность NULL значений
SELECT 
    COALESCE(имя, '') || ' ' || COALESCE(фамилия, '') AS полное_имя
FROM клиенты;

-- Но будьте осторожны с CASE и NULL
SELECT 
    CASE 
        WHEN столбец IS NULL THEN 'Значение отсутствует'  -- Правильно проверять на NULL
        WHEN столбец = 'значение' THEN 'Найдено значение'
        ELSE 'Другое значение'
    END AS результат
FROM таблица;
```

### Заключение главы

Условные выражения - мощный инструмент для трансформации и анализа данных в SQL. Они позволяют реализовать сложную бизнес-логику прямо в запросах, обрабатывать исключения и создавать динамические отчеты. Понимание и умелое использование условных выражений критично для написания гибких и эффективных SQL-запросов.

## Глава 58: CASE

### Введение

CASE - это мощный условный оператор в SQL, который позволяет выполнять различную логику в зависимости от значений данных. Он аналогичен операторам if-else в других языках программирования и является основным инструментом для условной обработки данных в SQL. CASE может использоваться в различных частях SQL-запроса: SELECT, WHERE, ORDER BY, HAVING и других.

### Два типа CASE выражений

#### 1. Простой CASE (Simple CASE)

Сравнивает выражение с фиксированными значениями:

```sql
-- Синтаксис простого CASE:
-- CASE выражение
--     WHEN значение1 THEN результат1
--     WHEN значение2 THEN результат2
--     ...
--     ELSE результат_по_умолчанию
-- END

SELECT 
    фамилия,
    имя,
    CASE пол
        WHEN 'М' THEN 'Мужской'
        WHEN 'Ж' THEN 'Женский'
        ELSE 'Не указан'
    END AS пол_для_отчета
FROM клиенты;
```

#### 2. Условный CASE (Searched CASE)

Проверяет логические выражения:

```sql
-- Синтаксис условного CASE:
-- CASE
--     WHEN условие1 THEN результат1
--     WHEN условие2 THEN результат2
--     ...
--     ELSE результат_по_умолчанию
-- END

SELECT 
    фамилия,
    имя,
    CASE 
        WHEN возраст < 18 THEN 'Несовершеннолетний'
        WHEN возраст BETWEEN 18 AND 65 THEN 'Рабочий возраст'
        WHEN возраст > 65 THEN 'Пенсионер'
        ELSE 'Возраст не указан'
    END AS возрастная_группа
FROM (
    SELECT 
        фамилия,
        имя,
        EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения) AS возраст
    FROM клиенты
) AS клиенты_с_возрастом;
```

### Примеры использования CASE

#### Пример 1: Классификация заказов

```sql
SELECT 
    з.id AS id_заказа,
    з.дата_заказа,
    з.общая_сумма,
    CASE 
        WHEN з.общая_сумма > 100000 THEN 'Высокобюджетный'
        WHEN з.общая_сумма > 50000 THEN 'Средний бюджет'
        WHEN з.общая_сумма > 10000 THEN 'Низкий бюджет'
        ELSE 'Микрозаказ'
    END AS категория_заказа,
    CASE з.статус
        WHEN 'новый' THEN 'В обработке'
        WHEN 'оплачен' THEN 'Ожидает доставки'
        WHEN 'в_доставке' THEN 'Доставляется'
        WHEN 'доставлен' THEN 'Завершен'
        WHEN 'отменен' THEN 'Отменен'
        ELSE 'Неизвестный статус'
    END AS статус_для_клиента
FROM заказы з
ORDER BY з.общая_сумма DESC
LIMIT 10;
```

#### Пример 2: Условная агрегация

```sql
-- Подсчет заказов по категориям
SELECT 
    к.город,
    COUNT(*) AS "Всего заказов",
    COUNT(CASE WHEN з.общая_сумма > 50000 THEN 1 END) AS "Высокобюджетные",
    COUNT(CASE WHEN з.общая_сумма BETWEEN 10000 AND 50000 THEN 1 END) AS "Средние",
    COUNT(CASE WHEN з.общая_сумма < 10000 THEN 1 END) AS "Низкобюджетные",
    ROUND(
        AVG(CASE WHEN з.общая_сумма > 50000 THEN з.общая_сумма END), 
        2
    ) AS "Средний чек высокобюджетных"
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
ORDER BY "Всего заказов" DESC;
```

#### Пример 3: Обработка значений с условиями

```sql
-- Сложная обработка в зависимости от нескольких факторов
SELECT 
    к.фамилия,
    к.имя,
    к.город,
    клиентская_статистика.общая_сумма,
    клиентская_статистика.количество_заказов,
    CASE 
        WHEN клиентская_статистика.общая_сумма > 200000 AND клиентская_статистика.количество_заказов > 5 
            THEN 'VIP-клиент'
        WHEN клиентская_статистика.общая_сумма > 100000 OR клиентская_статистика.количество_заказов > 10 
            THEN 'Премиум-клиент'
        WHEN клиентская_статистика.количество_заказов > 3 
            THEN 'Постоянный клиент'
        ELSE 'Новый клиент'
    END AS статус_клиента,
    CASE 
        WHEN к.город IN ('Москва', 'Санкт-Петербург') AND клиентская_статистика.общая_сумма > 150000 
            THEN 'Премиум-регион'
        WHEN к.город IN ('Москва', 'Санкт-Петербург') 
            THEN 'Регулярный-регион'
        ELSE 'Другой регион'
    END AS классификация_региона
FROM клиенты к
JOIN (
    SELECT 
        id_клиента,
        SUM(общая_сумма) AS общая_сумма,
        COUNT(*) AS количество_заказов,
        MAX(дата_заказа) AS последний_заказ
    FROM заказы
    GROUP BY id_клиента
) AS клиентская_статистика ON к.id = клиентская_статистика.id_клиента
ORDER BY клиентская_статистика.общая_сумма DESC
LIMIT 15;
```

### CASE в разных частях запроса

#### CASE в ORDER BY

```sql
-- Сортировка с учетом условной логики
SELECT 
    фамилия,
    имя,
    общая_сумма_заказов
FROM (
    SELECT 
        к.фамилия,
        к.имя,
        COALESCE((SELECT SUM(общая_сумма) FROM заказы WHERE id_клиента = к.id), 0) AS общая_сумма_заказов
    FROM клиенты к
) AS клиенты_с_суммой
ORDER BY 
    CASE 
        WHEN общая_сумма_заказов > 100000 THEN 1
        WHEN общая_сумма_заказов > 50000 THEN 2
        ELSE 3
    END,
    общая_сумма_заказов DESC;
```

#### CASE в WHERE

```sql
-- Условия в WHERE с использованием CASE
SELECT 
    фамилия,
    имя,
    пол,
    возраст
FROM (
    SELECT 
        фамилия,
        имя,
        пол,
        EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения) AS возраст
    FROM клиенты
) AS клиенты_с_возрастом
WHERE 
    CASE 
        WHEN пол = 'М' THEN возраст BETWEEN 18 AND 60
        WHEN пол = 'Ж' THEN возраст BETWEEN 18 AND 55
        ELSE возраст BETWEEN 18 AND 65
    END;
```

#### CASE в GROUP BY

```sql
-- Группировка с условной логикой
SELECT 
    CASE 
        WHEN возраст < 25 THEN 'Молодежь (до 25)'
        WHEN возраст BETWEEN 25 AND 40 THEN 'Молодые профессионалы'
        WHEN возраст BETWEEN 41 AND 60 THEN 'Опытные профессионалы'
        ELSE 'Зрелые специалисты'
    END AS возрастная_группа,
    COUNT(*) AS количество_клиентов,
    AVG(сумма_заказов) AS средняя_сумма_заказов
FROM (
    SELECT 
        к.id,
        EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM к.дата_рождения) AS возраст,
        COALESCE((SELECT SUM(общая_сумма) FROM заказы WHERE id_клиента = к.id), 0) AS сумма_заказов
    FROM клиенты к
) AS клиенты_с_анализом
GROUP BY 
    CASE 
        WHEN возраст < 25 THEN 'Молодежь (до 25)'
        WHEN возраст BETWEEN 25 AND 40 THEN 'Молодые профессионалы'
        WHEN возраст BETWEEN 41 AND 60 THEN 'Опытные профессионалы'
        ELSE 'Зрелые специалисты'
    END
ORDER BY количество_клиентов DESC;
```

### Вложенные CASE выражения

```sql
-- Сложная логика с вложенными CASE
SELECT
```

### CASE для вычислений

```sql
-- Условные вычисления
SELECT 
    фамилия,
    имя,
    клиентская_статистика.общая_сумма,
    CASE 
        WHEN клиентская_статистика.общая_сумма > 200000 THEN клиентская_статистика.общая_сумма * 0.15
        WHEN клиентская_статистика.общая_сумма > 100000 THEN клиентская_статистика.общая_сумма * 0.10
        WHEN клиентская_статистика.общая_сумма > 50000 THEN клиентская_статистика.общая_сумма * 0.05
        ELSE 0
    END AS бонус_к_заказу,
    клиентская_статистика.количество_заказов,
    CASE 
        WHEN клиентская_статистика.количество_заказов >= 10 THEN 10
        WHEN клиентская_статистика.количество_заказов >= 5 THEN 5
        ELSE 0
    END AS скидка_в_процентах
FROM клиенты к
JOIN (
    SELECT 
        id_клиента,
        SUM(общая_сумма) AS общая_сумма,
        COUNT(*) AS количество_заказов
    FROM заказы
    GROUP BY id_клиента
) AS клиентская_статистика ON к.id = клиентская_статистика.id_клиента
ORDER BY клиентская_статистика.общая_сумма DESC;
```

### Практические советы по использованию CASE

#### 1. Эффективность

```sql
-- Для простых условий иногда лучше использовать другие функции
-- ВМЕСТО: CASE WHEN поле IS NULL THEN значение ELSE поле END
-- ИСПОЛЬЗУЙТЕ: COALESCE(поле, значение)

-- ВМЕСТО: CASE WHEN поле = 'значение' THEN 1 ELSE 0 END в агрегациях
-- МОЖНО ИСПОЛЬЗОВАТЬ: SUM(CASE WHEN условие THEN 1 ELSE 0 END)
```

#### 2. Читаемость

```sql
-- Хорошо форматированный CASE
SELECT 
    фамилия,
    CASE 
        WHEN дата_регистрации < '2020-01-01' THEN 'Давний клиент'
        WHEN дата_регистрации < '2022-01-01' THEN 'Постоянный клиент'

-- Плохо: все в одну строку
```


#### Задание 6: Сложная классификация клиентов

**Сценарий:** Отдел маркетинга хочет комплексно оценить клиентов.

**Задача:** Классифицируйте клиентов по следующим критериям: если общая сумма заказов > 150000 И количество заказов > 5, то "VIP-клиент"; если общая сумма > 75000 ИЛИ количество заказов > 8, то "Премиум-клиент"; если количество заказов > 3, то "Постоянный клиент"; иначе "Новый клиент".

**Решение:**
```sql
SELECT 
    к.фамилия,
    к.имя,
    клиентская_статистика.общая_сумма,
    клиентская_статистика.количество_заказов,
    CASE 
        WHEN клиентская_статистика.общая_сумма > 150000 AND клиентская_статистика.количество_заказов > 5 THEN 'VIP-клиент'
        WHEN клиентская_статистика.общая_сумма > 75000 OR клиентская_статистика.количество_заказов > 8 THEN 'Премиум-клиент'
        WHEN клиентская_статистика.количество_заказов > 3 THEN 'Постоянный клиент'
        ELSE 'Новый клиент'
    END AS классификация_клиента
FROM клиенты к
JOIN (
    SELECT 
        id_клиента,
        SUM(общая_сумма) AS общая_сумма,
        COUNT(*) AS количество_заказов
    FROM заказы
    GROUP BY id_клиента
) AS клиентская_статистика ON к.id = клиентская_статистика.id_клиента
ORDER BY клиентская_статистика.общая_сумма DESC;
```

#### Задание 7: Условный расчет скидки

**Сценарий:** Компания хочет автоматически рассчитывать скидку для клиентов.

**Задача:** Рассчитайте скидку в рублях по следующим правилам: если общая сумма заказов > 200000, скидка 15%; если > 100000, скидка 10%; если > 50000, скидка 5%; иначе 0%. Также укажите процент скидки.

**Решение:**
```sql
SELECT 
    к.фамилия,
    к.имя,
    клиентская_статистика.общая_сумма,
    CASE 
        WHEN клиентская_статистика.общая_сумма > 200000 THEN клиентская_статистика.общая_сумма * 0.15
        WHEN клиентская_статистика.общая_сумма > 100000 THEN клиентская_статистика.общая_сумма * 0.10
        WHEN клиентская_статистика.общая_сумма > 50000 THEN клиентская_статистика.общая_сумма * 0.05
        ELSE 0
    END AS размер_скидки,
    CASE 
        WHEN клиентская_статистика.общая_сумма > 200000 THEN 15
        WHEN клиентская_статистика.общая_сумма > 100000 THEN 10
        WHEN клиентская_статистика.общая_сумма > 50000 THEN 5
        ELSE 0
```

**Задача:** Отсортируйте клиентов так, чтобы "VIP-клиенты" (с общей суммой > 150000) были первыми, затем "Премиум-клиенты" (сумма > 75000), затем остальные. Внутри каждой группы сортировка по общей сумме заказов в убывающем порядке.

**Решение:**

#### Задание 11: CASE в WHERE

**Сценарий:** Классификация заказов по сложным бизнес-правилам.

**Задача:** Классифицируйте заказы: "VIP-заказ" если сумма > 100000 и статус не "отменен"; "Срочный заказ" если сумма > 50000 и прошло менее 1 дня с даты заказа; "Обычный заказ" для остальных.

```sql
    id_клиента,
    дата_заказа,
    общая_сумма,
    статус,
    CASE 
        WHEN общая_сумма > 100000 AND статус != 'отменен' THEN 'VIP-заказ'
```

#### Задание 15: CASE с вычислениями

**Сценарий:** Расчет бонусов для клиентов по сложной системе.

**Задача:** Рассчитайте бонусы: если общая сумма > 200000 и количество заказов > 10, бонус = 5% от суммы; если сумма > 100000 и количество заказов > 5, бонус = 3% от суммы; если сумма > 50000, бонус = 1% от суммы; иначе бонус = 0.

**Решение:**
```sql
SELECT 
    к.фамилия,
    к.имя,
    клиентская_статистика.общая_сумма,
    клиентская_статистика.количество_заказов,
    CASE 
        WHEN клиентская_статистика.общая_сумма > 200000 AND клиентская_статистика.количество_заказов > 10 
            THEN клиентская_статистика.общая_сумма * 0.05
        WHEN клиентская_статистика.общая_сумма > 100000 AND клиентская_статистика.количество_заказов > 5 
            THEN клиентская_статистика.общая_сумма * 0.03
        WHEN клиентская_статистика.общая_сумма > 50000 
            THEN клиентская_статистика.общая_сумма * 0.01
        ELSE 0
    END AS бонус
FROM клиенты к
JOIN (
    SELECT 
        id_клиента,
        SUM(общая_сумма) AS общая_сумма,
        COUNT(*) AS количество_заказов
    FROM заказы
    GROUP BY id_клиента
) AS клиентская_статистика ON к.id = клиентская_статистика.id_клиента
ORDER BY бонус DESC;
```

## Глава 60: COALESCE

### Введение

COALESCE - это SQL-функция, которая возвращает первое ненулевое (не NULL) значение из списка выражений. Она является важным инструментом для обработки NULL-значений, позволяя заменить их альтернативными значениями. COALESCE особенно полезна при работе с несовершенными данными, формировании отчетов и подготовке данных для анализа.

### Базовый синтаксис

```sql
COALESCE(выражение1, выражение2, ..., выражениеN)
```

Функция возвращает первое значение, которое не равно NULL. Если все выражения равны NULL, то COALESCE возвращает NULL.

### Простые примеры использования COALESCE

#### Пример 1: Замена NULL значений

```sql
-- Замена NULL значений в поле отчество
SELECT 
    фамилия,
    имя,
    COALESCE(отчество, 'Без отчества') AS отчество_или_заглушка
FROM клиенты;

-- Замена NULL в контактной информации
SELECT 
    фамилия,
    COALESCE(телефон, 'Нет телефона') AS контактный_телефон
FROM клиенты;
```

#### Пример 2: Последовательная проверка нескольких полей

```sql
-- Использование нескольких полей: сначала пробуем альтернативный email, потом резервный
SELECT 
    фамилия,
    имя,
    COALESCE(email, альтернативный_email, резервный_email, 'Контакт не указан') AS основной_контакт
FROM клиенты;
```

### Практические примеры использования COALESCE

#### Пример 1: Обработка адресов

```sql
-- Создание полного адреса с обработкой возможных NULL значений
SELECT 
    фамилия,
    имя,
    COALESCE(
        CONCAT(улица, ', д. ', номер_дома, ', кв. ', номер_квартиры),
        CONCAT(улица, ', д. ', номер_дома),
        улица,
        'Адрес не указан'
    ) AS полный_адрес
FROM клиенты
WHERE улица IS NOT NULL OR номер_дома IS NOT NULL;
```

#### Пример 2: Формирование ФИО

```sql
-- Безопасное формирование полного имени
SELECT 
    COALESCE(фамилия, '') || 
    CASE WHEN фамилия IS NOT NULL AND имя IS NOT NULL THEN ' ' ELSE '' END ||
    COALESCE(имя, '') ||
    CASE 
        WHEN (фамилия IS NOT NULL OR имя IS NOT NULL) AND отчество IS NOT NULL 
        THEN ' ' || COALESCE(отчество, '') 
        ELSE COALESCE(отчество, '') 
    END AS полное_имя
FROM клиенты;

-- Более простой вариант
SELECT 
    CONCAT(
        COALESCE(фамилия, ''),
        CASE WHEN фамилия IS NOT NULL AND (имя IS NOT NULL OR отчество IS NOT NULL) THEN ' ' ELSE '' END,
        COALESCE(имя, ''),
        CASE WHEN имя IS NOT NULL AND отчество IS NOT NULL THEN ' ' ELSE '' END,
        COALESCE(отчество, '')
    ) AS полное_имя
FROM клиенты;
```

#### Пример 3: Обработка числовых данных

```sql
-- Безопасное использование числовых значений
SELECT 
    наименование,
    цена,
    COALESCE(цена, 0) AS цена_для_расчетов,
    количество_на_складе,
    COALESCE(количество_на_складе, 0) AS кол_для_операций,
    -- Вычисления с безопасными значениями
    COALESCE(цена, 0) * COALESCE(количество_на_складе, 0) AS возможная_выручка
FROM товары;
```

#### Пример 4: Обработка дат

```sql
-- Работа с датами: использование последней доступной даты
SELECT 
    фамилия,
    имя,
    дата_регистрации,
    дата_последнего_заказа,
    дата_последнего_контакта,
    COALESCE(дата_последнего_контакта, дата_последнего_заказа, дата_регистрации) AS дата_последней_активности
FROM (
    SELECT 
        фамилия,
        имя,
        дата_регистрации,
        (SELECT MAX(дата_заказа) FROM заказы WHERE id_клиента = клиенты.id) AS дата_последнего_заказа,
        дата_последнего_контакта
    FROM клиенты
) AS клиенты_с_датами;
```

### COALESCE в агрегациях и вычислениях

#### Пример 5: Безопасные агрегации

```sql
-- Безопасная агрегация с обработкой NULL
SELECT 
    к.город,
    COUNT(*) AS "Всего клиентов",
    SUM(COALESCE(заказы_стат.общая_сумма, 0)) AS "Общая сумма заказов",
    AVG(COALESCE(заказы_стат.общая_сумма, 0)) AS "Средняя сумма (с 0 для клиентов без заказов)"
FROM клиенты к
LEFT JOIN (
    SELECT 
        id_клиента,
        SUM(общая_сумма) AS общая_сумма
    FROM заказы
    GROUP BY id_клиента
) AS заказы_стат ON к.id = заказы_стат.id_клиента
GROUP BY к.город
ORDER BY "Общая сумма заказов" DESC;
```

#### Пример 6: Условные вычисления

```sql
-- Безопасные вычисления в условиях
SELECT 
    наименование,
    цена,
    себестоимость,
    COALESCE(себестоимость, цена * 0.7) AS себестоимость_или_оценка,
    цена - COALESCE(себестоимость, цена * 0.7) AS прибыль,
    CASE 
        WHEN COALESCE(себестоимость, цена * 0.7) > 0 
        THEN (цена - COALESCE(себестоимость, цена * 0.7)) / COALESCE(себестоимость, цена * 0.7) * 100
        ELSE 0
    END AS рентабельность_в_процентах
FROM товары
WHERE цена IS NOT NULL;
```

### COALESCE в разных контекстах

#### В ORDER BY

```sql
-- Сортировка с учетом NULL значений
SELECT 
    фамилия,
    имя,
    отчество
FROM клиенты
ORDER BY 
    фамилия,
    имя,
    COALESCE(отчество, '');  -- Помещает строки с NULL в отчество в начало/конец
```

#### В GROUP BY

```sql
-- Группировка с обработкой NULL
SELECT 
    COALESCE(город, 'Не указан') AS город_группировки,
    COUNT(*) AS количество_клиентов,
    AVG(возраст) AS средний_возраст
FROM (
    SELECT 
        *,
        EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения) AS возраст
    FROM клиенты
) AS клиенты_с_возрастом
GROUP BY COALESCE(город, 'Не указан')
ORDER BY количество_клиентов DESC;
```

### Сравнение COALESCE с другими подходами

#### COALESCE vs ISNULL (SQL Server)

```sql
-- В PostgreSQL: COALESCE
SELECT COALESCE(поле, 'значение_по_умолчанию') FROM таблица;

-- В SQL Server: ISNULL (работает только с двумя параметрами)
-- SELECT ISNULL(поле, 'значение_по_умолчанию') FROM таблица;
```

#### COALESCE vs CASE

```sql
-- COALESCE для простой замены NULL
SELECT COALESCE(отчество, 'Без отчества') FROM клиенты;

-- Эквивалентный CASE (более громоздкий для простой проверки NULL)
SELECT 
    CASE 
        WHEN отчество IS NULL THEN 'Без отчества'
        ELSE отчество
    END
FROM клиенты;
```

#### COALESCE vs NVL (Oracle)

```sql
-- В PostgreSQL: COALESCE
SELECT COALESCE(поле, 'значение') FROM таблица;

-- В Oracle: NVL (также только для двух значений)
-- SELECT NVL(поле, 'значение') FROM таблица;
```

```sql
CREATE TEMPORARY TABLE товары_с_названиями (
```

### Практические советы по использованию COALESCE

#### 1. Используйте COALESCE для безопасных вычислений

```sql
-- ХОРОШО: безопасные вычисления
SELECT 
    цена,
    количество,
    COALESCE(цена, 0) * COALESCE(количество, 0) AS общая_сумма
FROM товары;

-- ИЗБЕГАЙТЕ: потенциальные ошибки с NULL
-- SELECT цена * количество FROM товары; -- результат будет NULL, если одно из значений NULL
```

#### 2. COALESCE и производительность

```sql
-- COALESCE вычисляет выражения слева направо и останавливается на первом не-NULL
-- Это эффективно, но убедитесь, что выражения не слишком сложные

-- ХОРОШО: простые значения
SELECT COALESCE(поле1, поле2, 'значение_по_умолчанию') FROM таблица;

-- ОСТОРОЖНО: сложные подзапросы могут быть неэффективными
-- SELECT COALESCE(поле1, (SELECT значение FROM другая_таблица WHERE условие), 'умолчание') FROM таблица;
```

#### 3. COALESCE в условных выражениях

```sql
-- COALESCE может использоваться внутри других функций
SELECT 
    фамилия,
    CASE 
        WHEN COALESCE(скидка, 0) > 10 THEN 'Высокая скидка'
        WHEN COALESCE(скидка, 0) > 5 THEN 'Средняя скидка'
        ELSE 'Маленькая скидка'
    END AS категория_скидки
FROM клиенты;
```

#### 4. Обработка специфических "пустых" значений

```sql
-- Иногда нужно обрабатывать не только NULL, но и пустые строки
SELECT 
    фамилия,
    имя,
    CASE 
        WHEN TRIM(COALESCE(отчество, '')) = '' THEN 'Без отчества'
        ELSE отчество
    END AS отчество_для_отчета
FROM клиенты;
```

### Заключение главы

COALESCE - мощный инструмент для безопасной обработки NULL значений в SQL. Он особенно полезен при:

1. Замене NULL значений на значения по умолчанию
2. Последовательной проверке альтернативных значений
3. Безопасных вычислениях с потенциальными NULL
4. Форматировании данных для отчетов
5. Работе с несовершенными или частично заполненными данными

Понимание и эффективное использование COALESCE позволяет писать более надежные и читаемые SQL-запросы, особенно при работе с реальными данными, которые часто содержат пропущенные значения.

## Глава 61: CAST

### Введение

CAST - это SQL-операция, которая позволяет преобразовывать значения из одного типа данных в другой. Это важнейший инструмент при работе с базами данных, особенно когда нужно выполнить операции с данными разных типов, экспортировать данные в определённом формате или обеспечить совместимость между различными системами. CAST позволяет явно указывать, как следует интерпретировать данные, что делает запросы более предсказуемыми и безопасными.

### Базовый синтаксис CAST

```sql
-- Стандартный синтаксис CAST:
CAST(выражение AS тип_данных)

-- Альтернативный синтаксис (PostgreSQL):
выражение::тип_данных
```

### Простые примеры использования CAST

#### Пример 1: Преобразование чисел в строки

```sql
-- Преобразование числа в строку
SELECT 
    цена,
    CAST(цена AS TEXT) AS цена_как_строка,
    цена::TEXT AS цена_как_строка_альтернативно
FROM товары
LIMIT 5;

-- Преобразование в строку с форматированием
SELECT 
    id,
    наименование,
    'Товар #' || CAST(id AS TEXT) || ': ' || наименование AS форматированный_текст
FROM товары
LIMIT 5;
```

#### Пример 2: Преобразование строк в числа

```sql
-- Преобразование строки в число (осторожно: может вызвать ошибку при недопустимом формате)
SELECT 
    строка_с_числом,
    CAST(строка_с_числом AS INTEGER) AS число
FROM (
    VALUES 
        ('123'),
        ('456'),
        ('789')
) AS строки_с_числами(строка_с_числом);

-- Безопасное преобразование с обработкой ошибок
SELECT 
    строка_потенцильное_число,
    CASE 
        WHEN строка_потенцильное_число ~ '^[0-9]+$' THEN CAST(строка_потенцильное_число AS INTEGER)
        ELSE NULL
    END AS безопасное_число
FROM (
    VALUES 
        ('123'),
        ('456abc'),
        ('789')
) AS данные(строка_потенцильное_число);
```

#### Пример 3: Преобразование дат

```sql
-- Преобразование строки в дату
SELECT 
    строка_с_датой,
    CAST(строка_с_датой AS DATE) AS дата
FROM (
    VALUES 
        ('2023-01-15'),
        ('2023-02-20'),
        ('2023-03-10')
) AS строки_с_датами(строка_с_датой);

-- Преобразование даты в строку в определенном формате
SELECT 
    дата_заказа,
    CAST(дата_заказа AS TEXT) AS дата_как_строка,
    дата_заказа::TEXT AS дата_как_строка_альтернативно
FROM заказы
LIMIT 5;
```

### Практические примеры использования CAST

#### Пример 1: Форматирование для отчетов

```sql
-- Создание форматированных строк для отчетов
SELECT 
    'Заказ #' || CAST(id AS TEXT) AS номер_заказа,
    CAST(дата_заказа AS TEXT) AS дата_заказа_строка,
    CAST(общая_сумма AS TEXT) AS сумма_строка,
    '₽ ' || CAST(общая_сумма AS TEXT) AS сумма_с_валютой
FROM заказы
LIMIT 5;
```

#### Пример 2: Выравнивание данных разных типов

```sql
-- Преобразование различных типов данных к одному для объединения
SELECT 
    'товар' AS тип_записи,
    CAST(id AS TEXT) AS идентификатор,
    наименование AS имя
FROM товары
UNION ALL
SELECT 
    'клиент' AS тип_записи,
    CAST(id AS TEXT) AS идентификатор,
    фамилия || ' ' || имя AS имя
FROM клиенты
LIMIT 10;
```

#### Пример 3: Преобразование для вычислений

```sql
-- Преобразование для выполнения арифметических операций
-- Предположим, у нас есть строковые значения, которые на самом деле числа

-- Создадим пример с тестовыми данными
WITH строки_с_ценами AS (
    SELECT '10000.50' AS строка_цена
    UNION ALL
    SELECT '25000.75'
    UNION ALL
    SELECT '5000.00'
)
SELECT 
    строка_цена,
    CAST(строка_цена AS NUMERIC(10,2)) AS числовая_цена,
    CAST(строка_цена AS NUMERIC(10,2)) * 1.2 AS цена_с_наценкой_20
FROM строки_с_ценами;
```

#### Пример 4: Работа с финансовыми данными

```sql
-- Преобразование для финансовых расчетов
SELECT 
    id,
    общая_сумма,
    CAST(общая_сумма AS INTEGER) AS сумма_без_копеек,
    ROUND(.Cast(общая_сумма AS NUMERIC), -2) AS сумма_округленная_до_сотен,
    CAST(общая_сумма * 0.2 AS NUMERIC(10,2)) AS сумма_ндс,
    CAST(общая_сумма * 1.2 AS NUMERIC(10,2)) AS сумма_с_ндс
FROM заказы
WHERE общая_сумма IS NOT NULL
LIMIT 5;
```

### CAST в разных контекстах

#### В операциях сравнения

```sql
-- CAST для корректного сравнения данных разных типов
SELECT 
    фамилия,
    номер_телефона
FROM клиенты
WHERE CAST(номер_телефона AS TEXT) LIKE '%123%';
```

#### В агрегациях

```sql
-- CAST в агрегационных функциях
SELECT 
    COUNT(*) AS общее_количество,
    COUNT(CAST(дата_регистрации AS TEXT)) AS с_указанной_датой,
    AVG(CAST(
        EXTRACT(YEAR FROM CURRENT_DATE) - EXTRACT(YEAR FROM дата_рождения) 
        AS REAL
    )) AS средний_возраст
FROM клиенты
WHERE дата_рождения IS NOT NULL;
```

#### В GROUP BY

```sql
-- CAST в GROUP BY для агрегации по частям даты
SELECT 
    CAST(дата_заказа AS TEXT) AS дата_в_виде_строки,
    COUNT(*) AS количество_заказов,
    SUM(общая_сумма) AS общая_сумма
FROM заказы
GROUP BY CAST(дата_заказа AS TEXT)
ORDER BY дата_в_виде_строки DESC
LIMIT 10;
```

### Безопасное использование CAST

#### Обработка ошибок при преобразовании

```sql
-- PostgreSQL не позволяет безопасно обрабатывать ошибки CAST в SQL,
-- но можно использовать CASE для простых проверок
SELECT 
    потенциальная_дата,
    CASE 
        WHEN потенциальная_дата ~ '^\d{4}-\d{2}-\d{2}$' THEN 
            CAST(потенциальная_дата AS DATE)
        ELSE NULL
    END AS безопасная_дата
FROM (
    VALUES 
        ('2023-01-15'),
        ('неправильная_дата'),
        ('2023-02-30')  -- недопустимая дата
) AS потенциальные_даты(потенциальная_дата);
```

#### Проверка на возможность преобразования

```sql
-- Для чисел можно проверить формат регулярным выражением
SELECT 
    потенциальное_число,
    CASE 
        WHEN потенциальное_число ~ '^[-+]?[0-9]*\.?[0-9]+$' THEN 
            CAST(потенциальное_число AS NUMERIC)
        ELSE NULL
    END AS безопасное_число
FROM (
    VALUES 
        ('123.45'),
        ('456'),
        ('abc'),
        ('123.45.67')  -- недопустимый формат
) AS потенциальные_числа(потенциальное_число);
```

### CAST и производительность

#### Индексирование с CAST

```sql
-- ХОРОШО: SELECT * FROM заказы WHERE дата_заказа = '2023-01-15'::DATE;
```

### Практические советы по использованию CAST

#### 1. Проверяйте возможность преобразования

```sql
-- Всегда убедитесь, что данные могут быть корректно преобразованы
-- ПЛОХО: SELECT CAST('abc' AS INTEGER); -- вызовет ошибку
-- ХОРОШО: использовать проверки или обработку ошибок (в приложении)
```

#### 2. Используйте подходящие типы данных

```sql
-- Не преобразуйте в тип с меньшей точностью без необходимости
-- ПЛОХО: CAST(123.456 AS INTEGER) -- потеря данных
-- ХОРОШО: CAST(123.456 AS NUMERIC(10,2)) -- сохранение точности
```

#### 3. Учитывайте локаль региона

```sql
-- При преобразовании дат и чисел учитывайте локализацию

-- Лучше использовать стандартный формат ISO: '2023-02-01'
```

#### 4. CAST vs оператор ::

```sql
-- В PostgreSQL оба варианта работают, но для переносимости лучше использовать CAST
-- CAST(поле AS тип) - стандарт SQL
-- поле::тип - PostgreSQL-специфичный синтаксис
```

### Заключение главы

CAST - важный инструмент для преобразования данных между различными типами. Он особенно полезен при:

1. Обработке данных из внешних источников
2. Форматировании данных для отчетов
3. Интеграции различных систем
4. Выполнении арифметических операций с данными разных типов
5. Подготовке данных для экспорта

При использовании CAST важно помнить о возможности ошибок преобразования и необходимости проверки данных. Правильное использование CAST делает SQL-запросы более гибкими и способными работать с разными источниками данных.

## Глава 62: NULLIF

### Введение

NULLIF - это SQL-функция, которая возвращает NULL, если два выражения равны между собой, и первое выражение, если они не равны. Функция NULLIF особенно полезна для избежания деления на ноль, обработки специальных значений и создания условных NULL в данных. Это мощный инструмент для очистки данных и безопасных вычислений.

### Базовый синтаксис

```sql
NULLIF(выражение1, выражение2)
```

Если `выражение1 = выражение2`, то результат - NULL.  
В противном случае результат - `выражение1`.

### Простые примеры использования NULLIF

#### Пример 1: Основное использование

```sql
-- Основная логика работы NULLIF
SELECT 
    значение1,
    значение2,
    NULLIF(значение1, значение2) AS результат
FROM (
    VALUES 
        (10, 5),    -- 10, т.к. 10 != 5
        (10, 10),   -- NULL, т.к. 10 = 10
        (20, 15),   -- 20, т.к. 20 != 15
        (NULL, 5),  -- NULL, т.к. NULL != 5, но первое значение NULL
        ('test', 'test'),  -- NULL, т.к. 'test' = 'test'
        ('test', 'other')  -- 'test', т.к. 'test' != 'other'
) AS данные(значение1, значение2);
```

#### Пример 2: Избежание деления на ноль

```sql
-- Классическое использование NULLIF для избежания деления на ноль
SELECT 
    числитель,
    знаменатель,
    знаменатель_с_нулем,
    CASE 
        WHEN знаменатель = 0 THEN NULL
        ELSE числитель / знаменатель
    END AS результат_без_nullif,
    CASE 
        WHEN NULLIF(знаменатель, 0) IS NOT NULL 
        THEN числитель / NULLIF(знаменатель, 0)
        ELSE NULL
    END AS результат_с_nullif,
    -- Или в более компактной форме:
    числитель / NULLIF(знаменатель, 0) AS результат_оптимальный
FROM (
    VALUES 
        (100, 5),
        (200, 0),
        (300, 10),
        (400, 0)
) AS примеры(числитель, знаменатель, знаменатель_с_нулем);
```

### Практические примеры использования NULLIF

#### Пример 1: Обработка специальных значений

```sql
-- Предположим, что -1 используется как "неизвестное значение" для возраста
SELECT 
    фамилия,
    возраст_сырое,

        WHEN NULLIF(возраст_сырое, -1) IS NULL THEN 'Возраст не указан'
        ELSE 'Возраст: ' || NULLIF(возраст_сырое, -1)::TEXT
    END AS возраст_для_отчета
FROM (
    VALUES 
        ('Иванов', 25),
        ('Петров', 30),
        ('Сидоров', -1),  -- специальное значение для "неизвестно"
        ('Козлова', 28)

```

#### Пример 2: Очистка данных от "заглушек"

```sql
-- Удаление специальных "заглушечных" значений
SELECT 
    email_сырой,
    NULLIF(email_сырой, 'not_specified') AS email_корректный,
    NULLIF(email_сырой, 'no_email') AS email_альтернативный,
    -- Комбинация с COALESCE для полной очистки
    COALESCE(
        NULLIF(email_сырой, 'not_specified'),
        NULLIF(email_сырой, 'no_email'),
        NULLIF(email_сырой, 'unknown'),
        'Контакт не указан'
    ) AS email_окончательный
FROM (
    VALUES 
        ('ivanov@example.com'),
        ('not_specified'),
        ('no_email'),
        ('petrov@example.com'),
        ('unknown')
) AS emails(email_сырой);
```

#### Пример 3: Безопасное вычисление процентов

```sql
-- Вычисление процентного соотношения с безопасностью от деления на ноль
SELECT 
    регион,
    продажи,
    план,
    CASE 
        WHEN план = 0 THEN NULL  -- или 0, в зависимости от бизнес-логики
        ELSE (продажи * 100.0 / план)
    END AS выполнение_плана_вручную,
    (продажи * 100.0) / NULLIF(план, 0) AS выполнение_плана_с_nullif,
    CASE 
        WHEN NULLIF(план, 0) IS NULL THEN 'Нет плана'
        WHEN (продажи * 100.0) / NULLIF(план, 0) >= 100 THEN 'План превышен'
        WHEN (продажи * 100.0) / NULLIF(план, 0) >= 80 THEN 'План выполнен'
        ELSE 'План не выполнен'
    END AS оценка_выполнения
FROM (
    VALUES 
        ('Москва', 120000, 100000),
        ('СПб', 80000, 100000),
        ('Новосибирск', 95000, 0),  -- проблемный случай - деление на 0
        ('Екатеринбург', 0, 50000)
) AS отчеты(регион, продажи, план);
```

```sql

    категория,
    доход,
    расход,
    CASE 
        WHEN NULLIF(расход, 0) IS NOT NULL 
        THEN доход / NULLIF(расход, 0)
        ELSE NULL

        WHEN доход > NULLIF(расход, 0) THEN 'Прибыль'
        WHEN доход = NULLIF(расход, 0) THEN 'Баланс'
```

### Связь NULLIF с другими функциями

```sql
-- Сложная логика с использованием NULLIF внутри CASE
```

#### Пример 6: Обработка значений по умолчанию

```sql
-- Замена значений по умолчанию на NULL
SELECT 
    цена,
```

```sql
-- Очистка строковых данных от заглушек
SELECT
```

### NULLIF в различных контекстах

#### В ORDER BY

```sql
-- Сортировка с учетом NULL значений, созданных через NULLIF
SELECT 
    фамилия,
    рейтинг
FROM (
    VALUES 
        ('Иванов', 5),
        ('Петров', 0),  -- 0 может означать "нет рейтинга"

        ('Козлов', 0)

    фамилия;
```

#### В WHERE

```sql
-- Использование NULLIF в условиях WHERE

    параметр,

        ('длина', -1)  -- -1 как "не применимо"
```

```sql
    FROM (
        VALUES
```


### Заключение главы

NULLIF - мощный инструмент для обработки специальных значений и безопасных вычислений в SQL. Он особенно полезен при:

1. Избежании деления на ноль
2. Очистке данных от специальных значений-заглушек
3. Создании условных NULL значений
4. Подготовке данных для анализа
5. Обработке нестандартных значений в данных

Понимание и эффективное использование NULLIF позволяет писать более надежные и безопасные SQL-запросы, особенно при работе с реальными данными, которые часто содержат специфические значения, обозначающие "неизвестно", "неприменимо" или другие особые случаи.

## Глава 63: Представления (Views)

### Введение

Представление (View) - это виртуальная таблица, результат выборки которой определяется запросом. Представление не хранит данные физически, а предоставляет удобный интерфейс для доступа к данным, которые могут быть получены из одной или нескольких таблиц. Представления позволяют упростить сложные запросы, обеспечить безопасность данных и стандартизировать доступ к информации.

### Базовый синтаксис CREATE VIEW

```sql
CREATE VIEW имя_представления AS
SELECT столбцы
FROM таблицы
WHERE условия;
```

### Простые примеры представлений

#### Пример 1: Простое представление

```sql
-- Создание простого представления с данными клиентов
CREATE VIEW клиенты_только_активные AS
SELECT 
    id,
    фамилия,
    имя,
    email,
    город,
    дата_регистрации
FROM клиенты
WHERE активен = TRUE;

-- Использование представления
SELECT * FROM клиенты_только_активные;
```

#### Пример 2: Представление с JOIN

```sql
-- Представление для получения информации о клиентах и их заказах
CREATE VIEW клиенты_с_заказами AS
SELECT 
    к.id AS id_клиента,
    к.фамилия,
    к.имя,
    к.город,
    з.id AS id_заказа,
    з.дата_заказа,
    з.общая_сумма,
    з.статус
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
WHERE к.активен = TRUE;
```

### Материализованные представления

Материализованные представления (Materialized Views) физически хранят результаты запроса и должны быть обновлены при изменении исходных данных.

```sql
-- Создание материализованного представления
CREATE MATERIALIZED VIEW аналитика_по_городам AS
SELECT 
    к.город,
    COUNT(DISTINCT к.id) AS количество_клиентов,
    COUNT(з.id) AS количество_заказов,
    SUM(з.общая_сумма) AS общая_сумма,
    AVG(з.общая_сумма) AS средний_чек,
    MAX(з.дата_заказа) AS последний_заказ
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город
ORDER BY общая_сумма DESC;

-- Использование материализованного представления
SELECT * FROM аналитика_по_городам;

-- Обновление материализованного представления
REFRESH MATERIALIZED VIEW аналитика_по_городам;

-- Обновление с поддержанием данных без блокировки
REFRESH MATERIALIZED VIEW аналитика_по_городам WITH DATA;
```

### Преимущества и недостатки представлений

#### Преимущества:

1. **Упрощение запросов**: сложные JOIN и вычисления скрыты за простым интерфейсом
2. **Безопасность**: можно ограничить доступ к определенным полям или строкам
3. **Повторное использование**: один раз созданное представление может использоваться многократно
4. **Абстракция**: изменение структуры базы не влияет на приложения, использующие представления
5. **Стандартизация**: единый подход к доступу к определенным данным

#### Недостатки:

1. **Производительность**: каждый вызов представления исполняет базовый запрос
2. **Сложности отладки**: труднее отлаживать запросы через представления
3. **Ограничения обновления**: не все представления поддерживают операции INSERT/UPDATE/DELETE
4. **Зависимости**: изменения в базовых таблицах могут повлиять на представления

## Глава 64: Индексы и оптимизация запросов

### Введение

Индексы - это структуры данных, которые ускоряют поиск и сортировку данных в таблицах. Правильное использование индексов может значительно улучшить производительность запросов, особенно при работе с большими объемами данных. В то же время неправильное использование индексов может замедлить работу базы данных из-за дополнительных затрат на поддержание индексов при вставке, обновлении и удалении данных.

### Базовый синтаксис CREATE INDEX

```sql
-- Простой индекс
CREATE INDEX имя_индекса ON имя_таблицы (столбец);

-- Индекс с различными опциями
CREATE INDEX имя_индекса ON имя_таблицы (столбец) USING метод [WITH (параметры)] [WHERE условие];
```

### Типы индексов в PostgreSQL

#### 1. B-tree индексы (по умолчанию)

B-tree индексы подходят для большинства случаев: равенства, сравнений, сортировки.

```sql
-- Создание B-tree индекса (по умолчанию)
CREATE INDEX idx_клиенты_email ON клиенты (email);

-- Индекс с сортировкой
CREATE INDEX idx_заказы_дата_сорт ON заказы (дата_заказа DESC);

-- Составной индекс
CREATE INDEX idx_заказы_клиент_дата ON заказы (id_клиента, дата_заказа);
```

#### 2. Hash индексы

Подходят только для точного совпадения (оператор =).

```sql
-- Hash индекс (для точного поиска)
CREATE INDEX idx_клиенты_хеш_email ON клиенты USING hash (email);
```

#### 3. GiST индексы

Поддерживают сложные типы данных, включая геометрические и текстовые данные.

```sql
-- GiST индекс для геометрических данных (если есть)
-- CREATE INDEX idx_гео_точки ON таблица USING gist (точка);

-- GiST для полнотекстового поиска
CREATE INDEX idx_товары_поиск ON товары USING gist (to_tsvector('russian', описание));
```

#### 4. GIN индексы

Хороши для массивов, JSON и полнотекстового поиска.

```sql
-- GIN индекс для массивов
CREATE INDEX idx_товары_теги ON товары USING gin (теги);

-- GIN индекс для JSONB
CREATE INDEX idx_клиенты_профиль ON клиенты USING gin (профиль);

-- GIN для полнотекстового поиска
CREATE INDEX idx_товары_поиск_gin ON товары USING gin (to_tsvector('russian', наименование));
```

### Создание и использование индексов

#### Пример 1: Основные индексы

```sql
-- Индекс на часто запрашиваемом столбце
CREATE INDEX idx_клиенты_email ON клиенты (email);

-- Индекс на столбце, часто используемом в WHERE

```

#### Пример 2: Специфические индексы

```sql

WHERE активен = TRUE;

-- Уникальный индекс
```

### Практические стратегии оптимизации

#### Стратегия 1: Оптимизация общих запросов

```sql
-- Найти самые частые запросы и создать соответствующие индексы
-- Пример частого запроса:
SELECT к.фамилия, к.имя, COUNT(з.id), AVG(з.общая_сумма)
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
WHERE к.город = 'Москва' AND з.статус = 'доставлен'
GROUP BY к.id, к.фамилия, к.имя;

-- Соответствующие индексы:
CREATE INDEX idx_клиенты_город ON клиенты (город);
CREATE INDEX idx_заказы_статус ON заказы (статус);
CREATE INDEX idx_заказы_клиент_статус ON заказы (id_клиента, статус);
```

#### Стратегия 2: Составные индексы

```sql
-- Правильный порядок столбцов в составном индексе
-- Для запроса: WHERE столбец1 = ? AND столбец2 = ? AND столбец3 > ?
-- Правильный порядок: (столбец1, столбец2, столбец3)

CREATE INDEX idx_заказы_оптимизация ON заказы (id_клиента, статус, дата_заказа);

-- Этот индекс будет эффективен для следующих запросов:
-- WHERE id_клиента = ? AND статус = ? (использует 2 первых столбца)
-- WHERE id_клиента = ? AND статус = ? AND дата_заказа > ? (использует все 3 столбца)
-- Но НЕ эффективен для: WHERE статус = ? (не использует первый столбец)
```

#### Стратегия 3: Частичные индексы

```sql
-- Частичные индексы для часто используемых подмножеств данных
CREATE INDEX idx_активные_заказы ON заказы (дата_заказа DESC) 
WHERE статус IN ('новый', 'оплачен', 'в_доставке');

-- Используется для запросов типа:
SELECT * FROM заказы 
WHERE статус IN ('новый', 'оплачен', 'в_доставке')
ORDER BY дата_заказа DESC;
```

### Управление индексами

#### Просмотр существующих индексов

```sql
-- Просмотр всех индексов в базе
SELECT 
    indexname,
    tablename,
    indexdef
FROM pg_indexes
WHERE schemaname = 'public'
ORDER BY tablename, indexname;

-- Подробная информация об индексах
SELECT 
    schemaname,
    tablename,
    indexname,
    idx_scan,      -- количество использований
    idx_tup_read,  -- количество прочитанных кортежей
    idx_tup_fetch  -- количество извлеченных кортежей
FROM pg_stat_user_indexes
ORDER BY idx_scan DESC;
```

#### Удаление неиспользуемых индексов

```sql
-- Найти неиспользуемые индексы (те, которые никогда не использовались)
SELECT 
    indexrelname AS индекс,
    relname AS таблица,
    schemaname
FROM pg_stat_user_indexes
WHERE idx_scan = 0
ORDER BY schemaname, indexrelname;

-- Удаление индекса
DROP INDEX IF EXISTS имя_индекса;
```

### Практические примеры комплексной оптимизации

#### Пример: оптимизация аналитического запроса

```sql
-- Сложный аналитический запрос
EXPLAIN ANALYZE
SELECT 
    к.город,
    EXTRACT(YEAR FROM з.дата_заказа) AS год,
    COUNT(*) AS количество_заказов,
    SUM(з.общая_сумма) AS общая_сумма
FROM клиенты к
JOIN заказы з ON к.id = з.id_клиента
WHERE з.дата_заказа >= '2023-01-01'
GROUP BY к.город, EXTRACT(YEAR FROM з.дата_заказа)
ORDER BY общая_сумма DESC;

-- Соответствующие индексы для оптимизации:
CREATE INDEX idx_заказы_дата_анализ ON заказы (дата_заказа);
CREATE INDEX idx_клиенты_город_анализ ON клиенты (город);
CREATE INDEX idx_заказы_клиент_дата_составной ON заказы (id_клиента, дата_заказа);
```

#### Пример: оптимизация текстового поиска

```sql
-- Для полнотекстового поиска
CREATE INDEX idx_товары_поиск_полный ON товары 
USING gin (to_tsvector('russian', наименование || ' ' || COALESCE(описание, '')));

-- Запрос с полнотекстовым поиском
SELECT *, ts_rank(to_tsvector('russian', наименование || ' ' || COALESCE(описание, '')), query) AS rank

ORDER BY rank DESC;
```

### Практические советы по оптимизации

#### 1. Не создавайте слишком много индексов

```sql
-- ПЛОХО: слишком много индексов замедляет DML операции
-- У каждой таблицы может быть 10+ индексов

-- ХОРОШО: баланс между производительностью SELECT и DML
-- Обычно достаточно 3-7 индексов на таблицу
```

#### 2. Мониторинг использования индексов

```sql
-- Регулярно проверяйте статистику использования индексов
SELECT 
    schemaname,
    tablename, 
    indexname,
    idx_scan,
    idx_tup_read,
    idx_tup_fetch
FROM pg_stat_user_indexes
WHERE schemaname = 'public'
ORDER BY idx_scan ASC;
```

#### 3. Используйте правильный порядок столбцов в составных индексах

```sql
-- ВАЖНО: порядок столбцов в составном индексе критичен
-- Правила:
-- 1. Столбцы с равенством первыми
-- 2. Столбцы с диапазонами последними
-- 3. Столбцы в ORDER BY могут следовать за остальными

-- ПЛОХО:
CREATE INDEX idx_плохой ON таблица (столбец_диапазон, столбец_равенство);

-- ХОРОШО:
CREATE INDEX idx_хороший ON таблица (столбец_равенство, столбец_диапазон);
```

#### 4. Используйте частичные индексы для часто используемых фильтров

```sql
-- Частичный индекс для активных записей
CREATE INDEX idx_активные_клиенты ON клиенты (дата_регистрации DESC) 
WHERE активен = TRUE;

-- Используется для запросов:
-- SELECT * FROM клиенты WHERE активен = TRUE ORDER BY дата_регистрации DESC;
```

#### 5. Рассмотрите материализованные представления для аналитики

```sql
-- Для сложных аналитических запросов материализованные представления могут быть эффективнее
CREATE MATERIALIZED VIEW аналитика_по_городам AS
SELECT 
    к.город,
    COUNT(DISTINCT к.id) AS клиенты,
    COUNT(з.id) AS заказы,
    SUM(з.общая_сумма) AS выручка
FROM клиенты к
LEFT JOIN заказы з ON к.id = з.id_клиента
GROUP BY к.город;

-- Создание индекса на материализованном представлении
CREATE INDEX idx_аналитика_город_выручка ON аналитика_по_городам (выручка DESC);
```

### Заключение главы

Индексы - ключевой инструмент оптимизации производительности баз данных. Правильное использование индексов может:

1. Значительно ускорить выполнение запросов
2. Уменьшить время ожидания пользователей
3. Повысить общую производительность системы

Однако важно помнить, что:

1. Индексы требуют дополнительного места на диске
2. Обновление данных замедляется из-за необходимости обновления индексов
3. Слишком много индексов может быть контрпродуктивным

Ключ к эффективной оптимизации - понимание реальных паттернов использования данных и создание соответствующих индексов для наиболее критичных запросов.
